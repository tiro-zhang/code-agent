## Context

动机见 `proposal.md` 的 Why。具体行为合同见本变更 `specs/`，执行顺序见 `tasks.md`；这些均为供评审的规划，不表示功能已经实现。

当前实现已经具备显式目录接口：`ToolContext.root` 是解析后的绝对路径，文件及搜索工具检查真实路径边界，命令工具以该目录启动独立 shell。但 `ChildRuntime` 仍复制父根；`PermissionManager.fork()`、Hook scope 和父会话 MCP 连接也沿用父目录语义。子结果缓存虽然按任务身份独立，仍位于工作根中，并由任务管理器保留引用。

角色入口严格拒绝未知 frontmatter 字段；defined 子运行从空历史开始，Fork 保留父已发送请求快照，两类子运行均非交互。现有规则还要求明确拒绝优先、规划模式只读、子结束不关闭共享服务、存档所引用证据不能被静默删除。

既有 `session-persistence` 的独立运行条款将主回流写成仅加载结果与斜杠结果，但现有 `subagent-runtime` 条款已包含 Agent 最终结果、接收凭据与异步结果。本变更在持久化增量中明确纳入这些既有回流类型，并为其添加 Worktree 来源，不扩大逐步子消息进入主历史的范围。

用户已确认四项决策：

1. 提供独立工作副本与默认 cwd 隔离，不提供操作系统文件系统沙箱。
2. 接受任务时冻结父 `HEAD`，明确提示不包含父目录未提交修改。
3. 第一版仅自动隔离声明 `isolation: worktree` 的 defined 角色；未声明角色和 Fork 保持现有行为。
4. 继承权限约束，不自动迁移父目录批准；子仍非交互，缺少批准返回 `approval_required`。

其余技术选择是本次完整规划采用的工程方案，供整体评审，不将此前的设计答复解释为这些细节已经逐项确认。此前待定的参数采用下表初值，避免将配置和验收条件留给实现阶段猜测。

## Goals / Non-Goals

**Goals:**

- 将 Git 工作副本管理与 Agent 执行上下文分开，使同一进程内的父子运行可以同时使用不同目录。
- 让创建、恢复、初始化、取消和清理都有可检查的归属与状态；排队或失败不得被描述为已开始模型工作。
- 在删除目录前保护实际文件成果、提交和可恢复证据，清理故障不改变子模型真实结束原因。
- 复用现有工具、权限、Hook、结果和存档契约，不新增并行编排入口。

**Non-Goals:**

- 不实现自动 merge、rebase、cherry-pick、push、代码同步或父目录未提交改动的复制。
- 不使用 `chdir`、修改共享执行器 root 或通过切换时清空所有缓存实现隔离。
- 不为 Fork、独立 Skill 或 MCP Server 新建独立隔离连接，不承诺 shell、共享服务及依赖软链不能访问其他目录。
- 不新增常驻清理守护进程，不自动强制删除成果，不新增面向模型的 Worktree 管理工具或斜杠控制命令。

## Decisions

### 1. 独立管理模块与不可混用的目录身份

建议新增 `src/mewcode/worktrees/`，集中管理 Git 命令、受管记录、初始化、租约和清理。管理器提供内部创建／恢复、进入、退出和删除接口，返回不可变的工作树描述；Agent 层决定何时调用，不直接拼接 Git 生命周期命令。

区分以下身份：

| 身份 | 用途 |
| --- | --- |
| `origin_root` | 父运行的实际工作根、权限上限来源 |
| `checkout_root` | 发起创建的 Git 工作树顶层目录，受管目录放置位置 |
| `common_git_dir` | 共享版本库的真实绝对路径，验证仓库归属 |
| `worktree_root` | 新工作树的顶层绝对路径 |
| `workspace_root` | 子运行实际工具工作根 |
| `base_commit` | 接受任务时冻结的完整提交身份 |

建议目录位于 `<checkout_root>/.mewcode/worktrees/<name>`，受管记录位于同级 `.mewcode/worktree-state/`，从 Git 和普通搜索中排除。启动于仓库子目录时，`workspace_root` 对应新工作树中相同的项目子目录；该目录在冻结版本中不存在时明确失败，不把工具根悄悄扩大到仓库顶层。

创建前验证管理目录未被追踪，并安全建立忽略规则；不能因为调用项目不是 MewCode 就假定其已有忽略配置。记录包含版本、仓库身份、目录、分支、基线、来源任务、初始化摘要和时间，按私有权限原子写入。运行租约与静态创建记录分开存储，避免快速恢复产生写入。

替代方案是复制整仓库或让父子修改共享 root：前者丢失原生共享版本库机制，后者不能支持同进程并发。使用 Git Worktree 和逐运行上下文符合本章目标。

### 2. 安全名称与 Git 参数边界

名称先按原始输入校验，再转换为路径，不能先规范化掉危险段。只允许 ASCII 字母、数字、下划线、连字符和作为分隔符的 `/`，总长不超过 128、单段不超过 64、深度不超过 4；拒绝空值、空段、`.`、`..`、首尾斜杠、反斜杠、绝对路径和控制字符。

名称通过校验后仍逐级检查真实路径与祖先链接，目标必须位于受管目录内。同一受管工作树不能成为另一工作树的祖先或后代；分组目录可以存在，但普通目录不能冒充完成的 Worktree。

自动名称建议为 `<role>/<task_id>`。分支身份由应用生成，使用独立的 Git 合法性校验，不把允许目录嵌套等同于任意字符串都可作为分支名。Git 使用参数数组与显式 cwd，不经 shell 插值；创建不使用覆盖已有分支的 `-B` 或跳过保护的 `--force`。

仅靠正则不能阻止祖先软链和检查后的目录替换，因此路径、受管归属与并发互斥检查都要保留，并在实际操作前复查。

### 3. 冻结基线、延迟创建与只读快速恢复

接受隔离子任务时解析父所在仓库并读取当时的 `HEAD`，将完整提交身份和角色隔离声明加入任务快照。该过程不复制父修改，也不消耗子模型请求预算。非 Git 工作目录、尚无提交或无法验证仓库状态时返回明确的未启动错误，不降级为共享目录执行。

任务排队期间不创建工作副本；真正启动后才从已冻结提交创建独立分支和目录。排队取消不会留下 Worktree。模型请求必须在初始化完成和进入成功之后开始。

```text
accepted --> queued --> creating --> initializing --> ready --> running
                           |             |                        |
                           v             v                        v
                        failed        incomplete               stopping
                                                                  |
                                                                  v
                                                         archive evidence
                                                                  |
                                                    +-------------+-------------+
                                                    |                           |
                                                    v                           v
                                                 retained                    removed
```

已存在目录先走纯文件系统恢复函数：读取受管记录和完成标记，检查普通文件／目录类型、Worktree 的 `.git` 指向、管理目录中的 `commondir` 与反向 `gitdir` 关联、分支身份及预期仓库。关联必须落在登记的真实路径内，不接受任意外部路径；不能把存在一个 `.git` 文件视为充分证明。

只有完整、归属一致的目录才返回恢复描述；恢复函数不调用 Git、不复制配置、不写状态、不重置分支。不存在时才进入创建流程，未知、损坏或半初始化目录返回明确诊断，不自动修复或接管。进入步骤独立取得运行租约并更新活动记录；完成恢复不代表允许两个子任务同时使用该目录。

同名创建、进入和删除需跨进程互斥，进入后持有运行租约直到真实收尾完成。PID 和超时只能作为诊断信息，不能单独证明目录已不活跃；租约检查应以实际锁所有权为依据。

规划模式不允许新建、初始化或删除 Git 工作树；声明隔离的任务若需要这些步骤，启动前明确拒绝。纯读取恢复和已就绪目录上的只读运行仍受规划及非交互许可限制。模式切换先停止新副作用并收尾，不借内部管理器绕过只读要求。

创建或初始化失败时，只可回收本次操作明确拥有且没有未知内容的资源；否则保留 incomplete 状态和原因。记录目录不存在、Git 已登记但初始化未完成等不同故障，不声称整段生命周期具有跨文件和 Git 的事务回滚。

### 4. 有界、声明式的环境初始化

使用原实际项目工作根下的版本化配置 `.mewcode/worktrees.yaml`，为复制、软链和忽略文件补齐声明明确清单；集中校验未知字段、重复键、类型和路径，第一版不支持任意初始化脚本。配置在接受任务时校验和冻结，缺失使用公开默认值；本轮只规划该接口，不创建产品配置文件。

配置接受 `version`、`copy-files`、`link-directories`、`copy-ignored-files`、`regenerable-paths`、`hooks-path` 和 `cleanup`。复制与软链项使用相对 `path` 和可选布尔 `required`（缺省 false）；忽略复制项使用相对 `pattern` 和同样的 required 标记，有界枚举实际被忽略的普通文件。目标沿用相同相对位置，路径分别相对 origin_root 与 workspace_root，不提供任意绝对目标。`regenerable-paths` 使用有界项目相对规则，不允许覆盖初始化文件或任意全目录；缺省只分类应用内部缓存和 `.pytest_cache`、`__pycache__` 产物，任何证据引用仍优先保护。`hooks-path` 可选，声明时相对新工作树顶层解析为专属 Git hooks 路径；省略保留原有效策略。cleanup 接受正整数 `ttl-days` 和 `interval-seconds`，布尔值不能当整数，省略为 30 和 1800。所有未知键和非法规则均拒绝，不部分采用坏配置。

初始化从冻结提交已经检出的文件开始，按清单补充运行环境：

- **复制**：按存在性复制指定的本地配置，默认包含原实际项目工作根下的可选 `.env`；其他启动配置可显式登记。复制后的配置独立，不覆盖已有目标，不输出凭据。不因为运行时配置来自仓库外就自动复制那个外部文件。普通复制单项不超过 1 MiB、合计不超过 16 MiB，有界枚举最多 512 个文件，超限明确失败。
- **Git hooks**：保留原有 hooks 策略；需要子目录专属路径时使用 `extensions.worktreeConfig` 和 `git config --worktree`，不能在子目录运行 `git config --local core.hooksPath` 后误改共享配置。Git 不支持所需能力或已有 `core.worktree`／`core.bare` 等配置无法安全迁移时明确失败，不静默禁用 hooks。
- **依赖软链**：按明确清单建立，例如 `.venv`、`node_modules`；来源应属于允许的原项目位置，不覆盖检出文件。软链是共享可变资源；目录越界文件工具仍拒绝通过它访问外部目标，shell 遵循现有权限。
- **忽略文件**：仅按规则复制实际被忽略且运行需要的普通文件。源、目标与祖先均检查路径边界，不用无界递归复制整个忽略目录，不复制父目录未提交的普通源码。
- **权限配置**：本地规则可以作为约束输入，但批准记录不得被初始化搬迁成新 root 的批准；会话、缓存和记忆运行目录不作为默认复制对象。

记录应用创建的配置文件摘要、权限位、依赖链接目标以及明确可再生的运行产物规则。初始化完成最后发布 ready 标记；恢复路径不重新执行这些步骤。复制父配置是运行环境补齐，不改变源码基于冻结提交的承诺。

Git 默认共享仓库配置，需要工作树专属配置的原因见 [Git 官方文档](https://git-scm.com/docs/git-worktree#_configuration_file)。实际调用前需验证兼容能力，不假设所有已安装 Git 都支持同一配置行为。

### 5. 每个运行绑定显式目录上下文

进入成功后，`ChildRuntime` 创建自己的 `ToolContext(workspace_root)`、目录权限视图、提示状态和目录相关服务视图，不修改父实例或进程 cwd。独立文件读状态和路径相关缓存使用真实绝对路径；聚合项目状态以绝对工作根标识，再结合配置版本和角色身份等实际输入区分记录。

固定基础系统提示仍可共享相同文本；只有依赖工作区的提示内容或缓存才按目录区分，不为全局常量强行制造目录副本。绝对路径防止串目录，不替代同目录文件变动的版本校验和重新读取。

项目指令从子实际根加载，角色正文采用已冻结定义；Skill 目录由子工作根发现并保留父工具上限，不直接借用指向父项目资源的目录快照。项目记忆读取自己的目录存储，用户域仍按现有约定共享；不因初始化默认导入父记忆，不新增对子任务的自动记忆提取。

首个工作请求包含子目录、分支、冻结提交、独立子身份和“父目录未提交修改不在本工作副本中”的说明；后续按现有完整／精简提醒机制保持实际工作根正确。父历史中的目录信息只描述历史，不能成为子当前目录或许可来源。

Hook 规则快照、会话 once、后台派发设施继续共享；子 scope 绑定自己的命令 runner 和权限视图，`tool.target_path` 相对于子工作根解释。异步 Hook 的运行租约持续到实际动作结束，不能随子模型最终回答提前释放。

共享 MCP 不支持通用的逐调用 cwd 重绑定：stdio 服务仍使用会话启动目录，HTTP 服务采用自身约定。保留这些语义，不注入虚假的子 cwd、不把 MCP 参数中的 path 自动解释为本地目标，也不为本章创建新连接。子调用仍须通过工具范围和子实际 root 下的权限判定；涉及目录的服务不能被描述为已经 Worktree 隔离。

### 6. 权限来源与执行目标分离

子权限视图以 `workspace_root` 解析实际目标，以父当前规则作为权限上限，并允许子目录适用规则进一步收紧。文件规则在各自作用域的规范项目相对路径上匹配，不能把子路径简单拼到父根后遗漏父原有的 deny；父与子任一明确拒绝都优先。受保护配置仍在工具层保护。

继承父权限模式，角色配置只能收紧；父注册时工具范围和当前规划上限继续生效。主 Agent 对 `agent` 启动的批准只批准委派，不授予子普通工具权限。

父文件、命令和 MCP 批准不因目录切换自动改写或重绑。批准继续精确关联实际工作根、工具和目标／参数；不能仅复制内存批准表就假定它适用于新 cwd。需要许可的操作可由已有适用规则或对子真实 root 的有效批准提供，否则返回 `approval_required`，不在子运行中弹出审批。

父规则更新产生的新 deny 必须继续限制活动子运行，不将复制的旧本地配置作为绕过当前父拒绝的来源。配置解析失败按照现有受控失败路径处理，不默认开放操作。

### 7. 先归档证据，再释放和判断删除

退出不等同于删除。先停止接受新操作，等待受控工具、命令进程组和关联 Hook 真正收尾，确定子模型的实际结束原因，并将父任务／存档需要的证据归档到父会话拥有的私有存储。

归档不依赖模型文件工具，而是应用管理的结果保存。保留原任务、调用、结果和工作根来源，将新缓存引用纳入父存档登记和校验；不能只复制文件而留下指向已删除目录的引用。归档失败或仍有旧引用时保留原目录和必要句柄，清理状态独立报告。

运行租约覆盖受控操作和 Hook 的实际收尾，证据删除保护另由持久记录与引用登记维持。只有两类保护都满足才能评估删除；归档失败时可以报告保留并在关闭时释放已收尾的句柄，不要求无限等待归档，也不能因进程退出释放锁就删除未归档证据。`record.state` 已到终态不代表进程或取消收尾已经结束，检查实际运行句柄和资源所有权。结果携带路径、分支、基线、初始化／归档状态、保留或删除状态及原因；清理失败不把 `model_done` 改成模型失败，也不将 cancelled 描述为回滚成功。

删除至少检查暂存和未暂存修改、未追踪文件、相对于初始化基线发生变化的忽略文件、提交状态及活动租约。只有初始化原样配置、登记链接和明确可再生的产物规则可以不作为成果；未知忽略文件仍需保护。

自动删除建议要求子 `HEAD` 仍等于 `base_commit`。任何新提交，包括已推送提交，均保留给上层处理；这样无需靠缺失 upstream 或可能过时的远端引用证明“已推送”。默认删除至少保护未推送提交；没有可核对依据、查询失败或状态不明都保留，不能把未知当作零个未推送提交。

删除目录和删除分支是独立步骤，只处理本应用拥有的准确目标，不批量 `prune` 或扫描删除仓库所有分支。已无新提交且已释放的应用分支才可安全删除；任何分支删除失败也报告实际状态。第一版不提供自动强制清理，存在成果时上层仍可自行决定后续 Git 操作。

### 8. 会话内有界的过期清理

建议会话启动及存活期间定期扫描本管理器登记的记录，清理运行受模式和关闭状态约束；建议初值为严格超过 30 天未活动、每 30 分钟检查一次。定时任务由会话拥有，退出取消并等待其本地收尾，不增加独立守护进程。

三层过滤依次执行：

1. **归属**：名称、路径、仓库、双向关联和受管记录一致；主目录、外部目录、未知目录、链接和损坏记录跳过。
2. **活跃**：有效活动时间严格过期，没有创建／运行／收尾租约，没有未释放证据引用；时间异常和锁状态不明跳过。
3. **成果**：复用显式删除的同一检查，确认没有需要保护的文件或提交；检测失败保留并诊断。

真正删除前在互斥保护下再次校验，避免扫描后目录重新进入活动状态。TTL 仅筛选候选，不撤销成果保护；过期但有改动的 Worktree 继续保留。旧版本或人工创建的目录不自动登记、接管或删除。

替代方案是按目录 mtime 清理或调用 Git 全局 prune：前者无法识别成果与活跃租约，后者扩大作用范围，都不采用。

## Risks / Trade-offs

- [新目录不包含父未提交源码] → 在任务结果和首个子请求明确基线；由上层决定何时提交，不自动复制或同步。
- [软链依赖、shell 或 MCP 仍可能影响其他目录] → 准确表达工作副本与默认 cwd 边界，保留真实路径及权限检查，不宣称强沙箱。
- [新 root 缺少可用批准导致子任务受限] → 保持非交互错误与真实结果，通过适用规则或对子实际 root 的批准配置所需操作，不扩权。
- [Git 配置默认共享、分支及 refs 也共享] → 子 hooks 使用专属配置，应用分支独立命名，仅删除准确受管目标，不将 Worktree 描述为整个版本库副本。
- [初始化或证据归档中断] → ready 标记最后提交；归属不明、内容不完整或引用未释放时保留目录，记录可检查的故障。
- [子任务已通知终态但本地操作仍收尾] → 以实际句柄和租约判断活跃状态，清理不依赖展示状态或单独 PID。
- [保守保护使带提交或未知忽略文件的目录长期保留] → 返回可检查的路径和保留原因，留给上层处理成果；不以存储期限覆盖保护。
- [不支持的 Git 布局，例如未验证的子模块或配置迁移] → 创建前明确检测并报告不支持，第一版不自动改造仓库布局。

## Migration Plan

1. 按本变更增量规格及实施任务开展开发；本轮仅完成规划，不修改主规格和产品代码。
2. 先实现并验证独立 Worktree 管理接口，再接入显式目录上下文、权限、Hook 与证据归档，最后接入声明隔离的 defined 角色。
3. 现有角色缺省保持共享工作根；新字段只接受受支持的声明，不用非法值回退开放模式。旧存档无 Worktree 信息时沿用旧合同。
4. 恢复存档只展示保存的工作树和成果证据，不自动恢复执行、重跑任务、迁移批准或接管活动目录。显式复用已有目录仍须通过纯读取恢复检查和独立进入租约检查。
5. 同步 README 与 checklist，并在临时 Git 仓库验证双子目录和父目录的产物独立、冻结版本、错误、取消、批准隔离及三层清理。实际 Git 测试验证分支与目录生命周期，供应商替身验证模型请求和结果边界。
6. 实现后配置真实且已授权的模型服务，通过本次 tmux 运行验证读取、编辑、测试、取消和有成果保留，并记录 checklist 的通过、失败或未执行原因；本轮草案不等同于功能验收。
7. 回退时停用隔离角色声明及自动清理，保留工作树、分支、受管记录和证据，交由上层检查；不为了回退删除成果或盲目关闭可能被其他工作树使用的 Git 配置扩展。
