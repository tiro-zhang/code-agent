## Context

动机与范围见 `proposal.md`。当前 `ChatSession` 持有进程内历史和待执行计划，`Agent.run()` 在完整响应及工具批次收尾后提交消息；`PromptState` 已有自定义指令和长期记忆补充入口，但不加载文件。`ContextManager` 会替换历史并维护原话来源、结果引用、摘要版本及连续失败次数；`ResultCache` 使用独立随机身份，正常退出删除本会话文件。应用关闭顺序是会话缓存、MCP、供应商、终端。

本次需要同时调整消息提交、检查点、私有文件生命周期和异步关闭，而非仅在启动时拼接 Markdown。用户确认的三个边界是：普通启动新建、旧任务显式恢复；用户级偏好只记录明确表达；项目和用户指令引用分别限制在各自根目录。其余采用已审阅的设计默认值。

## Goals / Non-Goals

**Goals:**

- 让指令、存档、记忆各有独立职责，由会话协调，终端只负责输入与可见反馈。
- 让 JSONL 成为会话唯一持久事实源，工作上下文可由它投影；索引是笔记的可重建视图。
- 保持当前完整工具批次、原文保护、摘要验证及真实副作用语义，恢复不执行历史操作。
- 后台维护有独立预算和生命周期，既能跨任务串行处理记忆，也能与当前工作请求并行。

**Non-Goals:**

- 不承诺从崩溃记录判断外部操作到底完成多少，不自动续跑工具或批准旧计划。
- 不恢复进程、终端草稿、会话授权、MCP 连接或工作 usage 估算锚点。
- 不将字节上限等同于精确 token 数，不递归摘要记忆维护输入。
- 不新增数据库、检索服务、后台守护进程或多个文件的通用事务引擎。

## Decisions

### 1. 沿用工作根目录，分离三个模块

新增 `instructions/` 管理发现、展开和来源，`sessions/` 管理记录、投影、扫描和清理，`memory/` 管理笔记、索引及后台更新。具体类名可在实施时按邻近风格确定。会话接收加载结果并持有持久化服务和记忆更新器；代理在历史提交、工具调度前后及压缩提交处发出与界面无关的持久化通知。不能从终端打印事件反推存档，否则替换消费者或中途退出会丢失记录。

项目根为实际工具工作根目录的真实路径，继续采用从工作目录启动的语义，不另外上溯 Git 根，也不以 `.env` 所在目录定位项目。

```text
<project>/
  MEWCODE.md
  .mewcode/
    MEWCODE.md
    sessions/<session-id>.jsonl
    context/<session-id>/<result-id>.jsonl
    memory/
      MEMORY.md
      <note-id>.md
~/.mewcode/
  MEWCODE.md
  memory/
    MEMORY.md
    <note-id>.md
```

选择项目内存档而非用户目录汇总，使项目身份、结果路径和清理所有权一致。保留两级笔记，使明确的通用偏好可跨项目使用；范围不明的内容不会被全局传播。

### 2. 手写指令采用确定性展开和显式优先级

按 `<project>/MEWCODE.md`、`<project>/.mewcode/MEWCODE.md`、`~/.mewcode/MEWCODE.md` 顺序加载。缺失入口视为空，不创建模板。每段附加可信加载器产生的来源和层级标识，按高优先级在前拼接，固定提示明确冲突规则：系统和实际模式／权限约束优先；手写指令在本功能三层内按上述顺序处理；自动笔记是背景知识，不覆盖手写约束。具体当前任务的明确要求继续按现有任务授权处理，文件不能提供新增工具授权。

引用语法为独立行 `@include <相对路径>`，整行余下文本作为路径，可含空格；围栏代码块中的相同文字按示例保留。不展开环境变量、`~` 或绝对路径。相对当前文件目录解析后检查真实路径：项目入口及其引用必须在项目根内，用户入口及其引用必须在用户 `.mewcode` 内。入口本身也接受真实路径检查；项目根入口指向目录外的符号链接不得加载。

入口深度为 0，允许引用深度 1 至 5，深度 6 被跳过。每次顶层加载使用真实路径的 `visited` 集合，已读文件不再次展开；同一次装载的多层入口共享已展开集合，高优先级先展开，使重复引用只出现一次，引用内容继承首次包含它的入口优先级。先检查边界，再打开普通 UTF-8 文件，避免把 FIFO 或越界链接当成配置。缺失、编码错误、非普通文件、环路和深度限制均给出来源诊断，继续加载其他有效内容。

除深度限制外，单次三层展开设置合计 256,000 UTF-8 字节的读取上限；触及上限跳过整个导致超限的文件并诊断，不截断一半指令。已加载文本仍计入完整请求预算，固定部分太大时沿用受控停止。选择有限展开而非无限递归，避免浅层的大量引用挤占内存；不引入新的设置项。

### 3. JSONL 是带版本的追加事件流，展示信息扫描推导

会话 ID 使用本地时间的 `YYYYMMDD-HHMMSS-xxxx`，`xxxx` 为四位随机十六进制；文件排他创建，碰撞重新生成随机部分，不覆盖已有存档。记录时间为带时区的 UTC ISO 8601，时间判断不从文件名推算。每行一个完整 JSON 对象，包含 `schema_version`、顺序号、记录身份、时间、类型及类型化 payload。首条 `session_created` 保存会话 ID、真实项目根、协议、模型和创建时间；不保存 API 密钥、服务鉴权头或完整运行配置。

记录类型与投影职责：

| 记录 | 内容及作用 |
| --- | --- |
| `session_created` / `session_resumed` | 身份、创建或本次恢复活动及必要兼容信息 |
| `task_started` / `task_finished` | 原始输入、任务身份、结构化模式、结束原因、最后确认的摘要失败／熔断状态及实际工作 usage 关联 |
| `mode_changed` / `maintenance_finished` | 不请求模型的模式切换，以及独立维护用途、实际 usage 和摘要失败／熔断状态；不恢复权限或待执行计划 |
| `interaction_started` | 完整已收集助手工具响应、对应候选输入和应用提醒；在调度任何工具前持久化 |
| `tool_result` | 真实返回的结构化结果及调用关联；完成顺序允许不同 |
| `history_commit` | 完整消息组，含普通最终答复或按调用顺序配对的工具批次 |
| `history_checkpoint` | 轻量替换或摘要后的完整工作投影、被覆盖记录边界及必要摘要状态 |

普通流片段、未完成助手响应、摘要草稿及记忆提取的内部思考不入档。已完成工作消息的供应商续接块按现有协议需要保留，不把必要签名当作可随意丢弃的显示思考。消息保存本地 ID、role、context_kind、tool_calls、tool_call_id、tool_result、provider_content、cache_path，恢复时严格验证类型、来源和关联，不通过正文标签重建应用身份。

消息数由扫描后去重的已提交消息身份计算，包含 user／assistant／tool，不包含 context、诊断事件或检查点自身；压缩不改变累计消息数。标题取第一条真实任务输入首个非空行的前 60 个字符，空白显示“未命名会话”，不为标题调用模型。最后活动时间取创建、恢复、任务、模式切换及用户主动摘要事件的有效时间，后台笔记更新不延长会话有效期。列表按最后活动时间倒序、ID 为稳定次序；实现可以有本进程缓存，但不落独立 meta 或汇总数据库。

### 4. 存档写入与内存提交分别保持安全边界

同一会话仅允许一个写入进程，通过持有 JSONL 文件的排他锁维持活动身份，恢复活动文件时明确拒绝。每条语义记录完整编码后追加并 flush；工具调度前的 `interaction_started`、历史提交、检查点和轮次结束执行 fsync。成功返回才确认持久提交，恢复文件时在锁保护下补一个换行隔开不完整末行，保留坏行原文再追加，避免新记录被拼到残缺 JSON 上。扫描只读，不因列出会话修改坏行。

在调度前写入失败时不启动本批工具；结果已经产生但写入失败时保留内存中的实际结果，停止后续工具及工作请求，以 `context_blocked` 报告无法安全保存上下文和可能已有副作用。不能把失败写入说成操作回滚。存储层局部重试不重新执行工具。

`history_commit` 保存完整消息组后再确认对应内存提交；`interaction_started` 和逐条结果让崩溃恢复仍能识别正在执行的批次。若所有结果已保存但最后组提交记录缺失，恢复器可在严格验证后按原调用顺序组装这一完整组；某调用缺少结果则不猜补结果。相同消息及结果身份重复出现时只应用一次。

检查点包含完整工作历史、历史版本、摘要版本、已校验原话及来源、所有必要结果引用、失败计数和熔断状态。它既用于摘要替换，也用于结果轻量落盘后的消息替换。压缩组件先生成并验证候选，持久检查点成功后再确认内存替换；不能先改内存后漏记检查点。新结果文件在发布路径之前原子写入，写失败保持原消息。

采用事件加检查点而非每轮重写整个 JSON，保留追加效率和原始操作证据，也避免启动时把所有已压缩消息装回。JSONL 容错降低损坏范围，但不宣称格式本身能保证掉电仅丢最后一行；保证对象是已经成功刷盘的记录。

### 5. 显式恢复先建立合法投影，再检查模型预算

`--resume <id>` 只接受规定 ID 格式；`--resume latest` 选择当前项目最新的非活动、未过期且有有效身份的存档，候选选择不请求模型；无候选明确报错，不偷偷新建。`--list-sessions` 扫描并展示 ID、标题、消息数、最后活动和可恢复状态，不启动供应商或 MCP、不执行模型请求。两参数互斥，保留现有 `--config` 必填语义。第一版仅在启动时选择会话，不引入运行中切换的 `/resume`。

恢复顺序：

1. 验证文件普通性、真实路径、会话身份与项目根，获取排他锁；跳过空行、坏 JSON、未知记录版本及字段非法记录，汇总警告。关键身份记录无效则不可恢复。
2. 选择最后一个完整合法检查点，应用后续有效事件。损坏检查点跳过；仅在其他合法记录足以构造工作状态时回退。原始存档保留。
3. 以批次身份匹配结果，按助手调用顺序重排。碰到缺失、重复冲突或孤立结果，工作历史退回此前最后完整交互边界，后续内容不进入工作请求，说明未确认操作可能已有副作用。
4. 验证工具结果引用和摘要状态，重开属于该存档会话的缓存。必要文件缺失或损坏时受控停止，提供明确原因，不把不存在路径作为成功引用。
5. 恢复可信记录中的 plan／execute 模式和摘要失败状态；会话批准、待执行计划与旧 usage 估算锚点不恢复。永久批准和权限模式按本次启动配置加载。旧规划答复可阅读，但 `/do` 需要新的有效计划。
6. 当前协议不同或携带供应商续接块的历史不能用于本次模型时，在发请求前提示兼容错误；第一版不静默删除签名或转换为伪造普通回答。无供应商续接块且协议相同的记录允许模型名改变，按新窗口重新预算。
7. 重新加载当前指令、记忆和环境，下一工作请求强制完整提醒，旧已提交上下文作为历史保留。历史时间跨度超过 24 小时时增加独立边界提醒，给出最后活动时间和跨度，要求涉及当前文件时重新读取；不是新的用户任务。
8. 在 MCP 注册及当前工具集确定后，对完整待发送上下文估算；不满足自动工作预算时先进行最多一次专用摘要尝试，复用手动单次路径与引用、原话、保护区、候选预算验证。维护请求独立计量，失败或无可压缩区时保留存档并返回明确的不可继续状态，不发超限工作请求。

恢复本身不发起工作请求，不续跑旧任务；预算允许后展示恢复结果并等待用户输入。恢复成功后追加恢复活动事件，避免长期继续使用的会话因创建日期较早被删除。读取扫描与模型窗口限制分开处理；同一份超长不可摘要输入不会递归调用摘要。

### 6. 结果缓存随存档保留，清理严格限定所有权

新会话和结果缓存统一采用同一 session ID。退出释放锁和文件句柄，保留存档关联的结果文件；缓存句柄关闭与过期删除是两个操作，不能继续复用当前“close 即删除”的生命周期。恢复以明确文件清单重新建立缓存所有权，不把任意目录里的所有文件当成本会话文件。

每次普通启动或显式恢复启动前扫描一次过期会话，周期为“每次启动”。有效最后活动距离当前时间严格超过 30 天的会话，取得非阻塞排他锁、再次确认活动时间后清理。活动文件、身份损坏、未来时间或无法判断归属的目录不自动删除，报告跳过原因。删除仅涉及会话存档及其登记的专属结果／结果索引；未知文件或清理失败可见，保留必要记录供下次重试。不同会话引用同一缓存被视为非法，不采用共享结果去重。

缓存、存档、自动笔记采用当前用户私有目录／文件权限（0700／0600），真实路径及普通文件验证防符号链接逃逸。目录自身建立忽略规则，确保任意用户项目不把私有数据加入 Git；普通项目搜索排除这些内部目录，明确路径的缓存读取仍经过现有工具权限和 deny。手写 `MEWCODE.md` 保持可共享、可显式读取。

旧版本随机缓存没有新会话身份记录，保持原有不自动接管或删除的规则，给出人工处理说明。不把历史残留伪称本次已清理。

### 7. 笔记为事实源，索引可重建且可直接使用

每条笔记为单独 UTF-8 Markdown，frontmatter 至少包含 `id`、`category`、`scope`、`summary`、`created_at`、`updated_at` 和 `sources`；source 保存会话／任务／消息身份及必要用户原话片段，不复制整个会话。category 为 `user_preference`、`correction`、`project_knowledge`、`reference`，scope 为 `user` 或 `project`。应用生成笔记 ID 和安全文件名，模型不能指定任意路径。单条笔记含 frontmatter 上限 16,000 字节，summary 为不超过 200 字符的一行可直接使用的事实。

四类笔记在项目级均可使用；用户级仅接受 `user_preference`，并要求存在已完成任务真实用户输入中的明确通用偏好原话。模型或工具输出、频次、单次项目做法及模糊纠正不能提升为用户级偏好。即使用户级提取无效，其他合法项目级候选仍可独立校验；校验失败条目说明原因，不自动改写成用户事实。模型判断语义去重，应用只验证结构、身份、来源、范围与大小。

`MEMORY.md` 由合法笔记的 frontmatter 确定性重建，每项是一句摘要加相对笔记路径，不是只列标题。索引失效或损坏时从合法笔记重建，损坏笔记跳过并诊断；不依赖索引反推完整笔记。每个索引文件不超过 200 行且 25,000 UTF-8 字节，两个索引合并注入后也满足这两个上限。标题、来源标识及每行换行都计入；条目整项保留或省略，不截断路径和半个事实。

选择时先偏好与纠正，再项目知识，最后参考资料；同类按更新时间倒序、ID 为稳定次序。注入输出中项目段在用户段前，并说明项目限定的约束覆盖通用默认。完整笔记在索引容量不足时保留，超限只影响自动注入集合，不自动删除知识；按明确路径仍可在现有工具边界内读取项目笔记。用户级文件仅由专用存储／加载器处理，不扩大模型文件工具根目录。

### 8. 后台提取使用独立请求，版本冲突不覆盖新笔记

只有完整工作响应无工具并以 `model_done` 结束时，才为该真实任务排队一次记忆提取；计划任务正常结束也遵循同一条件，但计划内容不能被记录为已完成事实。取消、流失败、未知工具上限、请求上限、`context_blocked`、手动摘要、恢复摘要、列表和后台维护完成均不触发。数据输入在触发时固化，包含真实用户输入、最终回复和带状态的必要工具证据；不是让后台任务持有可变 `history` 列表。

使用同一已配置供应商的独立无工具请求及专用系统提示，要求返回结构化新增／更新／合并／无变化候选。显式要求历史数据不是执行指令，记录事实、未知状态和来源，不记录配置凭据，不继续工作任务。供应商返回工具调用、断流、非法结构或无可信来源时丢弃候选。不要把内层思考或草稿存成笔记。

每次维护最多一次 LLM 请求，默认 30 秒截止，输入按现有估算器加输出预留及 3,000 余量检查。背景材料在预算内选取带身份的完整证据及既有笔记摘要；无法容纳保护的用户输入或必要材料时跳过并诊断，不递归摘要、不编造来源。请求前按索引选择顺序读取预算可容纳的完整旧笔记，记录本次实际提供全文的 ID 集合；只有此集合内的条目允许破坏性更新／合并，防止仅凭摘要丢失旧笔记细节。去重由模型结合两级 summary 判断；其他旧条目没有全文时不允许覆盖，无法判断重复时可保守新增，后续仍可合并。完整笔记及全部候选也必须计入本次输入／输出预算。

每个更新器串行处理本会话候选，并与正在运行的工作模型请求分离。跨进程的同一笔记存储采用专用文件锁和内容版本校验：LLM 调用不持锁，提交时重新检查所读笔记快照；旧版本候选不覆盖用户手工编辑或另一进程更新，跳过冲突条目并诊断，不为冲突无限重试模型。用户和项目存储分别提交，不承诺跨目录事务。

笔记单文件通过同目录临时文件、flush／fsync 及原子替换提交，失败保持该条旧文件；合并先提交包含全部来源的目标，再删除被合并旧条目。LLM／校验失败及提交前取消不改变笔记。多条提交中途失败时已成功笔记保留，报告部分更新，不伪称整批回滚。索引在笔记之后生成；索引写入失败时保留旧索引，下一请求或启动从笔记重建，不能声称旧索引已包含新内容。确定性版本信息由笔记内容和索引生成，不新增会话 meta 文件。

记忆更新有独立用途和真实 usage 记录，不占任务 `max_iterations`、不推进模式提醒序号、不改摘要熔断计数、不覆盖最近工作任务统计。每次工作请求前检查当前索引版本；有新版本时生成新的完整应用提醒，让本次请求已“读过”最新索引，既有历史保持不可变。固定系统提示和工具前缀不随索引变动。

### 9. 退出先收尾后台任务，再关闭供应商

会话退出停止接收新的记忆任务，默认最多等待后台更新 2 秒；尚未完成者取消，关闭其流并确认任务退出，然后释放存档／缓存句柄，沿用 MCP、供应商和终端关闭。不会一边关闭 HTTP 客户端一边让笔记任务继续使用。取消等待和关闭流复用现有保护性清理机制；取消本轮工作不取消此前已经完成任务的独立维护，退出则统一收尾。

退出等待超时说明“会话已保存，笔记更新未完成”，已提交笔记保留。后台状态、失败原因与实际用量在安全的维护区展示，不能把笔记正文或内部思考当作工作答复打印；恢复预算维护与记忆维护分别关联。崩溃可能丢失尚未完成的笔记提取，但任务证据已存档；本次不在重启时自动重放所有历史提取请求。

## Risks / Trade-offs

- JSONL 需扫描且长期追加会增长 → 列表单遍扫描、不加载所有会话全文；工作恢复采用最后有效检查点，30 天活动清理控制保留期。本次不新增磁盘索引或日志轮转。
- 丢失工具结果不能证明操作没执行 → 截断工作历史、明确副作用未知、等待新的用户请求，不自动重放。
- 结果缓存跨退出保留增加磁盘与敏感内容保留时间 → 私有权限、项目搜索与 Git 排除、按会话清理；磁盘失败显示真实结果和受控停止。
- 同一内容在手写规则与自动记忆中冲突 → 固定冲突规则、项目限定优先、明确原话才能进入用户级。
- LLM 遗漏、误分类或错误合并 → 来源、范围、格式及大小校验，保留实际证据；语义判断仍有模型误差，不宣称完全正确。
- 多文件部分提交与索引滞后 → 原子单文件、目标先于合并删除、笔记为事实源、索引重建及部分失败反馈；不伪称跨文件事务。
- 签名续接或协议切换不兼容 → 完整保存必要块、恢复前验证、不静默丢弃协议数据。
- 记忆维护带来额外延迟和费用 → 后台单次无工具请求、独立实际 usage、30 秒截止和 2 秒退出等待；正常工作结束不等待维护完成。
- 200 行／25KB 无法保证 2–3K tokens → 两级合并后仍进入现有请求估算，固定上下文太大时受控停止。

## Migration Plan

1. 先实现三个独立存储模块与行为测试，再接入消息提交、压缩候选事务及启动入口，最后接入后台维护和终端关闭顺序。
2. 现有用户未创建 `MEWCODE.md` 时指令模块为空；普通启动仍建立新对话，只新增自动存档。现有 `.env` 必填字段和权限文件不迁移。
3. 新格式会话采用版本记录，未知版本跳过并诊断；没有有效身份时拒绝恢复。已有随机缓存残留不自动接管。
4. README 说明目录、优先级、引用语法、列表／恢复、笔记分类及额外调用；`.gitignore`、项目搜索排除和 `checklist.md` 同步，手写指令可提交，私有数据排除。
5. 完成针对性及完整 pytest、构建、OpenSpec 严格校验，在临时项目使用本次已授权真实模型进行 tmux 验收，覆盖两种协议和重启后继续修改；记录通过、失败与未执行原因。
6. 回退代码前退出所有活动进程；旧版本继续启动新会话，新存档和笔记留在磁盘但不由旧版恢复，不把其删除作为回退必要步骤。新会话格式兼容问题以显式错误说明。
