## Why

Web 使用时出现打字、滚动和点击明显延迟；探索阶段已在现有组件中复现草稿编辑触发全部历史 Markdown 渲染，以及 SSE 积压逐事件读取完整状态的问题。当前功能验收缺少长历史、长回复和持续事件下的交互性能判据，需要在保持会话、审批、取消和恢复语义的基础上减少重复工作。

## What Changes

- 隔离按会话草稿的编辑状态，输入更新不再带动历史正文渲染，保留存储、输入法和提交版本回执语义。
- 复用未变化正文的渲染结果；生成中的回答采用轻量展示并合并更新，完成后恢复完整安全 Markdown 和代码高亮；折叠详情按需构建重内容。
- 合并 SSE 通知触发的状态读取，区分已接收事件与快照覆盖进度，补齐请求期间新增事件，保留列表刷新等独立通知。
- 优先同步审批、停止、任务结束和服务实例变化；操作回执确认后的会话列表刷新使用独立加载状态。
- 增加可复现的渲染次数、请求次数和生产浏览器交互延迟验收，覆盖刷新、断连、迟到响应与完成时格式化。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-interface`：增加长历史和流式输出下的响应性要求，明确轻量流式展示、合并同步、折叠详情及控制入口可用性，同时保留草稿、权威状态和连接恢复合同。

## Impact

- 前端：`frontend/src/App.tsx`、`Composer.tsx`、`Markdown.tsx`、`Details.tsx`、`state.ts`、`stream.ts`，以及按职责新增的草稿／同步模块。
- 验证：`frontend/tests/` 的状态、组件与浏览器回归；现有 Python Web 合同测试；新增本次性能验收材料。
- 文档与交付：实施阶段更新 `README.md`、`checklist.md`，重新构建 `src/mewcode/web/static/` 与摘要清单，验证 Python 安装包。
- 保留现有 `/api/v1/state`、SSE 信封、审批与幂等操作协议，预期无需后端协议或新增依赖。完整状态仍有与保留正文大小相关的传输成本，公开增量协议另行评估。
