## Why

MewCode 目前在服务报告上下文超限后按 1、2、4 个完整用户轮次删除历史，既会丢失任务信息，也无法处理当前单个长任务持续增长的情况。需要在有限上下文预算中优先缩减工具结果，再用结构化摘要替换较早交互，使长任务可以继续，并在无法压缩时受控停止。

## What Changes

- 新增会话级上下文管理：每次工作模型请求前先执行工具结果轻量落盘，再估算完整请求大小，必要时调用模型摘要较早历史。
- 单项工具结果超过估算 8,000 token 时落盘；同次助手响应的工具结果合计超过 20,000 token 时，按大小依次落盘；每项预览最多估算 1,000 token。保留工具层现有 64 KiB 采集上限，不补采已截断内容。
- 落盘结果存于项目内 `.mewcode/context/<session-id>/`，排除版本控制，正常退出清理；引用仍通过现有文件工具和权限系统读取。
- 当前任务用户原文与近期消息保留；较早用户消息允许摘要，关键约束逐字引用。近期从尾部保留约 10,000 token 且至少 5 条非应用提醒消息，切点扩展到完整工具交互边界。
- 通过上次有效工作请求的总输入 usage 锚定估算，只对增量按字符估算；历史替换或请求结构变化时修正或重建锚点。不开发精确 tokenizer 或学习型压缩策略。
- 自动压缩保留 13,000 token 安全余量，手动摘要请求保留 3,000 token；两者均在输出预算之外。摘要草稿与正式摘要共同占用摘要输出额度。
- 使用无工具的专用摘要调用，正式摘要采用六个固定部分，目标不超过估算 2,000 token；草稿用后丢弃。摘要成功后补充边界提醒，要求文件细节及编辑前重新读取当前文件。
- 新增 `/compact` 及上下文状态反馈；摘要连续失败三次熔断，成功清零，取消不计失败。熔断后每次显式 `/compact` 允许一次尝试，成功后恢复自动摘要。
- 自动摘要调用消耗现有任务请求预算；摘要失败保留原历史，无法容纳请求时受控返回提示符，不再自动无摘要删除旧轮次。
- **BREAKING**：配置新增必填 `context_window`，必须填写所用服务实际模型窗口；缺失时提示迁移配置，不猜测窗口。新增可选 `max_output_tokens`，默认 8192，并将实际请求输出上限与预算预留统一。

## Capabilities

### New Capabilities

- `context-management`：请求预算估算、工具结果落盘、历史分区、结构化摘要、原子提交、失败熔断和缓存生命周期。

### Modified Capabilities

- `agent-loop`：请求前上下文准备、摘要计入请求预算、超限恢复及上下文无法继续时的明确停止结果。
- `interactive-chat`：以摘要替代旧轮次直接删除，新增 `/compact`、压缩进度及上下文状态，并保持取消、计划和权限语义。
- `runtime-context`：允许摘要当前任务较早的完整工具交互；压缩后补发环境、当前模式和边界提醒，区分摘要与工作请求的提醒周期。
- `provider-configuration`：显式窗口与输出预算配置、启动校验及旧配置迁移提示。
- `llm-providers`：独立摘要请求、可约束输出上限、摘要内容与工作流隔离，以及压缩后的合法消息和 usage 语义。

## Impact

- 实现涉及 `src/mewcode/agent.py`、`session.py`、`types.py`、`config.py`、`prompts.py`、供应商适配和终端命令／状态；新增职责独立的上下文模块，不把策略堆进入口文件。
- 保留现有工具执行、64 KiB 输出上限、调用／结果配对、规划模式和明确拒绝优先；增加的文件写入仅用于应用自身上下文缓存。
- 不新增 tokenizer 或机器学习依赖，不新增会话跨进程恢复，不扩展 shell 原始输出采集，不将摘要作为权限或文件内容的事实来源。
- 后续实现需同步 `.env.*.example`、README、`.gitignore` 和 `checklist.md`，覆盖两种协议、取消、磁盘失败、预算和权限边界，并通过本次真实服务 tmux 验收。
