## Why

MewCode 已有确定性组件测试和真实模型的 tmux 验收，但固定任务的版本比较仍依赖人工阅读，缺少统一用例、自动评分及可重复的回归报告。需要评估真实模型与 MewCode 共同完成任务的能力，并为模型、提示和策略调整提供可追溯的比较依据。

## What Changes

- 增加独立的 agent 测评入口，复用真实 Provider、主 Agent、六个核心工具和现有规划／权限逻辑。
- 建立版本化的小型任务集，以独立初始环境运行修复、创建、错误恢复、规划及权限场景，支持重复试跑。
- 使用代码检查实际产物、独立功能验证和权限边界；答复准确性、计划质量由人工抽查，分别记录，首期不接入模型裁判。
- 保存试跑配置指纹、事件轨迹、最终答复、文件变化、实际用量及停止原因，明确区分任务失败、服务失败和测评器失败。
- 生成逐用例及汇总报告，支持离线比较代码版本、模型配置和提示／策略版本，分别呈现成功率、边界违规与效率。

## Capabilities

### New Capabilities

- `agent-evaluation`: 定义真实主 Agent 测评的任务、重复运行、受控配置、自动与人工评价、证据和离线对比行为。

### Modified Capabilities

无。测评复用现有 `agent-loop`、`core-tools`、`plan-mode` 和 `tool-permissions` 合同，不改变正常聊天的工具、授权或任务完成语义。

## Impact

- 预计新增 `src/mewcode/evals/` 模块及独立 `mewcode-eval` 命令，在 `pyproject.toml` 注册入口；版本化任务与评分资产放在 `evals/`。
- 接入 `ChatSession`、Provider 工厂、工具执行器及权限决策接口；测评专用工具范围和环境装配不得替换真实代理循环或通过模拟响应生成能力分数。
- 增加测评器自身的确定性测试；实现阶段同步 README、checklist 和本次真实验收记录。真实测评需明确提供已授权的模型配置，会产生模型调用费用。
- 使用现有依赖和 Python 标准库，不引入外部测评平台。首期范围为主 Agent 与六个核心工具及规划／权限，不覆盖 Skill、子 Agent、团队、MCP、UI 性能或公开 benchmark。
