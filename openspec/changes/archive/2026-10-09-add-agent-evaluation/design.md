## Context

动机与功能范围见 [proposal.md](proposal.md)，行为合同见 [agent-evaluation/spec.md](specs/agent-evaluation/spec.md)。

已有接入基础：

- `ChatSession.ask()`、`set_mode()` 和 `aclose()` 提供无界面依赖的会话执行与受控收尾，`task_finished` 表示父任务终态；`finished` 表示单个执行段结束。
- `Agent`、`ToolExecutor` 和 `PermissionManager` 已承担循环、工具调度及授权。权限模块支持审批 responder 和独立用户权限路径，适合声明式试跑审批。
- `TaskBudget.used` 与 `TaskBudget.usage` 是实际请求次数及请求用量账本；流中的 usage、段结束及任务结束可能重复表达同一统计，不能直接全部相加。
- `default_registry()` 包含核心工具及系统工具；`ToolRegistry` 默认允许部分系统工具穿过工具范围，因此仅过滤模型展示或普通工具白名单不足以限制首期范围。
- `docs/validation/structured-system-prompt/` 已保存固定任务、初始文件和人工版本比较，可提取场景，但旧材料中的 `/do` 自动执行假设必须按当前合同重写。

## Goals / Non-Goals

**Goals:**

- 在真实会话外建立任务装配、执行、证据、评分和对比的清晰边界，复用被测执行逻辑。
- 将测评器自己的确定性正确性与真实模型的随机表现分开验证。
- 输出可定位到单次尝试的结果，支持读取既有证据重新生成人工复核和对比报告。

**Non-Goals:**

- 首期不构建分布式平台、自动切换 Git 版本、排行榜、模型裁判或统计显著性判定。
- 不建立新的代理循环、工具实现、权限放行机制或正常聊天模式。
- 临时工作目录提供状态隔离，不承诺操作系统沙箱；首期只运行仓库内受信的小型任务，不接受不受信的外部任务包。

## Decisions

### 1. 独立命令与本地模块

增加 `mewcode-eval` 入口，使用现有 Python 和 YAML 依赖。`run` 明确要求 `--config`、`--suite` 和 `--output`；`compare` 仅读取结果，不接受模型配置，也不装配 Provider。

示例为计划中的接口，当前尚未实现：

```sh
uv run mewcode-eval run --config /absolute/path/.env --suite evals/core-v1 --output /private/tmp/mewcode-eval/baseline --label baseline --repeat 3
uv run mewcode-eval compare --baseline /private/tmp/mewcode-eval/baseline --candidate /private/tmp/mewcode-eval/candidate --kind code --output /private/tmp/mewcode-eval/comparison
```

支持重复 `--case <id>` 选择用例；默认全套、每例一次、串行执行。`--kind` 为 `code`、`model` 或 `strategy`，只描述比较目的，不自动改写模型、提示或工作树。不同源码版本由调用者分别运行；不同模型复用现有 `.env` 配置。提示／策略版本通过实际被测源码或用例已声明的应用指令产生，不增加产品旧版开关。

`run` 在全部尝试自动通过且无测评器错误时返回 0，有有效自动失败时返回 1，配置／任务集错误、测评器失败或收尾阻塞时返回 2，用户中断返回 130；报告始终列明具体原因，人工未评价不改变这些退出码。`compare` 在可完成描述性比较时返回 0，输入损坏或任务控制条件不兼容时返回 2 并输出原因；分数下降由报告表达，不作为比较器执行失败。

拟划分 `src/mewcode/evals/` 下的 `cli`、`suite`、`runtime`、`runner`、`graders`、`artifacts`、`report` 和 `compare` 模块。版本化任务保存在仓库 `evals/core-v1/`；命令通过显式目录读取任务集，首期不承诺 wheel 内置任务资源。

替代方案是把真实任务塞入默认 pytest 或依赖通用评测平台。前者混淆离线回归与付费模型调用，后者为小型本地任务增加装配和运维负担；独立命令保留两种验证各自的运行条件。

### 2. 用声明式任务描述用户步骤和检查

任务集入口为 `suite.yaml`，包含格式版本、集合版本与用例列表。每例声明标识、标签、初始文件目录、可选项目指令、用户步骤、权限规则与审批匹配、运行期限、自动检查及人工维度。

步骤只包含两种：`message` 提交真实用户文本；`mode` 通过真实模式切换接口进入 plan 或 execute。用户任务文本不隐含可信控制操作，不使用任意 Python 回调或通用用户模拟器驱动下一步。任务规范与评分资产使用相对资产路径，拒绝链接、父路径逃逸、非法类型、重复标识和未知字段。

总运行期限缺省 600 秒，每次明确用户任务的请求上限继承有效模型配置，缺省仍为 20；总运行期限按试跑而非按消息重置。请求预算、运行期限和工具期限写入控制指纹。正常会话的自动摘要仍使用同一任务预算，不为测评补发总结或重跑失败请求。

自动检查采用有限类型：文件存在／内容断言、保护文件指纹与允许变化范围、可信功能验证命令、结构化事件谓词及任务终态。事件谓词使用工具名、参数、结果错误码、审批决定、实际开始与阶段关系，避免对自然语言做脆弱的关键词通过判定。仅当用例明确测专用工具或错误恢复行为时约束对应事件，普通功能任务不固定完整调用序列。

检查程序属于仓库受信资产。执行前校验资产与运行依赖；功能用例应有已知错误的初始版本和正确参考版本，对评分器进行反例与正例校准，避免“评分器永远通过”。参考版本只校准评分器，不作为 agent 必须逐字复制的补丁。

### 3. 每次尝试装配真实核心会话

`runtime` 装配器创建真实 Provider、仅含六个真实核心工具实例的注册表、现有执行器和测评专用 `CoreEvalSession` 适配器。适配器继承真实 `ChatSession`，只收窄工具范围和上下文入口，不重写 ask、代理循环、模式切换、工具执行、预算或关闭逻辑。

注册表从现有工具实现取得六个实例，系统工具不注册；适配器的有效工具范围在 execute 为六工具，在 plan 为三个只读工具。声明工具、执行范围与提示中的有效工具信息保持一致，避免系统 passthrough 扩大测评范围。注入空 Skill 目录，隐藏范围外的角色／Skill 索引，阻止配置的 Agent 插件影响装配。

每次尝试创建新的工作目录和隔离用户域，显式设置 `PermissionManager.user_path`；不以重设 HOME 实现隔离。会话不恢复旧存档，关闭自动记忆。保持真实应用的 system、上下文管理及用例声明的项目指令；初始文件中只允许声明的项目指令与权限配置，不加载 Hook、用户目录或其他外部入口。临时用户域同时用于团队元数据的惰性装配，范围外入口始终不可执行。

`CoreEvalSession` 的适配面由测评器自身测试固定：工具列表与实际执行都受限，系统未知调用不能启动子任务，普通 `ChatSession` 的既有行为保持。若某项用户模型配置只服务于范围外能力，报告明确其未参与本次装配，不静默将其解释为核心运行条件。

### 4. 权限使用可重复的可信审批

正常能力用例保留真实权限模式与规则，由用例提供工具、完整参数或目标范围匹配的审批策略。策略仅返回 `once`、`session` 或 `deny`，缺省拒绝；不提供永久批准，也不使用全局 bypass 替代权限场景。

审批发生后仍由原权限模块重新检查规则和目标。拒绝场景以实际未开始、受保护文件保持及真实拒绝事件为依据；“模型提出禁止操作”和“禁止操作实际执行”分开统计。每次尝试的会话批准从空开始，多消息用例可保留本次会话批准。

替代方案是让用户手工批准每次试跑。它会把人工反应时间和不一致决定带入重复结果，故首期使用已声明的审批脚本，同时记录每次决定。

### 5. 执行和评分有独立生命周期

```text
Suite + Config --> Preflight --> Fresh Runtime --> User Steps
                                                      |
                                                      v
Report <-- Graders <-- Stable Artifacts <-- Close Runtime
   |
   v
Offline Compare + Manual Review
```

创建运行清单及尝试身份后再调用模型，逐步追加事件证据，最终结果原子提交。用例中的每条 message 消费完整任务终态，mode 步骤验证无额外请求／工具；范围外调用作为真实错误回灌。完成、取消、超时和异常均先受控关闭会话及 Provider，再冻结任务文件和启动评分。

用户取消整次运行时停止后续尝试；运行期限耗尽只停止当前尝试，完成收尾后继续其他计划尝试。收尾有单独有限期限，无法确认停止时记测评器失败和副作用未知，暂停整次运行，避免在环境状态不明时继续执行或评分。

评分资产在试跑执行期间不复制到工作目录；运行停止后，从已校验的可信资产复制到独立验证目录，针对冻结后的产物运行有界检查。明确的任务检查脚本可以在工作目录供 agent 使用，但其原文必须受保护，独立评分使用另外的可信资产。运行和评分前后核验评分资产指纹。

工作文件快照覆盖初始任务文件和新建普通文件。只排除装配器明确登记的内部缓存与运行元数据，保留排除清单；用例声明的项目指令、权限配置及检查脚本仍属于保护文件，不能把整个 `.mewcode/` 排除后漏判修改。

不把工作目录边界描述为 shell 的系统隔离。独立评分、事后引入评分资产和指纹检查用于降低误改及评分污染，首期无需容器；不受信任务或强对抗测评另行设计。

### 6. 首批八个用例

| 用例 | 自动检查 | 人工维度 |
| --- | --- | --- |
| `locate-read` | 明确要求的 glob、search、read 返回目标；工作文件保持 | 定位结论与文件内容一致 |
| `repair-verify` | 原有正确测试保持，新失败测试转为通过；真实执行用户要求的检查 | 改动与验证说明准确 |
| `create-file` | 新文件功能正确；已有文件保持 | 完成说明准确 |
| `edit-recovery` | 按任务明确要求触发歧义错误后修正；最终仅目标位置改变 | 解释真实错误与恢复 |
| `plan-revise` | 多轮规划始终只读，未启动写入／编辑／shell | 计划完整、修订纳入要求 |
| `mode-execute` | 切换 execute 本身无请求或副作用，明确任务后完成目标 | 执行答复符合最新要求 |
| `permission-deny` | 指定修改真实被拒；获准读取及其会话批准按声明生效；目标保持 | 如实说明阻塞与获准行动 |
| `failing-check` | 指定检查真实执行且退出非零；脚本和其他任务文件保持 | 未把失败说成通过 |

搜索、错误恢复等契约探针含明确工具要求，报告标注其标签；不能把这些分数直接外推为复杂真实项目能力。八例提供第一版可维护基线，新增任务或修改评分资产时更新任务内容指纹。

### 7. 自动结果、人工记录与失败分类

每次尝试状态为 `passed`、`agent_failed`、`provider_failed`、`harness_error`、`cancelled` 或 `not_run`。

- `passed`：所有必需自动检查与用例终态条件满足，且没有边界违规。
- `agent_failed`：被测运行未满足检查／预算终态，或 MewCode 执行逻辑异常；保留具体停止原因及异常阶段。
- `provider_failed`：真实模型请求或协议流失败；已有产物检查可保存，但该次不标自动通过。
- `harness_error`：环境准备、证据写入、评分器、产物冻结或无法确认收尾的错误；检查未判定和原因可见。
- `cancelled`：用户取消或试跑总期限结束；记录取消来源，不自动计为通过。
- `not_run`：计划尝试没有启动，记录用户取消、收尾阻塞等原因。

自动通过率为 `passed / (passed + agent_failed + provider_failed + cancelled)`；harness_error 和 not_run 分别展示，分母为零显示不可计算。测评器失败是结果可信度问题，不静默剔除原记录；被测 MewCode 自身异常不能伪装成测评器错误而被排除。

每项自动检查保留 `pass`、`fail` 或 `undetermined` 及证据；功能结果和边界结果分别展示。人工评价使用独立 `reviews.jsonl`，记录三重运行身份、维度、评价者、时间、判断、理由和证据引用。报告校验引用后合并显示，人工记录不覆盖自动状态和原证据；待评维度始终标未评价。

替代方案是把语义与执行打成加权总分。当前缺少经人工校准的语义裁判，合成分数会掩盖边界和失败类型，因此首期保留各维度。

### 8. 证据格式和效率统计

运行目录包含 `manifest.json`、每次尝试的 `trace.jsonl`、`result.json`、工作文件快照／变化记录和 grader 输出，以及汇总 `report.json`、`report.md`。人工记录是可选旁路文件。结果格式具有版本号，引用必须位于运行目录内，部分写入和不完整结果不能被比较器当作完整结果。

清单保存运行标识、任务与评分资产哈希、选例及计划次数、实际被测源码指纹、可用 Git 提交和脏状态、Python／依赖版本、实际协议与模型标识、脱敏服务身份、thinking、窗口和输出额度、请求预算、期限、权限脚本、工具范围和实际 system／工具／应用指令指纹。临时工作路径在比较指纹中归一化，但原始事件的路径归属仍可查。

代码身份以实际运行文件为准，不能只用当前仓库 HEAD 代表另外安装的包。服务身份隐藏 URL 凭据与敏感参数，运行清单不保存 `.env` 全文或 API key。轨迹按字段白名单输出，排除思考正文及供应商私有内容，对错误与工具文本使用现有脱敏能力；裁剪时明确标记，不声称证据完整。

请求计数和 Token 优先从每条真实任务的预算账本读取，多个阶段按不同任务账本合计，不把 usage 事件及结束汇总再次相加。保留字段完整性，未知不补零。工具意图、实际启动、失败和权限拒绝分别计数；运行耗时包含模型与工具，不包含独立评分，收尾和评分另记。串行执行减少同机资源竞争，不用首片段时间推断服务内部延迟。

汇总分别计算全部有效尝试和自动成功尝试的指标，显示样本数、缺失数及已知统计；采用每试跑的中位数和范围，首期不估算费用或发布显著性结论。

### 9. 比较器只处理保存的结果

比较器读取结果格式与内容指纹，按用例对齐。任务／初始文件／评分／权限／工具范围／请求及时间预算／选例必须兼容，无法兼容的结果保留差异说明，不生成混合总体改善结论。重复次数不同允许展示描述性比较，但明确分母与样本数。

`code` 比较固定模型配置和任务控制条件，列出实际源码与由源码产生的提示／工具变化；`model` 比较固定源码和提示条件，列出模型配置差异，包括协议、服务、窗口和输出额度；`strategy` 比较固定模型配置，列出源码及提示／策略身份变化。环境或其他本应固定的维度不同则标控制条件变化，呈现描述性结果，禁止单因素归因。提示指纹不能证明策略只改了提示，完整源码身份仍需保留。

每例列出两侧状态数量、自动通过率及差值、边界违规和失败原因，并展示效率及成功子集的变化。人工复核与覆盖率单列；未知统计不填零。输出 JSON 与 Markdown，不发起模型调用，不启动工具或自动重跑。

## Risks / Trade-offs

- [随机波动与模型服务变化] → 保留每次尝试、时间和有效配置，支持重复运行；小样本差异作为调查线索，不宣称显著改善或固定权重已验证。
- [真实调用产生费用与较长等待] → 默认单次、显式选例和重复次数，有限请求／时间预算；离线报告和比较不产生调用。
- [评分资产被误改或污染] → 使用受信任务，评分资产不放入执行工作目录，运行停止后从可信源独立验证并核验指纹；不把目录隔离宣传为系统沙箱。
- [适配器偏离正常会话] → 只控制首期工具与上下文入口，复用执行方法，并回归检查正常会话默认行为；报告始终注明核心范围。
- [隐藏环境错误或用错误分母得出乐观结果] → 分类记录失败、未执行、无效检查和有效分母，保留不完整运行；有测评器错误时不能标整次测评可靠完成。
- [旧验收包含过时命令行为] → 以当前规格及源码重写多轮用例，尤其验证切换执行模式不自动执行。
- [首期语义评价缺少自动化] → 人工旁路记录与证据抽查，显示未评价；以后引入模型裁判时另立可校准的变更。

## Migration Plan

1. 实现独立模块、入口和首批任务，对装配、评分、证据及统计运行确定性测试，不默认请求真实模型。
2. 在临时目录用已授权的两协议配置进行真实测评试跑，并按仓库要求在 tmux 完成本次端到端验收；只记录实际覆盖。
3. 保存第一批基线和人工抽查材料，验证离线比较与控制条件不兼容场景，更新 README、checklist 和验收说明。
4. 普通聊天默认配置和存档无需迁移；回退时移除测评入口与新增模块即可，既有结果目录作为带格式版本的证据保留。
