## Context

动机见 [proposal.md](proposal.md)，行为合同见 [web-interface/spec.md](specs/web-interface/spec.md)。

当前实现已经提供三个可复用边界：ChatSession 管理历史和会话能力；Agent 通过异步事件输出执行过程；PermissionManager 通过可替换 responder 请求批准。Journal 保持项目绑定与排他写入，恢复投影使用合法检查点。现有 app.py 同时承担资源初始化、终端输入、命令分发、后台唤醒和关闭；SessionCommandContext 则依赖终端状态与 renderer。Web 不能通过复制这条主循环长期维护另一套执行逻辑。

本设计遵循已确认的本机、单项目、聊天中心和会话间串行边界。下列框架、API、缓存限额和超时是本次方案的技术选择，尚未实施。

## Goals / Non-Goals

**Goals:**
- 用同一执行核心服务终端和 Web；明确资源所有者及事件来源，网页连接不拥有任务。
- 将只读浏览、运行会话激活、实际任务提交分开，既支持随时切换视图，也保持真实执行和恢复边界。
- 用可重连、可去重、可取消的结构化接口提供工作台；依赖、资源和存储开销保持有界。
- 先用现有 JSONL 表达持久证据，保持旧终端存档和原 CLI 可用。

**Non-Goals:**
- 不把浏览器作为模型供应商客户端，不把配置密钥发送给前端。
- 不把终端按键／渲染协议作为 Web API，不迁移或重写 Agent 循环。
- 不建立全机器文件互斥、持久任务队列、账号系统或第二套会话数据库。
- 不提供团队管理专用页面；已有会话内的团队控制仍遵守核心合同，并纳入运行占用追踪。

## Decisions

### 1. 独立 Web 适配器与公共运行生命周期

选择 FastAPI + Uvicorn 单进程、单 worker 承载 API 和静态资源；使用应用 lifespan 管理 Web 运行管理器。FastAPI 提供覆盖应用启动与关闭的生命周期接口，适合集中管理资源。[官方生命周期说明](https://fastapi.tiangolo.com/advanced/events/)

拟划分以下模块边界，名称可在实现时按现有结构微调：
- runtime/：从 app.py 提取配置／命令校验之后的运行会话构造、MCP 绑定、恢复准备、通知路由、后台唤醒和有界关闭；通过回调接收展示事件与审批能力，不导入终端 UI 或 HTTP 框架。
- web/server.py、routes.py、schemas.py：启动、路由、显式输入输出结构与错误映射；HTTP handler 不直接消费 Agent 到任务结束。
- web/manager.py：项目执行槽、唯一已加载运行会话、客户端操作回执、运行状态以及服务关闭。
- web/events.py、projection.py：事件序号、快照、前端可见字段投影及有界缓存。
- web/approval.py：把不可变审批快照转换为待决定项，将一次有效回答交回原权限 responder。
- web/commands.py：实现既有 CommandContext 的 Web 适配；公共查询及操作逻辑从 terminal adapter 中提取，终端外观留在原适配器。
- sessions/ 下增加只读展示投影能力，继续使用原记录校验和路径边界。

终端继续拥有输入、信号与呈现；公共层不注册终端信号处理器。初始迁移按资源初始化、通知与唤醒、关闭分步提取，每步保持原 CLI 测试。

备选是用子进程桥接终端 stdout／stdin，或复制 app.py。前者无法稳定传输结构化审批与详情，后者容易让取消和恢复合同分叉，均不采用。

### 2. 一个已加载运行会话，多份只读会话视图

服务启动只加载配置、校验目录与定义、绑定本机监听并提供静态资源。浏览列表通过只读扫描，打开历史使用展示投影，不创建 Provider、MCP、Hook 或 ChatSession。新建会话只创建合法空 Journal 并立即关闭其写句柄。

“继续会话”是明确的运行准备操作：
1. 在项目门禁内原子检查占用和预期状态，预检目标存档。
2. 若目标已经是当前可用运行会话，复用现有对象。
3. 切换已加载会话时，先关闭旧运行会话及其 Provider／MCP，确认后台活动已收尾，再释放旧写锁。
4. 取得目标 Journal 写锁，初始化核心资源、绑定审批与事件、完成必要恢复维护和启动 Hook。
5. 发布可输入状态，等待新的用户输入。

查看另一会话不执行以上步骤；运行中的会话始终由全局占用条指示。切换“已加载运行会话”与切换“正在浏览的会话”必须在界面和 API 中分开。卸载后再继续属于新运行代次，会话级批准清空，永久批准重新读取；页面在继续入口说明这一区别。

采用一个已加载会话，减少每份历史同时持有 Provider、MCP 子进程与后台维护的开销。保留很多活跃运行会话会使停用与副作用追踪更复杂，不符合当前串行目标。新建后的空会话也使用同一显式继续入口。

### 3. 执行槽覆盖完整会话活动

管理器提供原子 try-acquire，冲突返回 project_busy，不使用等待锁把 HTTP 请求悄悄排队。现有 serialized_turn 仅串行化一个 ChatSession 内的顶层入口，不足以承担项目范围门禁。

状态采用浏览视图独立于运行状态的模型。运行状态为 unloaded、preparing、idle、running、awaiting_approval、background、maintenance、cancelling、blocked、closing。运行代次改变时旧控制版本失效；状态快照同时包含占用会话、顶层任务及活动原因。

执行槽包含：
- 主 Agent／Skill 流、工具和审批。
- TaskManager 中运行或排队的子任务、待消费结果及能够唤醒父任务的续跑。
- 当前会话所属活动团队成员、团队启动／暂停／整合操作；已注册但空闲或已暂停的团队不是活动任务。
- 启动、结束与控制 Hook、恢复／手动摘要、尚未收尾的记忆维护及清理操作。

将原 _idle_input 中的后台唤醒部分抽为不依赖输入终端的事件泵：观察 tasks.changed、next_parent 和团队通知，接续仍归原父任务及原预算。Web 重连不能创建第二个事件泵。活动登记、状态发布和槽释放在同一管理边界协调，避免任务结束事件与新子任务登记之间的空窗。空闲运行会话的新增维护必须先经门禁；切换开始后冻结旧代次的后续启动。

停止占用会话活动时，抑制后续唤醒、取消主子运行并暂停其所属活动团队，按照原权限／团队合同清理。无法确认结束或存档不可安全追加时保留 blocked 占用。仅有 finished 事件、HTTP 断连或计时器到期都不能证明空闲。

此门禁只协调本次 Web 进程。另一个 Web 实例或 CLI 不同会话可能操作相同项目；同一存档的并发写入仍由原 Journal 锁拒绝。

### 4. HTTP 操作与单向事件流

采用版本化 HTTP JSON 操作接口和 SSE。SSE 是服务向浏览器推送事件的通道，可携带事件 ID，浏览器重连可报告 Last-Event-ID。[FastAPI SSE 文档](https://fastapi.tiangolo.com/tutorial/server-sent-events/)

核心接口建议如下：

| 入口 | 用途 |
| --- | --- |
| POST /api/v1/auth | 将启动凭据换为本次服务的浏览器认证 |
| GET /api/v1/state | 项目、占用、当前运行状态和快照游标 |
| GET /api/v1/sessions | 分页会话列表 |
| POST /api/v1/sessions | 仅创建空会话，返回会话 ID |
| GET /api/v1/sessions/{id}/history | 只读分页历史与保留范围 |
| POST /api/v1/sessions/{id}/activate | 显式准备运行会话 |
| POST /api/v1/sessions/{id}/inputs | 解析一次明确输入并返回操作／任务回执 |
| POST /api/v1/sessions/{id}/controls | 模式、权限、摘要、重置及停止等类型化操作 |
| GET /api/v1/operations/{client}/{sequence} | 查询已提交操作回执 |
| GET /api/v1/approvals/{id} | 完整审批快照的分块审阅 |
| POST /api/v1/approvals/{id}/decision | 回答指定请求 |
| GET /api/v1/events | 当前服务的有序状态与展示增量 |
| GET /api/v1/results/{id} | 读取已登记且归属正确的保留结果快照 |

首次任务提交经验证和槽预留后快速返回 202 及 run_id，运行由管理器持有的 asyncio Task 驱动。handler 断开或取消只终止该响应，不关闭运行生成器。停止和状态修改走独立请求。

事件信封包含 schema_version、server_instance_id、seq、session_id、runtime_generation、run_id、parent_run_id、kind 和白名单 payload；调用／审批另带原身份。不得对 AgentEvent、Message、Config 或异常对象进行无差别 asdict 输出。嵌套子事件保持来源。

采用一个页面一条项目事件流，而不是每个面板或会话一条。HTTP/1 下浏览器的同源 SSE 连接数有限；本服务最多同时保留 2 条 SSE，多余页面转为短轮询同一状态／游标接口，留出控制请求连接容量。[MDN SSE 连接限制](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

备选 WebSocket 也能实现，但这里客户端动作是离散提交，使用普通 HTTP 能清楚表达回执、错误和审批关联，无需另建双向消息协议。

### 5. 重连、快照与幂等

任务状态先在管理器更新，再递增全局 seq 并发布事件。初次连接或游标失效时，在事件发布边界取得快照及 high_water_seq；订阅从其后一条开始。前端按服务身份和序号去重，收到 snapshot_replace 时整体替换对应运行投影，不把快照再次追加到聊天末尾。

事件缓冲上限为 4096 条或序列化后 8 MiB，任一先到即逐出最旧事件。单订阅者待发送队列上限 256 条或 1 MiB，慢客户端断开并要求重新同步，不背压 Agent。临时文本另以有界累计投影保存；快照丢失的临时片段明确标记。持久聊天正文从历史分页加载。

所有变更请求包含 server_instance_id、服务签发的 client_id、严格递增操作序号、操作内容摘要，以及相关 runtime_generation／状态版本。管理器为每个客户端保留已处理最高序号和最近 256 个回执：相同序号与相同内容返回原回执；内容不符、跳号或低于保留窗口的请求明确拒绝，旧操作永不变成新操作。每次启动最多登记 32 个客户端；达到上限明确拒绝新增，不通过淘汰身份使旧请求可再次执行。

client_id、下一个序号和未确认提交存入标签页 sessionStorage，刷新后先查询原回执，不能盲目新建序号重发。服务身份变化后旧操作一律失效；用户查看持久历史后才能明确创建新的提交。幂等不跨进程承诺“自动恢复执行”。

### 6. 历史展示与模型恢复分离

保留 JSONL 为唯一持久会话事实源：
- 模型恢复继续调用既有 build_projection：最后有效检查点及其后完整提交组决定工作历史。
- 网页展示新建只读视图：根据合法 history_commit、可验证的调用结果、任务记录和边界事件展示时间线；按消息身份去重，不把检查点再算一遍聊天。
- 历史上下文消息、Skill 展开内容与用户原始输入区分来源。存档没有保存的原始输入不推测还原。
- 未完成流式文本和供应商可展示思考只保存在本次服务有界内存中，不新增持久思考日志；重启后呈现已保存证据与缺失标记。
- 只读分页使用受控游标，单页最多 50 项且正文总量不超过 512 KiB；超大单项通过结果身份分块读取。扫描基于稳定记录边界，尾部并发追加或残缺行不成为可执行历史。长文件读取不阻塞事件循环，不为分页创建磁盘索引。
- 缓存引用只能经服务端登记身份解析并验证真实路径、归属与保留状态；客户端不能提交 file path 读取内容。浏览没有触发工具执行的后门。

Web 展示保留当前段及最近 10 个已结束段，临时正文总计 8 MiB、思考 256 KiB、每条工具参数／结果展示副本 64 KiB、元信息 1 MiB、每段调用索引 1024 项。以上是展示缓存限额，不截断传给执行器的有效参数。完整待审批快照单独保留至决定或过期，按 32 KiB 块提供，不能以缓存裁剪为由批准用户未能审阅的内容。来自工具本身的截断不能通过后续读取伪装恢复。

不直接复用 TerminalProjection 的文本输出；只提取纯状态归并或快照逻辑，分页、折行和终端控制符留在终端模块。

### 7. 审批、停止与关闭

ApprovalBroker 保存不可变请求、原始 PermissionManager 请求身份、所属代次、任务、创建／到期时间和一个等待 Future；decision 原子消费 Future。保留拒绝／本次／会话／永久语义，由原 PermissionManager 复核规则、目标及保存结果。

审批 TTL 为 10 分钟，从创建时开始计时，不因重连延长。超时交回 deny，并呈现 approval_expired；取消则交回原取消路径，不能混为一次普通拒绝。审批分块预览支持完整参数、写入正文和 edit 的 old_text／new_text 局部 diff；脱敏只影响呈现，批准始终绑定原请求。

普通停止进入 cancelling，等待生成器关闭、工具清理、子任务及相关团队活动停止、Hook／维护收尾后发布终态。控制按钮依据状态版本，重复停止返回同一过程。如果运行超过 30 秒仍不能确认收尾，转为 blocked 并保留执行槽和诊断；后续实际完成可恢复空闲，不强行宣布成功。

服务退出先拒绝新操作，令未决审批失效，通知所有运行取消，再按 Session、MCP、Provider 的所有权关闭。Web 使用服务器生命周期处理 SIGINT／SIGTERM，不复用终端 signal handler。SSE 在关闭阶段先发送可用的状态通知并主动结束，避免长连接阻止服务器进入清理。全局收尾预算 30 秒，MCP 单项及记忆维护继续使用已有更短上限；届满只能对明确由本服务拥有的进程执行既有强制清理，未知存活状态记录到脱敏诊断，不删除存档。再次启动按现有残缺存档恢复规则处理。

### 8. 浏览器界面与命令适配

前端选择 React + TypeScript，使用组件分离会话导航、对话、输入、工具详情和审批；状态分为服务端投影与本地 UI 状态，不复制权限判定。[React 组件说明](https://react.dev/learn)

默认三栏；详情可收起，窄屏通过抽屉访问。审批作为明确的任务卡片和详情面板展示，不自动提交、不通过浏览历史获得授权。详情布局区分待执行预览、真实结果及局部修改快照。

草稿按 project_key + session_id 保存在标签页 sessionStorage，服务提供稳定且不含秘密的 project_key。单条提交上限 256 KiB UTF-8；超限显式拒绝。Markdown 禁止原始 HTML，代码高亮及复制保持源文本，外部图片不自动加载；不将工具输出解释为界面指令。输入法组合键、粘贴和 Ctrl／Cmd+Enter 单独处理。

按钮与斜杠命令共用 command service 和参数校验。已有单行／多行解析、别名、动态 Skill 和 // 转义保持。WebContext 不使用终端 renderer；本地回复用结构化消息展示。/clear、/exit 的终端专属语义在 Web 明确不适用，不发送给模型；帮助标明这一点。/session 继续是查询，网页“继续会话”是独立入口，不扩展原命令语法。团队命令与工具如果触发所属成员活动，统一进入执行占用追踪，并使用通用任务／状态展示。

### 9. 本机访问和资源分发

Web 入口固定 127.0.0.1，默认端口 8765，提供 --port 但不提供 --host。启动在终端输出带随机片段凭据的本机链接；前端读取片段后立即从地址栏移除，以同源 POST 交换本次服务 cookie。凭据来自高熵随机数，不能采用模型密钥；cookie 为 HttpOnly、SameSite=Strict，名称按服务实例隔离。项目接口和 SSE 均要求认证；状态变更验证 Origin 精确匹配实际地址并限定 JSON 请求，不设置宽泛 CORS。启动片段、cookie 和请求正文不进入访问日志。

限制 Host 为实际 127.0.0.1:port，不信任代理转发头；设置禁止框架嵌入、禁止不可信内联脚本、仅本机连接的内容策略与 Referrer-Policy。静态路由只映射包内资源，项目数据禁止中间缓存，框架调试文档不公开。开发预览也经后端同源入口，不通过关闭认证来解决跨域。

Vite 负责将前端源码构建为可静态托管的产物。[Vite 生产构建说明](https://vite.dev/guide/build.html) 源码置于 frontend/，使用锁文件；生成产物置于 src/mewcode/web/static/ 并随源码提交和 wheel／sdist 分发。构建生成包含源码与锁文件摘要的 manifest，校验命令发现前端源码已变但产物未更新时失败。开发者更新前端后运行 npm ci 和 npm run build，普通 uv sync、uv build 及安装运行不调用 Node 或网络前端构建。静态文件和 manifest 纳入 setuptools package-data，应用启动检查完整性，缺失时在创建运行会话前给出构建提示。

选择提交生成产物会增加 diff，但保留当前 Python 安装体验；要求最终用户安装 Node 或用 CDN 动态加载与该目标不符。具体依赖版本由实现时 Python 3.11+ 与当前依赖兼容验证确定并锁定。

## Risks / Trade-offs

- [公共生命周期提取影响 CLI] → 保留终端适配层与入口签名，先覆盖通知、恢复、取消及关闭合同，再让两个入口复用。
- [主任务结束与后台任务状态存在竞态] → 建立统一活动登记与代次冻结，验证子任务、团队、自动接续、维护和取消全部路径，未能证明空闲时保持占用。
- [单个已加载会话切换时需要重新连接模型／MCP] → 浏览历史始终即时只读；只有明确继续才初始化，页面显示准备进度和授权重新加载语义。
- [SSE 窗口丢失或多标签连接受限] → 有界重放、原子快照替换、连接限额与短轮询后备，控制请求不依赖流连接。
- [JSONL 全量扫描随历史增长变慢] → 展示读取分块、分页、移出事件循环；保持存档为事实源，暂不引入第二套持久索引。
- [工具输出包含不可信内容或秘密] → 输出字段白名单、来源标记、已知秘密脱敏与安全渲染；批准绑定未被展示转换修改的原快照。
- [独立 CLI 仍能改写同一项目] → 界面和文档准确说明服务内串行范围，沿用存档写锁，不宣称项目全局隔离。
- [生成静态文件与前端源码不一致] → 锁文件、源码摘要及构建产物一致性检查，安装包实测缺失／陈旧资源。

## Migration Plan

1. 先建立公共生命周期和通知接点，原 CLI 行为通过定向回归；不改变存档格式。
2. 添加只读历史视图、串行运行管理、审批桥接及 API，以供应商替身验证完整运行／取消／重连。
3. 接入前端并构建随包静态资源；增加入口参数、同源访问、安装包校验及使用说明。
4. 在临时项目进行浏览器真实模型验收，并在 tmux 中回归原终端流程；保存本次脱敏证据。
5. 发布后可通过不使用 --web 回到终端；关闭 Web 释放会话锁后，使用原 --resume 恢复合法存档。回退不自动重跑任务，不删除存档、缓存或真实修改。

## Validation Strategy

- Python：运行核心生命周期、权限、会话恢复、Skill、后台子任务及团队相关回归，再运行完整 uv run pytest -q。
- API：替身流覆盖慢响应、重复提交、并发抢占、旧代次控制、审批竞态、无客户端超时、取消收尾、快照接续和服务重启。
- 浏览器：自动化验证输入法／多行粘贴、草稿版本、流式阅读位置、面板键盘操作、两标签审批、刷新不重发、窄屏和内容安全；单纯视觉断言不替代调用次数与文件产物检查。
- 分发：npm ci、前端类型检查与测试、npm run build、构建摘要校验、uv build；从生成 wheel／sdist 在临时环境验证静态资源和无 Node 运行路径。
- 真实验收：本次授权模型配置在临时项目验证读取、编辑、审批、取消及恢复；tmux 启动 Web 并用浏览器交互，同时另做原终端回归，对 checklist.md 逐项记录本次结果。计划阶段不把这些任务标为已执行。
