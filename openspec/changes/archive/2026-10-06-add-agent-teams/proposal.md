## Why

MewCode 已有一次性并行子 Agent 和 Git Worktree 隔离，但成员不能跨任务保留身份与上下文，也不能直接共享任务或互发消息。需要增加本地长期团队，使主 Agent 成为 Team Lead，管理任务依赖、计划审批及成果整合，并允许用户主动启用专注调度的 coordinator 模式。

## What Changes

- 新增固定绑定一个 Git 仓库的小组，持久保存名称、负责人、成员花名册、成员角色、工作目录、运行后端、计划审批要求和恢复位置。
- 在用户目录 `~/.mewcode/teams/<team-name>/` 保存团队配置、共享任务、名称注册表、成员邮箱及上下文引用；提供显式创建、恢复、暂停和成员停止能力。
- 第一版支持 tmux 独立窗格内的完整成员实例和同进程协程。自动模式先探测并公开选择；显式后端不可用或已选后端启动、运行失败时，不自动更换后端。
- 按普通入口、Lead、团队成员和普通子 Agent 身份过滤工具。团队参与者获得共享任务增删查改、原子领取及点对点消息；只有 Lead 能派生成员、审批计划、验收成果和整合代码。
- 消息先经名称注册表解析稳定成员身份，再写入邮箱；支持广播、计划请求／决定、空闲、成果提交和停止协议。先保存再唤醒，运行中的消息在下一请求边界消费。
- 邮箱及共享状态使用固定锁文件上的 `flock` 和有界重试，原子保存；时间过期仅用于诊断，不能抢占实际持有的锁。
- 需要审批的成员先提交带版本的计划，收到匹配的结构化批准后才能执行；计划批准不授予工具权限，现有 deny 优先、非交互许可和规划只读边界继续有效。
- 成员自然结束后保存上下文、标为空闲并通知 Lead。成员身份及会话不随单次运行结束销毁；后续消息可以恢复上下文继续指派，不重放旧工具。
- Lead 分解用户目标、登记依赖并派人；前置成果先验收、整合到团队分支，后续成员同步成功后解除阻塞。全部成果接纳后统一合并到用户目标分支。
- 整合串行且记录操作前检查点。无法解决的冲突只撤销当前失败操作，保留此前接纳成果和所有成员分支，阻塞依赖并上报。
- coordinator 使用配置能力开关和真实进程环境变量两把锁，只限制 Lead 本人的文件编辑工具及直接开发分工，保留读取、shell 和团队管理；代码及冲突编辑交给成员。
- Lead 退出时停止并收尾活动成员，保留团队和成果；只有显式恢复才重新运行。异常退出留下的未知操作须核查，不能当作正常空闲。

本轮不做跨机器团队、成员间实时流式通信、终端原生分屏适配、常驻后台守护进程或复杂依赖表达式。只创建规划文件，不修改产品代码、主规格或运行配置。

## Capabilities

### New Capabilities

- `agent-teams`: 仓库绑定的团队身份、用户域持久化、Lead 所有权及暂停／恢复。
- `team-member-runtime`: 稳定成员身份、两类后端、独立目录、空闲恢复、计划门禁和运行收尾。
- `team-tasks`: 共享任务 CRUD、原子领取、简单依赖、成果提交与解除阻塞。
- `team-messaging`: 名称注册表、文件邮箱、锁、投递／消费／唤醒和结构化协议。
- `team-integration`: 成果验收、团队分支中途整合、依赖同步、最终合并及单操作回滚。

### Modified Capabilities

- `tool-system`: 团队身份的声明及执行双重过滤，协调角色自用范围与委派上限分离。
- `provider-configuration`: 团队后端选择、运行容量及 coordinator 双开关的配置合同。
- `session-persistence`: 成员会话存档、邮箱消费检查点、独立写入归属与恢复引用保护。
- `tool-permissions`: 计划审批与工具授权分离，成员当前权限及内部管理副作用的检查。
- `plan-mode`: 规划模式对团队派生、任务变更、执行唤醒和代码整合的只读上限。
- `interactive-chat`: 团队状态、后端诊断、协议审批结果、阻塞和退出反馈。

## Impact

- 建议新增 `src/mewcode/teams/`，接入 Agent 循环、会话、CLI／交互、工具注册与执行、权限、配置、提示和 Worktree 模块，避免把团队编排集中到入口文件。
- 复用现有 `agents/` 角色、Provider、上下文编码、`worktrees/` 与 `flock` 基础能力；保留普通 defined／fork 子任务的一次性执行、禁止嵌套及不恢复后台队列合同。团队成员是独立的运行类别。
- 依赖现有 Git CLI，独立进程后端额外依赖 tmux；协程后端不提供操作系统沙箱。成员 Provider／MCP 的共享或独立所有权随后端明确区分。
- 新增团队工具及显式恢复控制入口，文档说明配置、权限准备、冻结基线、依赖代码可用性和 coordinator 的工具层分工边界。
- 实现阶段同步 README、checklist，覆盖双后端、竞争、恢复、错误、取消及权限；按仓库要求在临时 Git 项目用真实授权模型和 tmux 做本次验收。
- 当前 `add-worktree-isolation` 已完成且相关代码已存在；实施前核对其归档／主规格状态，本变更不代为归档或改写该变更。
