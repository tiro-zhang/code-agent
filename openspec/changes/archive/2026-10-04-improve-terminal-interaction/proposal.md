## Why

MewCode 的终端已能完成自主任务和权限审批，但逐行输入不适合粘贴代码，缺少交互内命令帮助，重复的进度、用量和授权输出增加了阅读成本。已有真实验收中，三次工具调用的读取、编辑与验证产生约 90 行输出；本轮聚焦让用户容易输入、辨认当前状态并审阅待批准操作。

## What Changes

- 为支持交互能力的终端提供多行草稿、整块粘贴、当前进程内的输入历史和明确的发送／换行提示；聊天与审批输入相互隔离，非交互输入保留逐行兼容方式。
- 新增 `/help`、斜杠命令补全和本地用法校验；帮助同时列出已有规划、执行、退出和权限指令，以及本轮新增的 `/status`。
- **BREAKING**：未识别的斜杠命令和已知命令的非法参数不再发送给模型；使用 `//` 前缀可将以 `/` 开头的文本作为普通消息发送。有效的既有命令保持原有行为。
- 将当前模式、权限模式、模型请求次数及执行阶段归入持续更新的状态摘要；每个工具保留关联清晰的完成摘要，通过 `/status` 查看当前状态与最近任务的逐请求真实用量，减少重复刷屏。
- 统一授权呈现入口：摘要、完整参数、正文／差异和真实目标分层展示，按终端尺寸分页；审批输入区域保持清晰，其他调用的结果不插入当前决定提示。
- 保持四种授权决定、默认拒绝、权限判定、规划限制、取消／EOF 和工具实际启动语义；保留纯文本输出及可注入输入／审批通道。

## Capabilities

### New Capabilities

无。本轮扩展既有终端交互合同。

### Modified Capabilities

- `interactive-chat`：多行输入与命令帮助、状态和用量摘要、单一授权呈现及兼容终端行为。

## Impact

- 涉及 `src/mewcode/app.py`、`permissions/terminal.py` 和会话控制接线；输入编辑、命令路由及展示状态放入独立终端模块，复用现有 Agent 事件与权限回调。
- 预计新增一个支持异步输入与终端布局的依赖，具体采用边界见 design；不改变 Provider 协议、模型工具 Schema 或权限配置格式。
- 实现阶段需更新 README、终端相关自动化测试与 checklist，并在 tmux 中完成真实多行对话、工具执行和审批验收；本次仅生成规划产物。
- `add-mcp-client` 已完成实现及验收，作为本方案的既有实现基线。终端改造须保留 MCP 启动／关闭诊断、外部工具身份、精确授权范围及取消语义，并在新界面中重新验收。该变更随后已同步主规格并归档至 `archive/2026-10-04-add-mcp-client`；本轮以更新后的主规格为基线，保留 MCP 的既有要求和场景。

## Non-Goals

- 不新增会话持久化、任务恢复、自动重试、退出规划指令或空闲 Ctrl+C 行为变更。
- 不改变权限模式、授权范围、规则优先级、批量批准语义或撤销能力；不新增逐项授权选择、规则解释引擎或逐项撤销。
- 不新增 MCP 能力、实时 shell 日志、完整工具结果浏览器、Markdown 渲染器或全屏多面板工作台。
- 不修改主规格、其他变更、产品代码或历史验收结论；代码与文档实施由后续 apply 阶段完成。
