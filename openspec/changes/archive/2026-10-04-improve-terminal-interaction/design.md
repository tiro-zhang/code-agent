## Context

动机与本轮范围见 [proposal.md](proposal.md)。当前 `app._run` 逐行读取输入并分派命令，`_Renderer` 直接追加事件文本；`permissions.terminal.TerminalApproval` 又独立写入同一输出流，因此待授权提示可能被并发工具结果插入。`InputReader` 的可取消 fd 监听已解决后台读取吞掉后续输入的问题，这一保障不能在引入编辑器后丢失。

Agent 已提供接收、实际启动、结果、权限请求／解决、用量及停止事件，权限回调也可以注入。本轮复用这些边界，不重写 Agent 调度；现有 `StringIO`、pipe、PTY、权限及取消测试是兼容基线。任务用量是服务返回的实际统计，包含未知和不完整字段。

本变更引入终端依赖，横跨输入、事件展示和审批生命周期，且涉及输入隔离与控制字符处理，因此需要 design 产物。`add-mcp-client` 已完成实现及验收，现有 `app._run` 已在首次聊天输入前启动 MCP、绑定外部工具权限，并在退出时先关闭 MCP 再关闭 Provider。MCP 随后已同步主规格并归档至 `archive/2026-10-04-add-mcp-client`；设计以更新后的主规格和当前代码为基线。

## Goals / Non-Goals

**Goals:**

- 一个终端所有者管理输入、状态和审批，使活动任务与编辑草稿互不抢占。
- 把可更新状态和必须保留的对话／终态记录分开，降低普通事件刷屏，保留真实过程与异常证据。
- 让增强终端与纯文本后端共用命令解析、脱敏及展示数据，保持可注入测试边界。

**Non-Goals:**

- 产品范围按 proposal 的 Non-Goals；布局不决定工具是否获准，不合并授权范围，不重放任务。
- 不把渲染器状态写入模型历史，也不从模型输出中解析授权或本地控制命令。
- 不持久化 UI 历史或引入完整屏幕工作台；正文继续保留在终端滚动记录中。

## Decisions

### 1. 已确认范围与拟议默认值

已确认的是多行输入、命令帮助、状态摘要、授权布局四项，以及权限判定不变。以下是本方案供评审的具体默认值，不声称用户已逐个指定：Enter 发送、Esc 后 Enter 换行；命令仅在单行草稿生效，`//` 转义为普通斜杠消息；新增 `/status`；采用单一非全屏终端应用；只记录当前进程输入历史与最近一轮的展示统计。

空闲 Ctrl+C 仍退出，活动任务中 Ctrl+C 仍取消本轮。退出规划、编辑后重试、会话恢复等前期探索建议不进入本轮任务。

### 2. 一个异步终端所有者，两个后端

采用 `prompt_toolkit` 作为增强后端唯一的键盘解析与布局依赖，建立一个非全屏 `Application`，在现有 asyncio 循环运行。输入、状态与审批共享同一应用；不用 `PromptSession` 和独立实时输出组件各自控制光标。仅使用短期 PromptSession 的方案较小，但其底部工具栏在 prompt 返回后消失，不满足工具执行期间持续状态展示。

建议新增 `src/mewcode/terminal/`，按职责分为控制器、输入／命令、展示状态和审批视图；名称可依邻近代码调整，不建立通用插件框架。`app.py` 保留启动与任务编排，`session.py` 暴露只读计划可用状态，权限模块保留批准判定及存储。现有审批适配器转为请求终端控制器展示并等待决定，不再自行打印第二份界面。

增强能力仅在输入输出均为 TTY 且终端支持所需控制时启用；`TERM=dumb`、重定向及不可交互注入流使用 plain 后端。不额外打开 `/dev/tty` 绕过用户指定输入输出。plain 后端复用现有异步逐行读取，输出清晰的追加日志而不是光标重绘；布局初始化失败须先恢复终端再退回 plain，不能让两个输入读取者并存。缺少已声明依赖属于安装错误，不静默伪装为功能正常。

上游依据（实施时选择可安装且支持 Python 3.11 的稳定版本并更新依赖锁文件）：

- [输入与异步支持](https://python-prompt-toolkit.readthedocs.io/en/stable/pages/asking_for_input.html)。
- [Application、输入、布局与终端输出 API](https://python-prompt-toolkit.readthedocs.io/en/stable/pages/reference.html)。
- [底部工具栏的生命周期](https://python-prompt-toolkit.readthedocs.io/en/stable/pages/asking_for_input.html#adding-a-bottom-toolbar)。
- [括号粘贴解析](https://github.com/prompt-toolkit/python-prompt-toolkit/blob/main/src/prompt_toolkit/input/vt100_parser.py)及[默认粘贴处理](https://github.com/prompt-toolkit/python-prompt-toolkit/blob/main/src/prompt_toolkit/key_binding/bindings/basic.py)。这些源码链接用于确认能力，不要求跟随未发布主分支。

### 3. 用显式输入阶段隔离聊天与审批

控制器维护以下状态，不改变会话的 plan／execute 任务模式：

```text
STARTING --ready--> IDLE
STARTING --cancel--> CLOSING

IDLE --submit--> RUNNING --request--> APPROVAL
 ^                  ^                    |
 |                  +-----decision-------+
 +------finished-------------------------+
 |                                       |
 +-----------cancel + cleanup------------+

IDLE --exit/EOF--> CLOSING
APPROVAL --EOF--> CANCEL + CLOSING
```

STARTING 覆盖现有 MCP 初始化及工具发现，此时不接受聊天任务；启动取消沿用清理后退出的行为，不转入聊天。配置跳过或个别 Server 失败不阻止其他可用工具进入 IDLE。CLOSING 保留输出所有者直至任务收尾、MCP 和 Provider 清理诊断输出完成，再恢复终端；清理期限沿用现有管理器，不因状态动画延长。

聊天草稿与审批输入使用独立 Buffer 和按键集合。RUNNING 不允许提交新聊天任务；APPROVAL 不启用聊天历史或斜杠补全。每次进入新审批请求、任务结束或取消，切换输入代次，清理上一阶段的交互草稿、已解析按键、提交队列和未完成粘贴；仅 `tcflush` 不足以覆盖终端库内部已解析输入。回调及提交记录携带当前代次和 request_id，过时代次不得产生决定。该清理不适用于 plain 非 TTY 问题流预读的后续完整行：它们属于逐行协议队列，必须依次处理，且不能被审批消费者读取。

可识别的括号粘贴只插入文本，不触发发送。审批中的单行括号粘贴也须随后明确提交；多行答案作为无效决定处理，不能按换行拆成多个批准。旧请求中已接收的第二个数字在切换时丢弃；plain 或不支持括号粘贴的终端无法可靠区分分批到达的粘贴和新按键，因此只保证清除已有残留，不以速度启发式冒充绝对粘贴隔离。详情翻页发生在同一请求代次内，不清掉当前合法浏览输入，也不消耗批准。

raw 模式的 Ctrl+C 键事件与外部 SIGINT 都接入现有取消 Event 和受控清理路径；不把 UI 库默认 KeyboardInterrupt 直接当作应用退出。重复取消使用已有保护机制，真实 EOF 保留阶段对应的退出语义。退出 finally 恢复终端回显、光标、括号粘贴模式及监听器；不要依赖正常返回才恢复。

### 4. 多行编辑与命令路由使用独立模型

聊天 Buffer 使用多行编辑，Enter 在非粘贴状态提交，Esc+Enter 插入换行；Alt+Enter 仅作为能发送同等序列的终端别名，不依赖兼容性不一的 Shift+Enter。帮助始终显示可移植的 Esc+Enter。没有括号粘贴能力时不靠输入速度猜测粘贴边界，用户可使用手动换行；plain 模式明确保留一行一个问题。

普通消息不再整体 `.strip()` 后提交，只用它判断是否全为空白；CRLF／CR 统一为 LF，缩进、空行和尾部文本保留。输入历史仅保存已提交普通消息，位于首／末行时使用上下键选择历史，其他时候移动光标；审批值和控制指令不进入历史。历史是 UI 的易失缓冲，不影响 `ChatSession.history` 的成对提交和裁剪。

维护一个本地命令表供帮助、补全与分派共用，避免 README、提示和处理器分别维护语法：

| 输入 | 行为 |
| --- | --- |
| `/help`、`/status` | 本地只读展示，拒绝额外参数 |
| `/exit`、`/do` | 保持原行为，拒绝额外参数 |
| `/plan`、`/plan <单行任务>` | 保持原有规划语义 |
| `/permissions`、`mode`、`revoke` 子命令 | 使用现有严格处理器及合法值 |
| 未知 `/命令` | 本地用法错误，不调用模型 |
| 单行 `//文本` | 去掉首个斜杠后作为普通消息 |
| 任意多行草稿 | 整体普通消息，内部命令不执行 |

要在规划模式提交多行任务，先单独 `/plan`，再提交多行草稿。只在用于识别单行命令的副本上处理外侧空白；保留普通消息原文。补全仅用于已知命令及枚举参数，不自动补全文件内容，不在运行或审批时生效。命令提示必须完整写明 `/permissions revoke session|permanent` 的实际语法。

### 5. 可更新状态与追加正文分别存放

展示状态由现有 AgentEvent 更新，采用 `(run_id, tool_call_id)` 关联调用，本轮显示短编号如 `#1`、`#2`，避免直接截断 UUID 产生冲突；授权详情显示对应调用，任务结束后的 `/status` 提供最近任务的短编号、完整调用 ID、工具与终态表。该编号只服务展示，不替代执行或授权身份；这个状态表不扩展为完整工具结果浏览器。

增强区域包含状态摘要、活动调用和当前输入／授权区域。正文与思考通过统一输出通道追加到终端滚动记录；可使用 `run_in_terminal` 的受控输出机制，再恢复增强区域。所有模型文本和诊断先经过相同脱敏及控制字符处理，工具返回文本不能作为布局指令。不要同时安装多个 stdout 拦截器，也不要让审批回调、Renderer 和依赖诊断直接争用 stdout。

当前阶段与活动调用按状态变化更新；已完成调用从活动区移除，追加一条终态摘要。相同事件不会产生重复摘要；当前请求尚未批准时不能显示其工具已启动。若审批正在展示，完成摘要先保存在状态模型，增强后端在独立状态区体现，待审批关闭后追加到正文；plain 后端将旁路事件暂存，在本次决定结束与下一个提示之间按调用输出，保证活动操作和选项不被插断。错误、取消、截断、范围受限和保存失败不得丢弃；增强后端立即显示，plain 后端在上述安全边界显示。

任务 elapsed 使用单调时钟，授权期间继续显示真实经过时间，但不修改工具执行期限。刷新使用有界频率与批量失效通知，正文流仍在完成前可见，不逐字符重建整个历史。UI 不缓存完整工具结果或第二份无限对话记录；活动调用结束后只保留必要映射和最近任务摘要，正文由终端滚动区承载。

状态缩小时保留双模式、阶段和当前授权标识，长项目／模型名可缩略但能从 `/status` 看全。处理中文宽字符、制表符和 resize，不按 Python 字符数固定折成 100 列。极小终端仍提供可滚动详情与决定输入；空间不足时用文字提示引导浏览，不能裁掉范围后留下一个无上下文的批准按钮。

### 6. 用量摘要保留完整统计访问

不修改 TokenUsage 的统计口径。最近一次请求与累计摘要保留总输入、输出、缓存命中率及未知／不完整标记；已有缓存命中、未命中和实际写入字段保留在最近任务的逐请求记录中。任务结束留下紧凑累计行，空闲 `/status` 以表格展开最近任务各请求及累计所有字段；任务进行时不把 `/status` 插入 stdin，也不因刷新额外请求模型。

状态记录在新任务开始时切换为新任务，清晰标记尚无用量；本地命令不会清空最近任务统计。没有任务时显示“暂无任务记录”。退出后这些记录不恢复。plain 后端继续输出逐请求完整用量与阶段行，确保重定向日志没有被动态状态区吞掉。

### 7. 授权摘要、目标与参数使用同一个审阅数据源

权限管理器继续通过可信 responder 等待 `deny/once/session/permanent`。终端控制器接收请求后创建一次活动视图，`permission_requested` 事件只补充调用关联与状态，不再打印第二份提示；事件与回调到达顺序任意时都按 request_id 幂等关联。`permission_resolved` 只完成同一请求，不能关闭另一请求的视图。

首页显示工具、可读操作、原因、根目录、适用的目标数量及期限／范围，写入和编辑优先显示正文／diff 的可浏览视图，原始 JSON 放入明确的“参数”视图；全部视图基于同一份不可变请求快照。本地文件／搜索目标列表也进入分页系统，不在标题中一次打印数百路径；shell 展示完整精确命令，MCP 工具沿用现有身份与精确参数范围，接线见第 8 节。目录分组只是显示结构，不改变批准集合或授权粒度。保留 next/back/all 意图并提供固定的返回和决定入口；增强后端的 all 打开完整可滚动内容，plain 保留完整文字输出。

长内容仍必须能在决定前看全，但不强制用户逐页点完，也不把已看页数当作授权。diff 仅依据调用已提供的原文／新文，不为了补文件上下文去读取未获准文件。合法决定值、空答拒绝、默认拒绝、审批后复检和存储失败降级均不由 UI 修改。无可信通道的 plain 输入不能充当授权，程序注入的可信 responder 仍可独立使用。

### 8. 保留已实现的 MCP 接线与生命周期

本轮只修改 interactive-chat 中“提示符式交互”“进度与用量展示”，其余布局规则使用新增要求，保留 MCP 已实现的“工具状态可见”“人工授权决定”“未完成轮次处理”及启动／关闭合同。MCP 已同步主规格；本轮实施／同步时需对照更新后的主规格，不能用旧完整块覆盖其新增场景。

`app.py` 保留加载 MCP 配置、创建 `MCPManager`、绑定 `session.executor.mcp`、等待 `start(cancel_event=...)`、再调用 `bind_mcp_tools(mcp.tools)` 的顺序。MCP 的 `notify` 诊断不经过 AgentEvent，必须单独接入同一输出所有者，保留 Server、阶段及连接／发现／注册结果。`MCPManager` 已将后台诊断投递到主事件循环；UI 消费这个边界，不进入每 Server 的 SDK owner 线程，也不迁移其连接所有权。退出仍受保护地先关闭 MCP、再关闭 Provider；关闭失败或未确认资源回收的提示必须在终端恢复前输出。

授权视图直接消费 `ApprovalRequest.external` 中的 Server／原始工具名、`tool` 稳定别名、`connection_description` 安全连接描述及现有参数快照，不重新读取连接配置生成展示。展示通用工具名，不把工具数写死为六个；不把 MCP 的 path 参数描述为经过验证的本地真实目标。会话／永久范围仍绑定真实项目根、Server 有效配置身份、原始工具及规范 JSON 参数，本次批准还绑定当前调用；参数或连接身份变化即失效。保留永久批准会保存完整调用参数的提醒，展示继续脱敏且不输出连接 env、headers 或 URL 凭据。

MCP 的工具开始事件仅在 `tools/call` 实际发送后产生，不能以批准或进入队列代替。发送后取消／超时保留“远端可能仍在执行或已有副作用”，未发送则保留未启动标记；`mcp_unavailable` 保留所属 Server 与具体失败原因。单次取消继续使用现有调用取消路径，不关闭共享连接，不重发调用，也不声称远端已停止或已回滚。授权 EOF 仍先取消并收尾本轮，再关闭连接退出，区别于普通拒绝和 Ctrl+C 取消后继续聊天。

现有 [MCP 验收记录](../archive/2026-10-04-add-mcp-client/evidence/verification.md)及 [tmux 记录](../archive/2026-10-04-add-mcp-client/evidence/tmux-report.md)作为回归基线。本轮必须在新终端后端重新验证 stdio 与 Streamable HTTP 的诊断、授权、状态、取消后复用及退出；历史通过记录不代表新界面通过，不修改 MCP 原任务或验收结论。证据链接指向已归档的 MCP 变更。

## Risks / Trade-offs

- [raw 模式与旧 SIGINT 处理不同] → 同时覆盖按键事件、外部信号及重复取消的 PTY 验证，确保只走一条清理路径。
- [旧 Buffer 或已解析按键越过审批边界] → 输入代次、独立 Buffer、切换清理与多答案粘贴回归联合验证，不能只清内核输入队列。
- [非全屏重绘破坏流式正文或审批关联] → 单一输出所有者，正文受控追加，审批期间其他摘要进入独立状态区；tmux 检查两工具并发与长文本。
- [摘要减少可见细节] → 异常始终显示，完整用量通过 `/status` 可查，原始参数／目标／差异在批准前可查；plain 输出保留详细记录。
- [终端能力和窗口尺寸不同] → 以可移植 Esc+Enter 为基准，覆盖中文、窄窗口与 resize；能力不足时明确降级，不猜测粘贴速度。
- [未知斜杠文本不再调用模型] → proposal 标注 BREAKING，启动帮助和 README 说明 `//` 转义及多行正文处理。
- [终端接管遗漏 MCP 旁路诊断或破坏已实现生命周期] → 将 notify 和审批字段接入同一终端所有者，覆盖 STARTING／CLOSING、调用取消后连接复用及双传输回归；保留 SDK owner 和现有清理期限。

## Migration Plan

1. 在本轮实施中新增依赖和终端后端，先保持 plain 后端及原有注入接口可用，再接入输入和状态模型。
2. 按命令、草稿、状态、审批依次接线，整个阶段由同一 stdin／stdout 所有者接管，不同时开启两套读取循环。
3. 更新 README 与 checklist；用临时项目和已授权真实模型配置进行 tmux 验收，并保存脱敏记录。用 PTY 覆盖极端输入与并发时序；纯状态或字符串快照不能代替真实按键验收。
4. 无权限文件或持久数据迁移。增强布局不适用时自动使用 plain；回退代码时原有权限批准仍可读取。运行中降级必须先取消未决审批并恢复终端，不得通过回退路径默认批准。

## Validation

- 输入：多行／尾部换行粘贴只生成一次提交；缩进与空行保持；历史只编辑不执行；命令边界和 `//` 可预测。
- 交互：本地帮助／补全／非法命令零模型请求；空闲双模式可见；状态 elapsed 不冒充完成度或工具执行超时。
- 审批：同请求单一视图，完整参数／差异／目标可访问；并发结果不打断决定区域；切换、取消及多答案粘贴都不串答。
- 兼容：plain、StringIO、pipe 和可信 responder 仍可用，未知用量和受限结果不丢失，真实流式输出保持。
- MCP：stdio 与 Streamable HTTP 的启动／关闭诊断、身份与精确授权范围完整；请求发送前后状态准确，取消后的副作用提示及连接复用保留；覆盖初始化取消、授权 EOF 和关闭失败提示。
- 实际验收：在 tmux 中完成粘贴需求、帮助与错误命令、读取／编辑／验证、长详情与 resize、并发授权、Ctrl+C／EOF 及取消后继续对话，逐项记录 checklist。所有结果在实施后实际获得，本设计不预先宣称通过。
