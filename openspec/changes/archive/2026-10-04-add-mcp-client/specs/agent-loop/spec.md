## MODIFIED Requirements

### Requirement: 连续未知工具终止
系统 SHALL 按完整工具响应统计连续未知工具轮数。某响应全部调用的名称都未注册时 SHALL 累计一次，并为每个调用生成 `unknown_tool`；包含任一已注册名称时 SHALL 清零，不因该调用参数无效或被当前模式禁止而改变注册判断。连续 3 轮全部未知时 SHALL 在保存第三轮结果后以 `unknown_tool_limit` 停止。上下文恢复的失败尝试 SHALL NOT 改变该计数。

#### Scenario: 一次返回三个未知调用
- **WHEN** 一个正常完成的响应包含三个未注册工具调用
- **THEN** 每个调用获得错误结果，但连续未知轮数只增加一次

#### Scenario: 连续三轮全部未知
- **WHEN** 连续三个完整工具响应都只包含未注册名称
- **THEN** 系统保存全部调用及错误结果，以 `unknown_tool_limit` 停止，不再请求模型

#### Scenario: 混合调用清零
- **WHEN** 已累计未知轮数，随后响应同时包含已注册和未注册工具
- **THEN** 连续未知轮数清零，未注册调用返回错误，已注册调用进入正常的模式和参数检查

#### Scenario: 已注册外部工具失联
- **WHEN** 模型调用此前已成功注册但所属 Server 当前不可用的 MCP 工具
- **THEN** 该调用返回 mcp_unavailable，仍按已注册名称清零连续未知轮数，不把连接故障计为 unknown_tool

### Requirement: 按顺序安全分批
系统 SHALL 保留模型调用列表顺序，仅并发连续的只读工具调用，最多同时执行 4 个。每个非只读调用 SHALL 构成串行边界，后续调用 SHALL 在前序批次全部完成及清理后才开始；shell 命令与 MCP 工具 SHALL 始终属于非只读调用，MCP 工具即使具有 Server 声明的只读提示也 SHALL 形成串行边界。未知、禁止或非法参数 SHALL 返回对应结果而不启动工具。普通错误和超时 SHALL NOT 自动取消同一响应的其他调用。

#### Scenario: 连续读类工具并发
- **WHEN** 一个响应包含多个连续的 `read_file`、`glob_files` 或 `search_code` 调用
- **THEN** 这些调用可并发执行，活动执行数量不超过 4

#### Scenario: 修改后的读取
- **WHEN** 调用顺序是读取 A、编辑 A、再次读取 A
- **THEN** 编辑等待前序读取完成，第二次读取等待编辑结束，不能提前读取修改前的内容

#### Scenario: shell 形成串行边界
- **WHEN** 连续读调用之间包含一个看起来仅查询状态的 shell 命令
- **THEN** 系统仍将该命令作为串行边界，不根据命令文字放入只读并发组

#### Scenario: 一项工具失败
- **WHEN** 同一响应中一个工具返回错误或超时，其余调用仍可执行，且用户没有取消
- **THEN** 系统保留失败结果并继续处理其余调用，再将全批结果回灌模型

#### Scenario: 结果完成顺序不同
- **WHEN** 并发工具按与模型调用列表不同的顺序完成
- **THEN** 结果事件可按完成顺序发布，历史中的结果仍按原始调用顺序保存，每个调用 ID 恰好对应一个结果

#### Scenario: 外部工具形成串行边界
- **WHEN** 调用顺序是本地读取、MCP 工具、再次本地读取，且外部工具被 Server 声明为只读
- **THEN** MCP 调用等待前序读取完成，后续读取等待 MCP 调用得到结果并完成本地收尾，不把外部调用加入只读并发组

### Requirement: 取消后完整收尾
用户取消 SHALL 停止剩余调度和后续模型请求、关闭活动模型流、终止活动本地工具及受控的同组子进程，并对活动 MCP 工具通过 SDK 取消单次请求和结束等待；系统 SHALL 在发布终止事件前完成本地受控资源回收及历史配对。远端请求取消 SHALL NOT 被描述为外部执行已停止，远端完成状态不确定时 SHALL 说明可能仍在执行或已产生副作用。系统 SHALL 保留已经完成的实际结果，对开始但未完成的调用返回 `cancelled`，对未开始的调用返回带 `details.not_started=true` 的 `cancelled`。已发生的影响 SHALL NOT 被描述为已回滚。用户取消状态 SHALL 来自可信的本地任务取消信号，SHALL NOT 仅因远端错误代码、消息或结果正文包含 `cancelled` 而触发。

#### Scenario: 取消并发工具
- **WHEN** 用户在多个只读工作进程活动时取消任务
- **THEN** 系统终止并回收所有活动工作进程，各调用都获得完成或取消结果，后续批次不启动

#### Scenario: 取消尚未启动的调用
- **WHEN** 用户取消时，完整响应中的后续串行调用仍未开始
- **THEN** 这些调用获得明确标注未启动的取消结果，不产生工具副作用

#### Scenario: 工具已经返回结果
- **WHEN** 工具已经完成，用户在清理或下一次模型请求期间取消
- **THEN** 已完成的实际结果保留，不能声称该操作未发生；任务以 `cancelled` 停止

#### Scenario: 清理期间再次取消
- **WHEN** 用户在取消清理期间再次按 Ctrl+C
- **THEN** 系统完成进程回收和调用/结果配对，仅发布一次终止事件并恢复输入

#### Scenario: 取消正在进行的外部请求
- **WHEN** 用户在 MCP 工具请求进行期间取消本轮任务
- **THEN** 系统取消该单次请求、结束等待、补齐对应结果并停止后续调度，不主动终止整个外部 Server，不自动重发调用；已完成真实结果保留，未确定完成状态的调用明确报告可能的远端副作用

#### Scenario: 远端错误文字不是用户取消
- **WHEN** MCP Server 返回包含 cancelled 的错误，但用户没有发出任务取消信号
- **THEN** 该结果作为普通工具错误配对保存，循环可在剩余预算内继续，不伪造用户取消或取消其他调用
