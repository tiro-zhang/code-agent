## Context

动机与范围见 [proposal.md](proposal.md)。现有 `TerminalController` 统一管理输出和审批，`EnhancedTerminal` 使用非全屏 `prompt_toolkit.Application`，完整正文行进入终端滚动记录，尚未换行的片段显示在活动布局中。`TerminalState` 已按任务和工具标识关联事件；`_Renderer` 仍把思考、子 Skill 和维护事件直接转换为逐行文本。聊天提交会清空编辑缓冲，但没有统一的提交回显。

当前命令注册表已有描述、用法及同代 Skill 快照，Tab 补全、粘贴隔离、默认拒绝、权限复检和取消清理均已具备。设计保留这些边界。本次横跨事件投影、流式格式、输入阶段与审批审阅，满足跨模块和安全／兼容复杂度条件，创建 design 产物。

## Goals / Non-Goals

**Goals:**

- 让正文、短暂状态、需要决定的操作和按需详情各有稳定位置，正常输出量随对话段落增长，不随每个底层事件增长。
- 用一个展示投影处理父任务、子 Skill、审批和维护，明确每条记录的来源及用途，不在终端后端重复实现计数规则。
- 在现有终端所有者下实现即时阅读和详情浏览，保持当前输入代次与授权关联的可靠性。

**Non-Goals:**

- 产品边界沿用 proposal；不新增全屏滚动历史、会话切换器、任务队列或持久日志服务。
- 不改变模型历史、调用调度、权限对象、Token 计算、思考请求参数或后台记忆算法。
- 不承诺完整 CommonMark 排版、执行 Markdown／终端链接、系统剪贴板集成或所有终端支持相同键位。

## Decisions

### 1. 保留非全屏架构，增加统一展示投影

继续由 `TerminalController` 持有输入／输出所有权。将事件归一化、聚合和详情保存放入 `terminal/` 下职责清晰的展示模块，`app.py` 只接线。展示记录带顶层任务、子运行来源、调用标识、用途及真实终态；维护记录走独立用途，不修改工作任务计数或结束状态。

投影产生三种结果：更新活动状态、追加稳定正文／摘要、更新最近任务详情。增强与 plain 后端共用这一结果；plain 没有原地重绘，只在实际阶段改变时输出简短状态，并在聚合边界输出摘要，不输出计时刷新或控制码。

不选仅在 `_Renderer` 中过滤字符串：这无法可靠处理 Skill 来源、聚合数量和事件去重。不选全屏重写：现有终端滚动记录和输入安全边界足以承载本轮需求。

### 2. 提交回显与对话段落

输入确定提交后，将普通问题或提示词命令的原始文字经统一安全展示追加一次；保留多行缩进及空行。以 `//` 转义的输入回显用户所写内容，实际模型输入仍按原解析规则转换。Skill 的展开 SOP 不回显为用户正文。

本地命令的结果使用“本地”类别，可保留原命令说明来关联反馈，但不生成工作轮次、重置最近任务或加入输入历史。空白提交、选择菜单候选和关闭详情不回显为提交。`/clear` 的清屏意图优先，不立即重新打印已清掉的提交记录。

增强终端用角色标题、间距和适度样式区分用户、助手、操作摘要、警告；同一来源的连续正文片段只显示一次标题。由子 Skill 返回主调用的同一已展示结果可通过结构化来源标识标为“子任务结果已在上方展示”，不再次打印全文；父模型随后新生成的答复始终正常显示，不以文本相似度删减模型内容。

### 3. 成功调用聚合与异常保留

运行中在活动区更新真实操作和累计完成数量；成功结果不立即逐条进入正文。助手正文开始、新的人工授权出现、异常到达、来源切换或任务结束时，先提交之前累积的成功摘要，再输出当前事件。未完成调用仍保持活动状态；晚到结果归入之后的分组，不移动既有正文。一次事件重复到达不得重复计数。

按来源和操作类别聚合。不同文件读取按已知规范目标去重；同一文件分页／重复读取记录读取次数，例如“读取 1 个文件（3 次）”。无法确认目标身份时只报“完成 3 次读取”，不以路径字符串猜测不同文件。搜索按成功调用次数统计；写入／编辑区分动作和目标数；命令只报告执行及实际退出状态，不推断测试通过。MCP 或其他扩展按真实工具身份计调用次数，不将任意 `path` 参数解释为本地文件。

失败、拒绝、取消、超时、截断、搜索受限、永久批准保存失败及副作用未知单独显示，包含短调用标识、操作和影响。结果即使 `ok=true`，只要存在这些注意事项就不进入普通成功组。审批期间保留现有旁路结果通道：优先显示异常，完整记录可通过 `results` 审阅，正文在安全边界追加。

### 4. 一行状态与一次结束摘要

状态区以当前双模式、阶段、实际耗时和请求次数／上限为核心；窄屏优先保留双模式、阶段及当前授权身份，不靠截断隐藏需要决定的对象。空闲后显示当前模式和等待输入，不重绘上轮整段统计。

每轮只追加一条结束摘要，包含可读结束原因、耗时、请求次数、累计输入／输出以及未知或不完整标记。正常停止可显示“本轮结束”，不能自动称为业务目标成功。缓存命中率、读／写／未命中和最近请求的完整字段进入 `/status`，其中统计计算与工作／摘要／记忆／恢复的归属不变。

正常记忆排队、运行、完成和无变化不进入对话正文，状态与用量仍由 `/memory`、`/status` 可查；失败、冲突、退出未完成保留简短警告。用户明确发起的 `/compact` 仍显示其实际结果和独立用量。Skill 激活简报保留名称及有效范围变化，完整路径和重复操作帮助放入既有查询入口；子运行身份只在开始时显示一次，完整身份在详情可查。

### 5. 有界详情与思考默认收起

增强终端新增 F2 详情入口，在空闲或运行期间显示当前／最近任务的“调用”和“思考”分页视图；Tab 切换视图，PgUp／PgDn 翻页，Esc 或 F2 关闭。底部提示列出入口和当前可用操作。采用现有布局中的只读面板，不启动第二个终端应用，不重复把完整详情写入滚动记录。

浏览时 Enter 不提交聊天或授权，Ctrl+C 按底层任务阶段执行取消／草稿规则。打开和关闭详情保存并恢复原草稿及光标，隔离已解析按键；模型继续接收事件，浏览页不被新文本强行滚动。出现授权时关闭普通详情并进入独立审批视图，浏览期输入不得成为授权答案；审批仍使用已有 `targets/arguments/content/summary/results`，F2 不改变当前决定对象。

plain 无交互面板，任务结束后的 `/status` 提供同一份有界调用和思考详情；不新增斜杠命令，不占用用户 Skill 名称。查看只读取本进程展示缓存及已持有的结果引用，不请求模型、不执行工具、不自动读取缓存路径或工作文件。

仅缓存当前／最近一个顶层任务的正文外详情，主子运行分开标识；草案默认详情正文总预算 2 MiB，其中思考最多 256 KiB、单条工具结果沿用既有 64 KiB 采集上限。超出展示预算时按最旧详情正文淘汰，保留已有轻量状态、数量、调用关联和可用结果引用，并明确标记“详情因展示容量限制已移出”；不声称可查看未保留或采集时已截断的内容。新工作任务替换上一任务展示缓存，`/reset` 清除，`/clear` 保留；本地查询和维护不覆盖最近工作详情。

工作模型实际返回的思考默认不进入正文，只反映真实“思考中”阶段；没有思考片段时不得伪造思考过程。可在详情查看已收到的内容和容量标记；内部摘要草稿、隐藏推理和协议签名不进入该视图。该缓存不写入会话存档或记忆，不影响既有协议续接数据的处理。不选持久化全部思考，也不为了折叠而再次调用模型生成思考摘要。

### 6. 授权首页按操作类型组织

仍使用同一份不可变 `ApprovalView` 请求快照。将“固定操作身份与范围”“可分页操作内容”“唯一决定栏”拆开：固定区显示短关联、动作、目标数量、根目录／必要外部身份及四种期限的准确含义；正文优先显示读取目标、完整命令或写入／编辑内容；决定栏只显示一次，并保持回车／1 拒绝、2 本次、3 会话、4 永久及 Ctrl+C 含义。

编辑预览仅比较请求携带的 old_text／new_text，不为补上下文读取文件。长内容显示页码及完整详情入口，不让几行预览成为全部批准依据。MCP 显示 Server、真实工具身份、安全连接描述、有效参数和精确范围，不以本地文件语义替代。权限原因、完整请求 ID 和原始 JSON 仍可审阅，重复说明合并但不省略长期批准会保存什么、匹配什么以及撤销入口。

小屏按可用宽高分页；所有固定字段在空间不足时进入可达的摘要页，不显示缺乏对象说明的孤立批准入口。用户可以直接选择决定，无需逐页看完；翻页、查看详情和关闭面板从不授予权限。

### 7. 取消阶段与草稿处理

增加展示态 `cancelling`，由实际取消请求触发，立即显示“正在停止”，但不提前报告取消完成。保持至 Agent、工具和流的既有清理完成，期间不接受新任务、不改变既有 timeout，也不把第二次 Ctrl+C 解释为批准、强制成功或新的提交。

增强终端键盘 Ctrl+C 在空闲且编辑缓冲含文字（包括空白）时仅清空草稿、候选及相关输入残留，不调用退出回调；缓冲为空时按现有路径退出。运行／审批／手动压缩时取消当前任务，结束摘要区分已完成、未启动和状态未知，MCP 保留远端可能仍执行或已有副作用的说明。启动、退出阶段沿用既有清理语义。外部 SIGINT 保持进程级既有语义，plain 保持当前 EOF／Ctrl+C 行为，不假装拥有增强草稿编辑能力。

此项保护的是有草稿时不误退出；不新增跨重启草稿恢复、撤销栈或运行期提前输入队列。按键处理必须先作阶段判断，不能先触发旧的退出事件再尝试撤回。

### 8. 流式正文样式

使用统一的增量正文展示器，维护当前来源、段落和代码围栏状态；支持标题、列表、围栏代码和 diff 行的轻量样式，其他 Markdown 保留可读原文。复用 `prompt_toolkit` 的安全格式化输出，由同一控制器提交完整行和更新未结束的当前行。

未闭合代码块／半个标记到达时即时显示已收文本，不等待整轮或代码块结束；完成后不将整份回答再打印一遍。用户切换详情或发生授权时暂停当前可视区而非丢弃片段，返回后保留顺序。终端宽度变更只影响当前布局，不重新输出历史正文。

样式仅由可信渲染器生成；所有用户、模型、工具内容先脱敏并转义控制字符，不执行 ANSI、OSC、HTML 或远程资源加载。代码保留缩进、空行和原字符，不插入妨碍复制的行号；颜色同时配文字标识，plain 输出保留 Markdown 原文且不注入样式控制码。暂不引入完整 Markdown 渲染依赖，避免第二套实时输出所有者与整段重排。

### 9. 斜杠自动发现与既有补全分开

使用同代命令注册表获取名称、别名、说明、类型及参数提示。自动发现仅在空闲、单行、去掉前导空白后以单个 `/` 开头且光标处于命令位置时展示，输入继续筛选；隐藏定义及别名不出现。自动发现即使只有一个候选也不擅自改写草稿。

显式 Tab 继续沿用单候选补齐、多候选选择及固定参数补全规则；菜单打开时 Enter 仅接受候选，菜单关闭后的下一次 Enter 才执行。Esc 只关闭当前菜单，同一文本不立即重新弹出，后续编辑再触发。完整命令已确认或进入普通参数输入后不重复拦截执行；多行、`//`、括号粘贴及授权阶段不触发自动菜单，粘贴结束后必须显式编辑或按 Tab 才发现候选。动态 Skill 快照整体更新，不从磁盘逐键重新扫描。

只增加 UI 自动发现行为，`slash-commands` 的解析、分发、注册、帮助与显式补全合同不变，因此 delta 保持在 `interactive-chat`。

## Risks / Trade-offs

- [聚合掩盖异常或重复计数] → 先以调用身份归并终态，再分类成功／需注意；覆盖乱序、重复、同文件多次读取和父子同名工具。
- [详情缓存增加内存或泄漏思考] → 限定最近任务和字节预算，脱敏、明确容量淘汰、不新增落盘；测试维护及 reset／clear 生命周期。
- [Markdown 分片破坏代码与复制] → 以原文本为底层来源，样式和内容分离；覆盖逐字符围栏、无尾换行、中文、制表符和中途断流。
- [详情浏览或菜单按键串入授权] → 复用代次隔离，真实 PTY 覆盖打开详情后授权抢占、粘贴、Enter 和 Ctrl+C。
- [精简后缺少状态证据] → 异常即时可见，所有统计仍由 `/status` 查询，聚合短标识可追溯；plain 保留明确阶段与摘要。
- [Ctrl+C 行为变化造成习惯差异] → README、帮助和底部提示同时更新，明确非空草稿、空草稿、活动任务及外部信号的区别。
- [实现一次覆盖面较大] → 按展示投影、正文／聚合、详情／思考、审批／输入分层实施；每层先验证状态与内容不丢失，再进行真实终端验收。

## Migration Plan

1. 先引入展示投影和最近任务详情，保留 Agent／权限／会话接口，接入父子及维护事件。
2. 接入回显、成功聚合、结束摘要和流式样式，再加入详情与思考收起。
3. 改造授权首页、取消阶段与草稿分支，最后启用自动命令发现；沿用相同纯文本语义。
4. 同步 README、checklist 和受影响测试，用真实且已授权服务执行本次 tmux／PTY 验收；新证据不得用历史记录替代。
5. 不迁移权限文件、会话格式或真实配置。回退代码可恢复旧展示；思考展示缓存随进程结束清除，回退不会触发历史工具重放。
