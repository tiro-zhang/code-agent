## Why

当前终端将回答、工具事件、重复统计、独立 Skill 进度和后台维护混合输出，用户难以找到问题与回答、判断当前状态及定位需要操作的事项。已有增强终端提供统一输入和授权边界，本次在此基础上重新安排信息层级，并改善授权、取消、正文阅读与命令发现。

## What Changes

- 已提交问题和提示词命令保留一次原始输入回显，明确区分用户、助手、操作摘要和异常；本地命令反馈不伪造新的模型任务。
- 成功工具按连续活动批次合并，例如“已读取 3 个文件 · 完成 1 次搜索”；异常、拒绝、超时、截断及受限结果单独展示。子 Skill 使用同一规则，重复身份和正常后台维护进度不再刷屏。
- **BREAKING** 默认用量展示改为结束时一条累计摘要，完整请求、缓存和缺失统计在 `/status` 查看；空闲状态区不重复打印上轮统计。
- 授权首页突出目标、操作正文或编辑差异、准确批准范围与唯一一组决定入口，完整参数和长内容仍可在批准前审阅。
- **BREAKING** 增强终端空闲且草稿非空时，Ctrl+C 清空草稿并留在会话；空草稿时继续退出。任务或授权期间取消立即显示“正在停止”，清理完成后才恢复输入。
- 回答采用标题、列表、代码块与 diff 的轻量样式，保持真实流式显示和可复制文本；纯文本后端继续输出无样式控制码的内容。
- **BREAKING** 工作请求实际返回的思考内容默认收起，按需查看；不修改模型 thinking 配置，不展示内部摘要草稿，不新增思考持久化。
- 增强终端在单行草稿输入 `/` 时自动展示命令与用途，按前缀筛选；候选确认与执行分离，保留显式 Tab 补全及 Esc 关闭，多行正文、`//` 和授权输入不触发。
- 提供最近任务的有界详情浏览，支持聚合调用追溯、子任务来源和收起的思考；不执行工具、不增加模型请求、不改变权限。

本轮不引入全屏工作台、运行中任务队列、自动重试、自动批准或新的权限范围；不重写 Agent 调度、会话恢复和记忆提取算法。

## Capabilities

### New Capabilities

无。上述能力统一属于已有终端交互能力。

### Modified Capabilities

- `interactive-chat`：调整对话轮次、工具聚合、状态与用量、思考可见性、审批布局、取消与草稿行为；增加流式正文格式、最近任务详情和斜杠命令主动发现。

## Impact

- 主要影响 `src/mewcode/terminal/` 的状态、布局、输入、授权与展示代码，以及 `app.py` 的事件接线和正文输出；按职责拆分展示逻辑，不向入口文件继续集中实现。
- 复用命令注册表的名称、说明和现有解析／Tab 补全语义；必要时增加只读候选元数据访问，不新增保留斜杠命令或影响 Skill 命名空间。
- 保留同一终端所有者、输入代次隔离、脱敏、控制字符转义及 plain 退化。工具详情仅展示既有结果快照或已有结果引用，不为 UI 读取未授权目标文件。
- 优先复用现有 `prompt_toolkit`；首版不以更换终端框架或完整 Markdown 解析器为前提。
- 实施时同步 README、checklist 及相关终端／Skill 测试；使用本次真实模型 tmux 和定向 PTY 验收，覆盖多轮、长流式内容、窄屏、授权、取消、补全和 plain 模式。
