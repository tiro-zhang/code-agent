## Context

动机见 proposal.md。当前 `Agent` 已提供非交互 ReAct 循环、有限请求预算、权限错误回灌、上下文压缩及异步事件，适合复用；它仍把系统提示固定为全局构建结果，并把工具声明与实际允许范围绑定。

`skills/runner.py` 的独立执行已有子历史、子审计和摘要，但使用父权限对象及顶层共享预算。`skills/history.py` 将选中历史转换为 JSON 背景，不能作为 Fork 的原始前缀。现有 Skill 行为继续保留，新 Agent 运行时单独实现初始化及预算政策。

`HookRuntime` 同时拥有会话 once 标记、提示词队列及后台动作；前两者必须拆分归属，不能简单复制整个 Hook 实例。官方 Anthropic 适配器目前只在系统提示末尾设置缓存断点，Fork 的长历史复用还需消息缓存策略。供应商缓存事实依据 [Anthropic 官方文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)，缓存效果以实际返回的用量为准。

## Goals / Non-Goals

**Goals:**

- 用统一委派入口和同一个执行核心支持两种上下文初始化，子过程不进入父语义历史。
- 每个运行持有独立可变状态；共享服务由会话拥有并统一关闭。
- 前后台转换只改变等待与呈现，不重启执行；自动接续不刷新父预算。
- 工具限制、非交互权限、取消及用量归属可以分别验证。

**Non-Goals:**

- 不提供文件事务或冲突隔离；同一工作根的写操作可以相互影响。
- 不实现团队、子 Agent 再委派、任务跨进程恢复或新插件安装系统。
- 不迁移独立 Skill 的历史格式／共享预算，不接通 Hook 的 `subagent` 占位动作。
- 不保证缓存一定命中，也不把子 Agent 的自述当作任务成功的独立证据。

## Decisions

### 1. 三个模块及会话资源归属

```text
Main Run --> agent tool --> Task Manager --> Child Runtime --> Agent loop
                                |                 |
                                |                 v
                                |           Shared Services
                                v
                           Result Inbox --> Main request boundary
```

`agents/` 负责角色目录、启动快照和子运行；`tasks/` 负责执行任务、等待、通知及父任务接续。`session.py` 持有这些服务，终端只处理事件和本地管理动作。

| 独立运行状态 | 会话共享基础设施 |
| --- | --- |
| 消息及消息内可变对象、提示状态、Skill 激活副本 | 文件系统和实际工作根 |
| 权限管理器、本会话批准副本、授权审计 | 权限规则与永久批准的存储 |
| 上下文估算、摘要状态、结果缓存命名空间、文件读状态 | 工具登记快照、MCP 连接 |
| 请求预算、逐请求用量、取消事件 | LLM 传输客户端和 Hook 规则／派发器 |
| Hook 待注入提示词 | 会话级 once 标记、共享关闭协调 |

不要直接创建新的完整交互 ChatSession：它会带来输入、恢复和记忆维护的额外生命周期。不要直接复用现有独立 Skill runner：其预算与背景格式不同。复用 Agent 执行核心，通过显式运行上下文提供上述策略。

### 2. 角色格式、来源和发现

使用 `.mewcode/agents/*.md`、`~/.mewcode/agents/*.md`、包内 `agents/builtin/*.md`，及配置 `agent_plugin_dirs` 提供的本地目录；该配置是 JSON 路径列表，缺省为空，仅提供最低层角色来源，不安装或执行插件。每层只识别直接 Markdown 文件，不扫描参考文档。

```yaml
---
name: explore
description: 定位代码并提供有来源的分析结论
allowed-tools: [read_file, glob_files, search_code]
disallowed-tools: []
model: inherit
max-iterations: 20
permission-mode: inherit
---
你是代码探索 Agent。围绕收到的子任务定位实现、追踪调用关系，报告证据和未确定的部分。
```

`name`、`description` 必填；正文非空并作为定义式运行的固定系统指令。省略白名单表示不增加限制，空白名单表示没有可执行工具；黑名单优先。模型仅接受 `inherit/haiku/sonnet/opus`，权限接受 `inherit/strict/default/bypass`，请求上限是正整数，布尔值不视为整数。

沿用 Skill 的安全 YAML、64 KiB 文件预算、无符号链接和同层重名处理模式。非法文件局部跳过并诊断，不覆盖低层有效项；同层有效重名导致候选目录失败。有效工具名在内置和 MCP 发现完成后校验，拼错名称明确阻止发布。四层依次整体覆盖，不拼接正文或字段。

初始内置 `explore` 和 `general`，均使用继承模型；前者限制为三个读工具，后者不附加白名单。项目可按常规优先级覆盖。只将角色名和说明放入动态能力目录，不把全部角色正文放入主系统提示，也不把角色枚举写进工具 Schema。目录在用户输入边界完整更新，任务注册时冻结选中的定义及来源。

采用严格有效目录而非加载时才发现工具拼写错误，以避免后台执行开始后才失效；采用文件覆盖而非字段合并，以便准确追踪实际生效角色。

### 3. 单一工具契约

工具 API 名为 `agent`，描述及 Schema 与角色目录无关：

```json
{"type":"defined","role":"explore","prompt":"定位权限检查入口","background":false}
```

```json
{"type":"fork","prompt":"验证上述方案的边界","background":true}
```

`type`、非空 `prompt` 必填。defined 必须提供 `role`，`background` 缺省 false；fork 禁止提供 role，缺省／true 都使用后台，显式 false 返回 `invalid_arguments`。不提供工具级模型覆盖；defined 使用角色配置，fork 固定父请求配置。

入口作为主进程系统工具登记，始终以单一 Schema 存在于主 Agent 工具列表，形成串行调度边界。空父普通工具范围仍可委派纯文本任务，但子范围不能被扩大。通过参数、权限和容量检查后注册任务；启动失败的结果包含 `not_started=true`。返回原 `ToolResult` 契约并保留原调用 ID。

前台自然完成返回最终结果；后台或转换后台返回接收凭据，至少包含 task_id、parent_task_id、状态和展示模式。凭据表示任务被接受，不表示子任务成功。前台结果已通过原调用回流时，不再排入收件箱产生第二次主请求。

逐角色注册工具会破坏稳定列表；增加 Fork 独立工具也会重复执行契约，因此采用一个类型分流入口。

### 4. 两种上下文初始化

定义式使用新历史、清空父 Skill 激活及文件读状态，将固定基础系统提示与角色正文组合；工作根、项目指令和当前模式约束仍生效。父旧消息、思考、记忆抽取结果或激活 SOP 不隐式继承，所需目标由 prompt 显式传入。

Fork 深复制触发委派的父模型请求快照，保留系统提示、工具定义及顺序、模型／思考配置、消息块和适用签名，不重写为背景摘录。快照止于触发请求的输入，尚未配对的当前 assistant 委派调用不导入。追加明确的 Fork 子任务消息及子身份提醒，并使用独立的控制状态副本。父在这之后的消息、压缩和 Skill 更新不修改该快照。

选择“触发请求输入”而非“实时历史列表”，可以复用已经发送的前缀，避免半个工具批次及并发父消息。首次 Fork 请求不为追求容纳而改写该前缀；不可容纳时返回上下文限制错误。首次之后可在子预算内按现有策略压缩自己的历史。

### 5. 工具声明与实际执行权限分开

定义式声明其启动时允许的工具。Fork 保留父声明以复用缓存，包括父可见的 agent 入口；实际执行范围独立计算，所有子运行均禁止 agent，即使模型返回该调用也不能启动。

实际允许范围依次受父启动范围上限、当前规划上限、角色白名单／黑名单、子 Skill 交集、全局禁止及后台白名单限制。global guard 在所有系统工具分流前执行，不使用现有 system 属性豁免这些限制。

后台默认白名单为六个核心工具和 load_skill；load_skill 仅允许合法资源读取或共享激活，独立 Skill 启动被全局拒绝。后台 MCP 通过可选 `agent_background_tools` JSON 精确名称列表显式纳入；配置省略使用默认值，空列表表示不允许工具，未知名称拒绝配置。前台 MCP 仍受父范围、角色和权限约束。

切后台不取消已启动的前台操作，其原授权和普通工具期限继续有效；后续调用按后台白名单复查。声明保持稳定，受限调用返回 `tool_not_allowed`。普通工具调度顺序只对单个运行负责，不提供跨 Agent 文件顺序保证。

选择保留声明并硬拦截而非删掉 Fork 的委派声明，会暴露少量不可执行工具，但能保留前缀；提示词解释边界，正确性由执行器保障。

### 6. 权限快照、模式上限和非交互

任务注册时复制父本会话批准，独立维护子授权追踪；本次批准绑定原调用且不复制，子执行不写新的本会话或永久批准。后续父会话批准及撤销不修改这份子副本；用户需要停止其授权执行时可取消该子任务，规则 deny 和永久撤销按每次执行的最新存储检查。

子权限模式取父启动模式与角色模式中较严格者，顺序 strict > default > bypass，inherit 不增加限制。实际路径、shell 结构、MCP 身份和规则重新检查；模式批准不能扩大工具上限。

子运行前后台均无审批输入通道。缺少许可返回 `approval_required`，模型可调整或自然结束，不把它设置为用户取消。搜索维持候选级受限合同：排除没有非交互许可的候选并报告 skipped_files，参数／配置／调用级错误仍是失败。Hook 命令也使用当前运行的非交互权限，不能间接弹出主授权界面。

选择批准副本而非共享 PermissionManager，可以沿用用户已有授权，同时避免模式和批准状态串扰。

### 7. 模型别名和客户端所有权

新增可选 `agent_models` JSON 映射，为 haiku、sonnet、opus 显式提供实际 model、context_window 及可选 max_output_tokens；继承使用父配置，不猜测最新 Claude 型号，不把兼容协议当作别名已配置。缺少映射或预算非法时，启动前返回 `agent_model_unavailable`，不回退父模型。

同服务的不同模型使用不同不可变 Provider 配置包装、同一异步传输客户端。缓存不能跨模型宣称复用。客户端、MCP 连接由会话持有；子结束只释放私有流、缓存命名空间和状态，不能调用共享客户端的全局 close。仍保留独立 Skill 原额外客户端的所有权合同。

### 8. 父任务、执行段和预算

TaskContext 持有父 task_id、原始用户目标与来源 ID、原预算、取消、会话代次及子任务集合。MainRun 每次前台执行或自动接续有新的 run_id，但使用同一父预算；每个执行段恰好一个 finished。父在 pending children 时可以结束执行段并恢复输入，父任务尚未最终结束。

新的 Agent 子运行使用自己的有限请求预算和 token 账本；普通工具不增加模型请求计数，子摘要计入子预算。原独立 Skill 继续共享其顶层预算。主预算耗尽不取消已接受的后台子任务，但只显示结果，不再自动接续。父不可恢复失败停止自动接续；已经接受的后台结果仍可查看。

每个请求以 run_id 和 request_id 去重；主自身用量、各子用量及按真实请求求和的汇总分别展示。原任务接续不增加新的用户目标，也不重复执行原工具调用。父最终完成或受控取消另发布一次 task_finished，执行段 model_done 与父终态分别呈现。记忆维护只在父任务最终自然完成后按原合同触发一次，子结束或中间执行段不触发。

沿用共享预算会违背新子 Agent 的独立最大轮次；每次自动唤醒发新父预算则会导致无界接续，因此采用独立子预算、保留原父预算。

### 9. 后台管理和三种切换

所有子任务由同一会话 TaskManager 持有 asyncio 执行任务；系统工具 handler 只是等待者。任务状态 queued --> running --> completed/failed/cancelled 与展示模式 foreground/background 独立。正常无工具非空答复为 completed；预算／上下文／流错误为 failed，携带具体 reason。completed 不等同业务检查通过。

设计默认值：每会话最多 4 个活动子运行、32 个排队子任务，前台等待 30 秒转后台，角色缺省请求预算 20，回流摘要内容预算 64 KiB。这些是本方案选定默认值，不是用户逐项指定；实现保持可注入以便测试，修改数值不改变状态和权限合同。

显式后台与 Fork 立即返回凭据；前台等待到期或用户 Ctrl+B 时切换同一个任务，返回相同身份。操作完成与切换同时发生时，原子决定一个回流通道；切后台不取消 Task，也不再次创建缓存、调用模型或重新执行工具。队列满时拒绝新提交，不无限堆积。

### 10. 收件箱、自动唤醒和输入优先

后台终态存入有来源结果记录并产生一次通知，内容包含任务／父身份、类型、角色来源、reason、最终文本、实际证据、用量和可能副作用。最终回答本身作为摘要，不额外请求总结模型；超出预算的正文有截断标记，完整结果可通过本地任务查看，控制元数据不截断。任务记录引用的证据缓存由管理器保留到会话关闭，子结束只释放私有句柄，不提前删除仍被引用的结果。

收件箱不修改正在发送的消息列表。在下个实际主工作请求开始时，按 task_id 选择和去重通知，作为后台结果上下文追加；无同一 task_id 的第二个 tool_result。任务尚未结束的前台等待也不被结果到达打断。

主空闲时，先让已提交的用户输入／控制命令取得运行权，再合并同一父任务已到达结果，启动最多一个主执行段。不同父任务的通知按入箱顺序分别接续，使用各自预算；任何时刻只有一个主运行。未提交草稿保留，后台通知不读取或提交它。新用户任务执行期间，旧任务结果留在原父收件箱，不抢占新目标；待主空闲再按原身份处理。

通知在实际请求开始时记为已投递，准备后取消不消费；流失败不伪造成功历史或自动无限重送，任务记录仍可本地查看。原父剩余预算为零、已取消、失败或代次失效时，只显示结果，不自动发新请求。

### 11. 取消、规划、重置和退出

父执行段自然 model_done 不取消后台子任务。用户主动取消父任务，先设置父不可唤醒，原子关闭其后续提交，再取消该父全部 queued/running 子任务并有界收尾；其他父任务、历史记忆维护及独立 Hook 后台动作仍按各自合同处理。

`/tasks cancel <id>` 只取消一个子任务，其真实取消结果可由未取消父任务正常处理；`cancel-parent` 同时停止该父的自动唤醒。退出和 reset 使旧会话代次不可接续，停止所有子任务后释放资源／清空历史。reset 不清除会话权限及 Hook once，也不删除已完成实际副作用；终态任务记录留供本次进程本地查看。

进入 plan 前暂停新副作用及自动接续，取消 execute 模式启动的活动／排队子任务并完成清理，再发布只读状态。plan 中可委派只读子任务，Fork 声明来自只读父快照。裸 /do 不启动或复活旧任务；模式切换期间完成的结果只通知，后续显式任务仍须正常授权。

普通工具保留进程组回收及 MCP 单请求取消，关闭模型流。停止等待不表示远端停止，结果记录明确不确定副作用。先收尾子任务、Hook 和记忆服务，再关闭共享 MCP／Provider。

### 12. 本地管理与 Hook

增加 `/agents [list|show <name>]` 和 `/tasks [list|show <id>|cancel <id>|cancel-parent <parent_id>]`，注册到现有命令目录、帮助和补全，不请求模型。前台等待 Agent 时 Ctrl+B 转后台；其他输入阶段保持既有含义，退化界面显示可用性，不把控制键当子命令标准输入。

Hook 规则编译结果和 once 保持会话共享；运行视图提供当前 run_id、parent_run_id、权限模式、取消和独立 PromptQueue。主队列按父 task_id 归属，跨该父的新执行段保留；子队列按子身份归属，不被其他父任务或兄弟消费。子提示词只被子下一工作请求消费，关闭子不能关闭会话派发器。新子 Agent 的 Hook 命令受同一非交互许可与当前 plan 限制；Hook 副作用不因目标工具获准而获准。

Hook `subagent` 仍按现有占位规格记录未实现，避免把自动事件委派作为未经探索的新增入口。所有现有独立 Skill 子运行也不能调用新的 agent 工具，防止借旧入口绕开禁止嵌套；原 Skill 的授权交互、下一层独立加载错误和共享预算继续按既有合同执行。

## Risks / Trade-offs

- [共享目录有并发改写] --> 明确运行状态隔离的边界；保留每次工具权限／真实路径检查，跨运行修改后重新读取，不宣称文件事务。
- [Fork 仍继承父历史及旧提示] --> 冻结控制状态，追加明确子任务；保证子过程不回流父，而非声称所有上下文影响消失。
- [服务、TTL、模型或签名导致缓存未命中] --> 协议能力分支、请求前缀对比及真实 usage 验收；不依据速度或复制成功推定命中。
- [稳定声明包含禁止工具] --> global guard 覆盖系统入口、角色和后台上限，使用伪造调用测试验证。
- [自动唤醒和新输入竞争] --> 单一主运行所有者、父身份收件箱及会话代次，取消先于提交。
- [长任务阻塞退出或远端影响未知] --> 有界本地收尾，逐调用保留实际状态，最后释放共享客户端。
- [子独立预算增加总用量] --> 有限单子预算、并发／排队上限及不重复汇总展示；不承诺固定费用下降。
