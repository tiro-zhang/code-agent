## Why

主 Agent 需要把探索、实现和验证等子任务交给独立运行的 Agent，避免子消息、思考和工具过程持续占用主上下文。现有独立 Skill 已有摘要回流能力，但共享父权限对象、请求预算和 Hook 运行态，且把历史转换为背景摘录，不能直接提供并发隔离及 Fork 的缓存前缀复用。

## What Changes

- 增加单一 `agent` 工具，以 `type=defined|fork` 分流；角色目录变化不增删角色专用工具或改变工具 Schema。
- 用带 YAML frontmatter 的 Markdown 定义角色，支持工具白黑名单、模型别名、最大请求次数和权限模式，按项目、用户、内置、插件的顺序覆盖。
- 增加独立子运行：定义式使用空历史和固定角色系统提示；Fork 使用父请求的合法冻结前缀并强制后台，实际工具限制由执行层强制实施。
- 隔离消息、权限追踪、授权快照、上下文与文件读状态、取消和用量；共享供应商传输客户端、MCP 连接、Hook 基础设施和工作文件系统。
- 子运行非交互执行到自然无工具响应或有限停止条件；需要批准时返回 `approval_required`，角色权限只能收紧父模式。
- 增加会话内任务管理，支持显式后台、前台等待超时自动转后台和手动切后台；后台允许获准的写入、编辑及命令，禁止嵌套委派。
- 结果通过带任务身份的收件箱回流；主 Agent 运行中在请求边界消费，空闲时自动续跑原任务且不重置父预算。主动取消父任务会取消其全部子运行并停止自动唤醒。
- 保留原独立 Skill 的执行契约和 Hook `subagent` 占位；补齐所有子运行的防嵌套和 Hook 提示队列归属。
- **BREAKING**：新增 `/agents`、`/tasks` 控制命令保留名，已有同名 Skill 按现有命令冲突合同报错，需要改名。
- 本次不实现 Worktree 文件隔离、多 Agent 团队编排、后台任务跨会话恢复。

## Capabilities

### New Capabilities

- `agent-definitions`：角色格式、来源覆盖、模型解析、能力发现和定义快照。
- `subagent-runtime`：统一委派入口、两种初始化、运行隔离、工具限制、完成结果和资源所有权。
- `background-tasks`：内存任务管理、前后台切换、结果投递、自动接续、预算归属及取消收尾。

### Modified Capabilities

- `agent-loop`：区分父任务与执行段，保留自动接续预算及终态、用量归属。
- `tool-system`：登记统一入口，明确 Fork 声明与执行权限分离及系统入口不可绕过上限。
- `tool-permissions`：支持委派入口的精确权限匹配、子批准快照、只能收紧的权限模式和非交互错误。
- `plan-mode`：允许只读委派并约束活动后台执行及规划切换后的接续。
- `prompt-caching`：冻结 Fork 请求前缀、覆盖消息缓存边界并用真实统计验证复用。
- `interactive-chat`：后台状态、手动切换、自动接续和单一输入所有权。
- `slash-commands`：角色与任务的本地查看／取消及 reset 的后台清理。
- `lifecycle-hooks`：共享会话 once 标记，按运行隔离提示词及权限上下文。

## Impact

- 主要涉及 `agent.py`、`session.py`、`prompts.py`、`types.py`，以及新增 `agents/` 和 `tasks/` 模块；入口与终端只负责协调和呈现。
- 工具注册／执行／调度、权限配置／授权存储、上下文缓存、供应商请求与客户端生命周期需要增加运行归属。
- `.mewcode/agents/`、`~/.mewcode/agents/`、包内角色资源及插件提供的角色目录成为新定义来源；模型别名使用同一模型服务的显式配置。
- 新工具 `agent` 始终使用同一参数契约；子运行的硬限制必须覆盖原系统工具白名单例外。原核心工具、Skill 入口和 MCP 参数契约保留。
- 实现阶段需要同步 README、checklist，增加并发／权限／缓存／终端测试，并在 tmux 中执行真实模型验收；本次方案创建不执行模型请求或修改实现。
