## Context

动机与用户行为范围见 `proposal.md`。本设计以已同步的斜杠命令、上下文、权限、MCP 和会话主规格为基线。

现有 `PromptState` 预留 `active_skills` 字符串，但完整补充内容只在第 1、6、11 等工作请求及必要补发时出现。`Agent.run` 在任务入口一次性计算工具声明和允许集合，任务中新增激活状态不会改变下一轮工具。`ToolExecutor` 将普通内置工具交给 spawn 工作进程，无法在那里更新主会话状态；MCP 已有主进程异步路由。`CommandRegistry` 注册后冻结，帮助、补全、分发及终端持有同一对象。会话已经有 JSONL 追加存档、成对工具结果、历史检查点、独立摘要预算和统一取消信号。

这些机制可复用，但 Skill 的状态、执行和发现需要独立边界，不能继续集中到 `app.py`。

## Goals / Non-Goals

**Goals:**

- 用一份目录快照连接元信息、命令和加载入口，完整指令按需进入模型上下文。
- 将工具可见性、执行许可和人工授权分开；所有普通调用使用同一有效工具集合。
- 独立执行复用现有 Agent、权限及 MCP，隔离可变历史、提示状态和窗口估算。
- 将加载、热更新、重置及恢复作为有持久边界的状态变化，并保留真实操作证据。

**Non-Goals:**

- 不增加包下载、市场、安装命令、版本声明、依赖求解或自动脚本执行。
- 不创建工作树或复制业务工作目录；独立执行仍使用当前项目，文件副作用真实存在。
- 不引入文件监听后台服务、跨供应商路由、任意模板语言或多层独立 Agent 编排。
- 本次仅捕获规划文件，不改产品代码、主规格、现有配置或依赖。

## Decisions

### 1. 已确认边界与本次默认值

已确认：`/reset` 清历史和激活状态，`/clear` 只清屏；同时激活的白名单取交集；只有独立模式可指定模型；热更新影响下一任务，正在运行的任务使用固定定义；子对话继承父对话当前普通工具范围作为上限。

其余细节采用以下本次设计默认值，便于按一致方案实现及审阅：独立历史默认 0，正整数按完整用户轮次选择；模型名表示当前服务下的模型 ID，其他模型的窗口由配置显式声明；独立执行只支持一层；激活保持到本地停用或重置；同层有效重名是整体配置错误。它们是本次选定的技术默认值，不标记为用户已逐项确认的决定。

### 2. 新增独立 Skill 包，统一有界定义

建议职责划分如下，具体文件拆分在实现时可沿邻近风格调整：

| 模块 | 职责 |
| --- | --- |
| `skills/models.py`、`loader.py` | 元信息、解析诊断、单遍字面替换和资源边界 |
| `skills/catalog.py` | 三层发现、覆盖、候选校验、不可变入口快照 |
| `skills/runtime.py` | 激活映射、显示顺序、渲染 SOP、工具交集、状态提交 |
| `skills/runner.py` | 独立对话、历史导入、取消、预算、最终摘要及审计 |
| `skills/builtin/` | 随包内置 Markdown 与目录资源 |

入口采用 UTF-8，frontmatter 用安全 YAML 解析并拒绝重复键和未知字段。`name`、`description`、`mode` 必填；名称采用 `[a-z][a-z0-9_-]{0,63}`，说明必须为非空单行字符串。`allowed-tools` 可省略，表示不附加限制；空列表表示没有普通工具。只允许精确的已注册工具名，不支持通配符或 Bash 参数表达式。

`mode` 为 `shared` 或 `isolated`。`history` 只允许独立模式使用，缺省 0，取非负整数或 `all`，布尔值不当作整数。`model` 为可选非空模型 ID，也只允许独立模式使用。共享模式出现 `history` 或 `model` 属于文件定义错误，局部跳过。

正文为非空 SOP。支持 `{{args}}` 和 `{{skill_dir}}`：前者替换用户参数原文，后者替换来源包的绝对目录；单文件包目录为入口文件所在目录。替换只遍历原模板一次，不重新解释用户内容中的占位符，不执行表达式、不读取环境变量、不当作 shell 参数解析。无参数时 `{{args}}` 为空，默认目标由 SOP 规定。

入口原文限制为 64 KiB；展开后的加载结果也必须满足现有 64 KiB 内容预算。展开过大时返回 `skill_content_too_large`，不截断 SOP、不部分激活。运行时窗口估算仍需计入所有 SOP，64 KiB 合法不等于模型一定容纳得下。

```markdown
---
name: test
description: 按指定范围运行测试并报告真实结果
allowed-tools:
  - read_file
  - glob_files
  - search_code
  - execute_command
mode: isolated
history: 2
---

测试目标：{{args}}
先读取项目约定并确定测试命令，按当前权限运行，再报告通过、失败和未执行项。
最终回答写成供主对话接续的摘要，列出证据和未完成事项。
```

### 3. 三层发现和错误分层

项目根固定为实际工具根目录；依次发现 `.mewcode/skills/`、用户 `~/.mewcode/skills/`、随包资源。各层只识别直接子项中的 `*.md` 与 `<目录>/SKILL.md`，不把 `references/` 等 Markdown 当成新 Skill。名称来自 frontmatter，同名有效项按项目、用户、内置覆盖；高层解析失败的文件不参与覆盖，低层合法项可继续生效并报告来源。

入口原文作为有界本地快照保留，第一阶段只解析元信息、保存来源与内容指纹，向模型导出名字和说明；正文只在调用阶段提取、替换并注入。这样任务内首次调用尚未激活的 Skill 也使用本任务发现的定义，不因磁盘中途变化混用新旧内容。

缺失目录视为空。不可读、非法 YAML、非法字段、非普通文件、符号链接或超限入口产生单项诊断并跳过。同层两个有效项同名，或有效 Skill 与保留控制命令／别名冲突，拒绝整体候选。旧 `/review` 固定命令退出控制命令表，名称交给内置 Skill。

基础控制命令与 Skill 名称冲突先于 Provider、Journal 和 MCP 初始化检查；有效覆盖结果的工具名校验在 MCP 工具发现完成后、恢复预算检查和接受用户输入之前进行。任一未知工具立即启动失败，包含未激活 Skill。被覆盖项不进入最终工具校验。已有但当前规划模式不允许的工具不是未知名称，加载后仍受实际模式限制。

与逐个注册、反复全量重建或引入监听服务相比，有界快照可以在一次明确的输入边界内校验并交付，也更容易处理候选失败。

### 4. 主进程系统加载入口和目录资源

注册表保留可序列化名称、Schema 和路由标识；主进程另持有运行服务，禁止把会话对象或闭包塞进会被 spawn 序列化的注册数据。系统路由用于 `load_skill`，正常文件／搜索／命令及 MCP 路由保持现有执行方式。

建议加载参数为 `name`、可选 `args`、独立模式可选 `history` 覆盖，以及可选 `resource`。普通调用加载完整 SOP：共享模式提交激活后返回指令和有效工具；独立模式运行子对话后返回摘要与停止状态。`history` 覆盖只改变这次独立调用，不修改定义。

带 `resource` 时只读取对应目录包内的相对 UTF-8 文本资源，不运行 Skill、不改变激活、不接受执行参数。读取在实际包根内进行普通文件和真实路径检查，拒绝绝对路径、`..` 逃逸、符号链接、特殊文件及二进制内容；超限资源返回错误，引导拆分参考文件。单文件 Skill 没有包内资源读取入口。资源按实际读取结果返回，与冻结的入口定义区分，不宣称引用文件永不变化。

`load_skill` 总在系统可见集合，且不能被普通白名单排除；它仍进行参数校验、注册包边界检查、适用的 `load_skill` 权限规则与人工授权判断。权限匹配对象是规范化的名称及参数，不把包入口加载伪装成可读取任意工作区外路径的 `read_file`。明确拒绝仍优先，拒绝前不读取资源正文、不激活、不启动子对话。目录发现仅用于本地配置扫描，不代表激活授权。

完整激活或独立执行均为调度串行边界，主进程提交状态后才检查后续调用；包资源读取也沿该入口串行处理。普通工具在实际启动时获取当前有效集合，不能只使用请求发送时的旧集合。只做白名单过滤不能解决同批先加载、后编辑的情况。

激活／资源加载采用现有本地工具期限；独立执行是有限模型任务，不套普通工具的固定 30 秒总期限。子对话内每个普通工具仍有原期限，模型请求受统一预算和可信取消信号控制。

### 5. 激活和工具范围由会话状态管理

共享激活映射以规范名称为键，并保存参数、当前定义指纹、完整展开 SOP 和普通工具集合。再次调用同名 Skill 更新参数和渲染内容，不追加重复段落；不同 Skill 按首次激活顺序排列。调用中更新参数仍使用当前任务的冻结定义。

令 R 为普通已注册工具，M 为当前模式普通工具上限，P 为子对话继承的父上限（主对话取 R），W_i 为各激活 Skill 的白名单（省略取 R）：

```text
ordinary = R intersect M intersect P intersect W_1 ... intersect W_n
visible  = ordinary union {load_skill}
```

交集为空时仍允许加载其他 Skill，但新激活只会保持或进一步收窄普通范围；终端显示当前范围和本地停用入口，不以并集补齐工具。模型不能通过加载同名项改变定义的工具范围，也不能自行调用本地停用命令来解除限制。

`/skills` 或 `/skills list` 列出名称、说明、模式、来源及激活状态；`/skills active` 显示当前激活项和有效普通范围；`/skills deactivate <name>` 或 `/skills deactivate --all` 由用户在空闲期解除激活。它们使用现有窄会话接口，状态保存成功后再发布新内存状态，不直接操作历史或终端副本。

### 6. 每轮钉住完整 SOP，保留提醒与历史身份

固定系统提示仍使用七模块稳定拼装，更新其 Skill 加载、当前清单和冲突说明。每个工作请求的 `<mewcode-context>` 开头为当前激活 Skill 全文（无激活时明确当前为空），之后提供可发现的名字／说明，再提供本轮完整或精简环境／模式提醒。完整提醒继续含环境、手写指令和记忆，精简轮次也不能省略激活 SOP 或当前工具范围。

位置只提高可见性；Skill 仍不能覆盖固定系统约束、手写项目规则、当前模式和有效授权。多个 SOP 存在无法协调的行为冲突时模型应说明冲突，不从排列位置推导新权限。

旧请求提醒保持历史身份，仍按已有完整响应、成对结果和存档提交合同保存，不在停用、热更新或摘要时改写旧消息。最新激活清单才描述当前状态，旧 SOP 是历史快照。摘要后从运行状态重建全文；专用压缩／记忆模型不注入正在执行的 SOP 以驱动工作。

预算预览、实际请求和提交后预算使用同一渲染内容及工具声明；不可容纳的 SOP 集合产生 `context_blocked`，不静默摘要或截断活跃指令。相比只把正文留在某次工具结果中，这能保证结果落盘和历史裁剪后指令仍存在。

### 7. 两个入口共用一次调用，独立历史不污染主对话

`/<name> [参数]` 在本地完成加载请求校验，复用同一 Skill 服务；无需先请求模型再让它猜加载工具。共享模式先激活，再通过统一会话任务入口提交一次包含目标参数的请求，SOP 从上下文注入；独立模式直接调用同一独立执行器。模型自然选择能力时通过 `load_skill`，返回结果按原调用 ID 配对。

独立运行仅建立新的历史、PromptState、ContextManager、结果缓存命名空间和子任务身份；工作根、权限服务、授权终端及 MCP 连接复用父运行服务，环境、手写规则、记忆索引和 Skill 目录采用父有效快照。父激活 SOP 不直接继承为子指令，父普通工具集合在启动子任务时冻结为不可扩大的上限；子对话的新共享激活继续与该上限取交集。本次子对话不再启动另一层独立对话，返回明确未启动错误，但可加载共享 Skill 和包内资源。

历史取值：0 不带主历史；N 选择最近 N 个已提交用户任务轮次；`all` 选择当前合法历史投影，不读取已退出上下文的全部旧存档。每个轮次保留完整工具交互。主 Agent 正在调用加载工具时，尚未配对的本轮调用不导入；当前 Skill 参数及当前任务用户输入单独作为子任务目标，不因 history=0 丢失。

选中的消息转为带角色和来源的只读背景摘录，工具结果按完整组表达，摘要标明为摘要，应用 runtime 提醒与旧激活正文不导入为控制指令。摘录是新对话的数据，不作为目标模型的原生助手／工具消息，因而不复制其他模型的签名续接块；主历史原文和签名保持不变。

SOP 要求子 Agent 的正常最终回答本身为主对话可用摘要，执行器追加任务身份、来源、停止原因和真实工具证据引用，不额外调用总结模型。工具入口将摘要放入 `load_skill` 结果，主 Agent 可在预算内继续；斜杠入口把一次用户目标和摘要／失败状态作为主历史记录提交。子步骤、流片段及思考不作为主历史的独立对话消息。失败或取消也回流实际已完成、未完成和副作用状态，不以摘要冒充成功。

### 8. 主子执行共用请求预算与可信取消

新增任务级预算对象，主 Agent、独立 Skill 及任务内自动摘要每次实际请求共用同一个剩余额度。默认上限仍为配置的 `max_iterations`，不能通过连续加载独立 Skill 获得新的 20 次请求。斜杠直接独立调用创建一个顶层任务预算；模型调用独立 Skill 时消费主任务剩余额度。后台记忆、空闲 `/compact` 和启动恢复仍使用原维护预算。

主子运行共用可信取消事件，但子状态错误不是父用户取消。取消停止后续主子模型请求和调度，关闭子模型流、回收活动普通工具并补齐父加载结果；保留实际已完成结果。子运行 finished 必须带子身份，不能提前结束父任务或触发另一份后台记忆提取。

每个请求的 usage 仅记录一次，标识所属顶层任务、子运行和工作／摘要用途；顶层累计包含子运行但不再重复相加子累计。独立进度、输出、授权和停止反馈在终端明确关联 Skill。独立结束后释放自己的上下文及额外模型客户端，不关闭父 Provider、共享授权或 MCP。

### 9. 指定模型复用服务，独立窗口显式配置

`model` 省略或等于主模型时使用主配置。其他模型使用当前 `protocol`、`base_url`、`api_key` 和 thinking 配置，只覆盖模型 ID 及独立预算；不允许 Skill 文件放入 endpoint、密钥或指向任意配置文件。

在主 `.env` 增加可选 `skill_models` JSON 映射，以模型 ID 为键、`context_window` 和可选 `max_output_tokens` 为值。每项必须显式给出正整数窗口，输出额度省略时沿用主配置，并满足既有 `C > O + 13000`；拒绝未知字段、重复键、布尔值及非法结构。缺省映射不改变旧配置。

```dotenv
skill_models='{"small-model":{"context_window":64000,"max_output_tokens":4096}}'
```

未配置所需模型预算时，调用返回 `skill_model_unavailable`，不启动子模型、不静默换回主模型；服务拒绝该模型或 thinking 设置时如实回流失败。不同模型不共享 usage 估算锚点；使用新的背景摘录对话保持主供应商历史不变。

直接替换模型名却沿用未知窗口可能造成错误预算；增加完整多服务配置又超出本次目标，故采用同服务显式预算映射。

### 10. 热更新发布完整快照，重置有持久事务

在空闲期下一次非空输入提交边界检查来源指纹，先完成候选目录、命令命名空间、所有有效工具名及现有激活项重渲染，再整体发布。帮助、补全、分发、会话和下一请求必须引用同一代快照；当前执行中不监听或修改定义。新发现项无需先激活就拥有短命令。

局部解析错误仍跳过对应文件并报告，合法覆盖结果按三层规则重新计算；不再存在的激活项停用并提示，合法同名新定义按原参数更新。名称／工具等整体候选错误使本次刷新失败，保留上一合法快照，不创建半更新命令或先放宽白名单。失败诊断在该输入边界展示，用户仍可本地查看或修复定义。

`/reset` 在空闲期原子保存空历史、空激活映射及新的摘要／窗口估算状态检查点后，清掉内存历史、旧任务快照、摘要失败／熔断状态和工作 usage 锚点，准备下一次完整提醒。它保持当前会话 ID、模式、权限服务和长期记忆；终端可刷新状态但不把它实现为 `/clear`。存档和仍被存档引用的结果文件保留，取消既有后台记忆没有被定义为重置的一部分，后台维护不能把旧历史重新加入当前对话。检查点保存失败时内存旧状态保持，并沿既有持久化失败合同停止后续工作。

### 11. 激活恢复与独立审计采用结构化记录

激活变化保存规范名称、参数、顺序及来源指纹；检查点携带当前激活描述。恢复只读取合法结构化描述，不从历史 SOP、工具输出或名字猜测状态；用当前目录按既定覆盖规则重新加载和校验。来源变更、删除或坏文件按当前目录处理并给出诊断，最新工具校验失败仍阻止启动。旧存档没有激活字段时按空集合恢复；重置之后不从更早事件复活历史或 Skill。

子运行使用带父任务及子运行 ID 的独立审计记录，复用 Journal 的排他追加与刷盘规则。子工具启动前保存意图，实际结果随后保存；主历史投影只接收主入口的最终回流，不把子 history_commit 当作主 history_commit。实现可通过子 Journal 适配器路由这些记录，不能复制第二个同文件写入句柄。

恢复遇到未完成独立运行时展示实际证据与未确认副作用，截断不完整主调用组，不自动重跑子任务、不制造成功摘要。子缓存使用主会话下明确登记的子命名空间，随主会话生命周期保留；回流证据引用必须在主检查点中可验证。非持久测试会话可使用私有临时缓存。

新增记录和可选字段保持新版本读取旧 JSONL 的能力；不承诺旧版本正确识别新独立审计或重置状态，回退前必须停止活动任务并使用新版本检查存档。

## Risks / Trade-offs

- 每轮完整 SOP 会增加请求输入和历史中的重复提醒 → 全量计入预算、压缩完整旧交互、窗口不足明确停止；不静默省略活跃正文。
- 多个白名单交集可能没有普通工具 → 显示有效范围，提供本地停用；子运行同样不扩大父上限。
- 候选热更新可能同时改变覆盖来源及限制 → 整体校验和发布，坏候选保留上一合法快照；局部跳过及停用必须可见。
- 加载混入普通 spawn 或只读并发会丢失主状态或使用旧许可 → 系统主进程路由、串行边界与执行时动态校验。
- 独立执行耗时可能超过普通 30 秒工具期限 → 区分任务期限与工具期限，以总请求预算和可信取消约束独立任务。
- 子运行副作用与摘要回流可能在崩溃时分离 → 调用前意图和实际结果持久化，恢复仅报告、不重放。
- 同服务模型可能不支持相同 thinking 配置，实际窗口也需用户配置 → 请求前校验预算，服务错误如实回流，不猜窗口或偷偷换模型。
- 辅助资源可在磁盘上变化 → 入口定义固定，资源按实际读取结果处理并保留来源；不将旧模板当作当前业务文件。

## Migration Plan

1. 建立解析、目录和纯运行状态接口，覆盖错误分层及候选事务，再接入系统工具路由与动态工具集合。
2. 更新提醒和预算预览，接入共享 Skill、目录资源及三个随包内置样板；验证源码包和 wheel 均可发现样板。
3. 接入独立执行、历史摘录、统一请求预算、模型预算配置及子审计，验证取消和资源归属。
4. 接入命令快照、管理、热更新、`/reset` 和恢复；迁移固定 `/review`，保留其内置默认目标合同。
5. 同步 README、配置示例及验收清单，运行 pytest、构建及本次真实服务 tmux 验收，保留脱敏证据。
6. 实现验证通过并另行获准归档时再同步本变更十份增量主规格，并更新主 `slash-commands` 的 Purpose 中“固定提示词”描述为注册的对话能力。本次规划捕获不编辑主规格。

回退仅在所有主子运行结束后进行，保留新增存档和缓存供检查，不尝试删除实际业务副作用。旧配置兼容，新目录及可选 `skill_models` 由旧版本忽略或按其配置合同处理；含新记录的会话应先在支持本变更的版本中检查后再决定接续方式。
