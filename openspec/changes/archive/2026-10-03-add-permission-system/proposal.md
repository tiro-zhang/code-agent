## Why

MewCode 已能在 Agent Loop 中自主调用文件、搜索和 shell 工具，但除了工作目录边界与规划模式外，缺少统一的执行授权入口。需要在产生副作用或读取受限内容之前落实用户的权限策略，同时把拒绝作为模型可处理的工具结果，支持其在当前任务内调整方案。

## What Changes

- 增加五层防御：不可配置解除的危险命令正则黑名单、文件与搜索路径沙箱、细粒度规则、会话权限模式和人在回路授权。shell 不纳入操作系统级文件隔离。
- 用户级、项目级、本地级 YAML 的规则合并判断，统一遵守 `deny > ask > allow`；来源不构成覆盖顺序。
- 支持 `工具名(模式)` 规则表达式以及显式 `exact` / `glob` 匹配；`Bash` 是现有 `execute_command` 的配置别名，不改模型 API 工具名。
- 引入严格、默认、放行三档权限模式；所有档位保留显式 `deny`、硬黑名单、路径边界与 `/plan` 只读限制。
- 提供本次、本会话、永久授权；批准记录独立于规则，有效记录可满足 `ask`，但不能越过新的拒绝条件。
- 对 shell 完整命令及显式子命令检查 `deny` / `ask`；glob 放行只适用于简单命令。组合调用在执行前整体决定，无法解析的语法返回检查失败。
- 搜索按实际候选文件路径授权，拒绝的文件在读取内容之前排除；结果明确说明权限导致的搜索范围限制。
- 增加可取消、串行展示的授权交互，等待批准时不得显示工具已经启动；拒绝继续 Agent Loop，取消仍结束当前任务。
- **BREAKING**：默认模式下未命中放行规则或有效授权的工具调用将要求确认；原来可直接执行的 shell 语法可能因无法安全解析而被拒绝。

## Capabilities

### New Capabilities

- `tool-permissions`：五层判定、三来源 YAML、规则与匹配语义、权限模式、授权有效范围和持久化、拒绝与配置错误的行为。

### Modified Capabilities

- `tool-system`：在启动工具前加入异步授权，区分授权拒绝与取消，等待授权不占工具执行超时。
- `core-tools`：shell 结构检查与整体批准；文件与搜索按真实目标应用权限，搜索报告部分范围受限。
- `interactive-chat`：权限模式切换、活动任务内的授权输入、授权范围展示和等待状态。
- `plan-mode`：规划／执行模式与权限模式相互独立，`/do` 不隐式授予工具权限。

## Impact

- 涉及 `src/mewcode/tools/`、`agent.py`、`session.py`、`app.py`、`cli.py`、事件类型及新的权限模块；继续使用现有结构化工具结果和供应商协议。
- 引入安全 YAML 读写能力以及能识别所支持 POSIX shell 结构的解析能力；具体依赖在实现前做兼容性验证。
- 建议默认配置位置为 `~/.mewcode/permissions.yaml`、`<root>/.mewcode/permissions.yaml`、`<root>/.mewcode/permissions.local.yaml`；永久授权默认落到本地级，后者应被 Git 忽略。
- 补充权限单元／集成测试、真实 tmux 对话验收，以及 README 与 checklist 的权限章节。当前变更阶段只生成规划产物。
- 本章不增加网络请求限制、资源配额、审计日志、操作系统级 shell 沙箱，也不承诺检查脚本内部或运行时生成的命令。
