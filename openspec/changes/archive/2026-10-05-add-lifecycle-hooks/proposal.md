## Why

格式化、工具拦截和上下文补充等重复工作目前缺少统一的生命周期自动化入口，需要人工关注执行时机。在 Agent 的关键节点提供声明式 Hook，让触发条件明确、动作固定的工作自动执行，并将工具拒绝原因反馈给模型调整后续操作。

## What Changes

- 新增项目级 `.mewcode/hooks.yaml`，以必填 `event`、可选 `if`、必填 `action` 声明规则，启动时集中校验并加载固定快照。
- 提供会话、用户任务轮次、消息、工具四层生命周期事件，以及模式切换、上下文压缩等少量系统事件。
- 提供扁平 `all` 或 `any` 条件组合，支持精确、glob、正则及反向匹配；抽取共用底层匹配能力，保留现有权限 YAML 格式和匹配语义。
- 支持命令、提示词、HTTP 三种实际动作及子 Agent 声明占位；命令使用标准输入、HTTP 使用 JSON 请求体接收触发时的事件快照。
- 工具执行前的同步命令或 HTTP 动作可通过成功返回的显式 JSON 决策拒绝当前调用；拒绝生成配对的工具结果，主 Agent 可继续调整操作。
- 支持会话内只尝试一次、后台异步及命令超时；提示词同步注入下一次工作模型请求，并参与发送前的上下文预算检查。
- Hook 配置或执行失败仅产生诊断，不中断 Agent；动作遵守已确认的权限、规划模式、取消、资源清理和防递归边界。
- 本次不实现子 Agent 真实运行、一次性标记持久化、配置热重载或显式执行优先级。

## Capabilities

### New Capabilities

- `lifecycle-hooks`：声明式规则与集中校验、生命周期事件、条件匹配、动作输入及结果、工具拦截、提示词注入、一次性执行、后台任务及安全执行边界。

### Modified Capabilities

无。新增 Hook 行为由 `lifecycle-hooks` 描述；现有权限配置、拒绝优先级、规划工具范围、调用与结果配对及模型请求预算要求保持有效。

## Impact

- 预计新增 `src/mewcode/hooks/` 和共用匹配模块，接入 `session.py`、`agent.py`、`prompts.py`、工具执行与调度、模式切换及上下文维护入口；避免把规则解释和动作执行集中到 CLI 或终端打印逻辑。
- 复用现有权限判定、真实路径语义、结构化工具结果及受控进程清理能力；子 Agent 占位不调用现有独立 Skill 执行器。
- YAML 沿用现有依赖；HTTP 使用仓库已通过供应商及 MCP 依赖安装的 httpx2，并在实际直接使用时将其声明为直接运行时依赖。
- 新增匹配、配置、事件、拦截、注入、并发、取消及权限边界测试；实现时同步 README 和 checklist，并使用真实模型服务及 tmux 在临时工作目录完成本次验收。
