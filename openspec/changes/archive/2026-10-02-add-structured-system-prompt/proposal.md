## Why

MewCode 已能自主调用工具完成任务，但全局提示仍是简短文本，工具选择、编辑前读取和结果验证缺少一致指引；规划模式还会整体替换系统提示。将稳定规则结构化，并将环境和当前模式作为独立应用上下文注入，可以提高行为一致性，同时为重复模型请求保留可复用的缓存前缀。

## What Changes

- 将固定系统提示按身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出七个模块依次拼装，以空行分隔；环境信息置于补充上下文，后接自定义指令、已激活 Skill、长期记忆的可选位置。本章仅预留这些位置，不实现外部加载。
- 在全局工具规则和相关工具描述中共同强调专用工具优先、编辑现存文件前先读取相关内容，以及修改后按需验证；继续沿用既有工具操作语义。
- **BREAKING（内部上下文契约）**：模式状态从整体替换系统提示改为应用生成的 `<mewcode-context>` 提醒；在两种协议中通过普通消息内容传输，由固定系统提示解释用途，不将其描述为原生 system 权限。真实用户任务、应用提醒和工具结果在本地保持可辨别。
- 按会话内每次实际发出的模型请求计数，跨普通用户任务累计，模式切换后重置；首轮完整、默认每隔 5 次请求完整重复，其余精简，历史裁剪后强制补发。已提交提醒原样保留，随所属任务裁剪。
- 以现有 DeepSeek Anthropic 兼容配置为真实缓存验收基准，使用自动公共前缀缓存；保留规划模式三工具筛选及执行前拦截，接受模式切换时重新建立相应前缀。
- 补齐缓存用量的字段映射、统计与终端展示，区分缓存命中、未命中和实际缓存写入，缺失数据保持未知；准备固定场景进行提示调整前后的人工比较。
- 本章不实现项目指令文件加载、自动记忆、Skill 自动激活、真实 MCP 接入、自动化评估或新的权限审批系统。

## Capabilities

### New Capabilities

- `system-prompt`: 七模块的确定性拼装、可选模块位置、工具规则双重强化和稳定内容边界。
- `runtime-context`: 环境与模式提醒的标签形式、请求级注入频率、会话计数、历史提交和裁剪语义。
- `prompt-caching`: 按服务处理缓存策略、缓存用量语义、DeepSeek 真实命中验收及人工对比方案。

### Modified Capabilities

- `llm-providers`: 将应用上下文映射为合法协议内容，替代模式指令必须独立走 system 的要求；明确总输入及缓存用量的归一化。
- `interactive-chat`: 在现有进度与用量输出中展示缓存统计，并避免将应用提醒显示为用户输入或回复目标。

## Impact

- 预计新增提示模块拼装和会话提醒策略，调整 `types.py`、`session.py`、`agent.py`、`providers/tool_messages.py`、两个 Provider、Collector、用量聚合与终端展示，以及六个工具的用途描述。
- 保持既有 `.env`、启动命令、请求预算、计划有效性、工具调度、目录边界和取消语义；不增加框架依赖或新的用户配置项。
- 增补模块顺序、1/6/11 请求频率、跨任务计数、失败/裁剪/模式切换、消息配对及缓存缺失数据的确定性回归；实施后使用 tmux 在 DeepSeek 上执行真实工具任务，并按 `checklist.md` 记录缓存命中与人工比较证据。
