## Context

动机与范围见 `proposal.md`，行为合同见六份增量规格。本变更跨输入入口、命令定义、会话控制和终端布局，需要明确接口及迁移顺序。

现有 `terminal/commands.py` 用固定名称元组、解析分支、手写帮助和补全分支维护七个命令；`app._run` 再按解析结果选择本地操作或会话异步流。增强终端已有聊天 Buffer 和 Tab 绑定，但需要可见的候选菜单。`TerminalController` 已统一增强／plain 输入输出与安全展示，可以作为界面适配基础。

`ChatSession` 当前维护待执行计划快照，`execute_plan` 消费快照并自动构造执行问题；这与已确认的 `/do` 仅切换模式冲突。记忆存储的 `snapshot` 会进入会建目录及锁文件的路径，读取还可能修复文件权限，`refresh` 会重建索引，因此不能直接用作本次只读查看。当前项目已有会话扫描能力和独立摘要事件流，可复用而不引入新服务。

## Goals / Non-Goals

**Goals:**

- 一份登记信息驱动查找、帮助和补全；注册错误在会话和外部资源初始化前暴露。
- 命令解析和处理可在无真实终端、无真实供应商的环境下测试，终端库仅存在于适配层。
- 保持单一输入拥有者、任务取消、事件流关闭、授权阶段隔离和工作／维护统计边界。
- 把模式切换与用户任务提交分开，保留可选 `/plan <任务>` 的便捷入口。

**Non-Goals:**

- 不建立插件加载器、事件总线、运行时注册或用户自定义命令配置。
- 不增加提示词生成模型、命令级权限或新的审查模式；工具权限继续由原权限系统决定。
- 不实现运行中更换会话，也不提供记忆的新增、编辑、删除或显式重建指令。
- 不迁移存档格式或修改过去的历史记录。

## Decisions

### 1. 命令核心移到独立包，静态定义并在启动时冻结

新增 `src/mewcode/commands/`，分别容纳定义与注册、解析、分发、内置处理函数和能力协议。名称使用无 `/` 的规范标识，展示时添加 `/`；不可变定义保存 `name`、`aliases`、`description`、`usage`、`kind`、可选 `argument_hint`、`hidden` 和异步 `handler`。

注册表保留有序的规范命令列表以及名称／别名查找表。统一 `lower()`，逐个验证名称与别名；重复项即使属于同一命令也拒绝。空定义、无处理函数或非法执行类型同样属于启动错误。默认注册完成后冻结；默认顺序按高频十条及兼容退出安排，不使用集合顺序。

应用在创建 Provider、会话存档和 MCP 之前构造注册表。注册错误转成明确的启动错误和退出码 2；立即退出，不要求输出 Python 栈作为用户体验的一部分。测试可注入替代定义制造冲突，生产入口不提供动态注册接口。

继续保留多处 if/elif 会维持同步负担；引入插件发现及装饰器自动扫描又会扩大初始化副作用。本次采用显式内置定义列表。`terminal/commands.py` 可保留迁移期薄转发，但不再保存第二份名称、帮助或候选数据。

### 2. 解析保留原始任务，参数解释留给对应命令

解析结果区分空输入、普通消息及带规范化名称和参数尾部的命令调用。未知命令由注册查找产生用法错误，不在解析器中维护已知名称。处理顺序为全空白、多行普通消息、单行 `//` 转义、普通消息、单行斜杠命令。

只对命令判定和参数边界去空白，普通正文原样保留。以第一个空白分隔名称和参数，支持空格及 Tab；只对名称转小写。参数不经 `shlex`，保留引号、大小写和内部空白。权限、会话及记忆子命令自行验证固定语法，`review` 直接接收原始目标文本。参数校验完成后才访问操作接口。

这一选择保持现有多行、路径转义及 `/plan <任务>` 语义；通用 shell 解析会改变自然语言目标且无实际执行需求。

### 3. 处理函数返回明确结果，任务流仍由一个应用入口消费

内置处理函数统一为异步调用，接收参数及 `CommandContext`。结果限定为已处理、对话提交、摘要维护或受控退出；结果中的任务文本只由统一入口消费一次。可立即完成的本地与状态命令先通过能力接口展示或操作，再返回已处理。

`CommandContext` 组合窄能力接口：

- 界面端口：显示完整安全文本、清屏、刷新状态及查询终端能力。
- 会话服务：读取会话、用量和记忆，切换模式、执行现有权限操作。
- 对话／维护端口：消费对话提交或摘要结果，调用统一发送用户消息及事件流处理入口。

命令核心不持有 `TerminalController`、Renderer 或终端 Buffer。应用适配器把端口绑定到当前会话和统一终端输出。上下文不允许处理函数直接改会话历史列表或界面模式副本。

```text
Submitted Input --> Parser
                      |
                      +--> Empty --> Return
                      +--> Message --------------------------+
                      +--> Command --> Registry --> Handler  |
                                                       |    |
                                                       +--> Handled
                                                       +--> Exit
                                                       +--> Maintenance --> Summary Runner
                                                       +--> Prompt -----+
                                                                        |
                                                               Conversation Runner
                                                                        |
                                                                       Agent
```

应用提取可复用的任务流消费逻辑，统一建立取消事件、输入阶段、事件渲染、异常展示、受保护的流关闭和 EOF 收尾。`/review` 与普通消息共享该入口，展开文本不再次进入命令解析。`/plan <任务>` 先完成模式切换，再返回一次对话提交；切换存档失败则不提交任务。`/compact` 返回摘要维护结果，继续使用 `purpose=summary` 的既有通道，不清空最近工作统计或触发新的记忆提取。

这种明确结果比处理函数任意启动 Agent 或向输入队列注入文本更容易保证一次提交、取消及流关闭；无需另建后台命令队列。命令类型描述用户可观察的用途，不作为不同授权等级。

### 4. 模式仍由会话负责，移除自动消费计划状态

沿用内部 `execute`／`plan` 值，界面分别映射为 `[DEFAULT]`／`[PLAN]`，不会把展示标签改成新的权限模式。会话服务在模式事件成功持久保存后才更新模式、PromptState 和界面；失败保留原模式。

`/plan` 继续进入或重新进入规划并准备新提醒周期，可附带任务。`/do` 从规划切回执行并准备下一工作请求的执行周期；已在执行模式时重复 `/do` 仅显示当前模式，不追加任务或重置周期。两者保留历史、权限模式和已有精确授权。

移除 `_pending_plan`、快照生成和 `execute_plan` 的命令用途，并清理无剩余用途的内部状态及错误类型。规划答复保存为正常历史，执行请求来自用户的新消息。状态页去掉“待执行计划可用”字段。旧 JSONL 已有模式事件及历史足够恢复，不改记录版本，也不从历史文本构造自动执行凭证。

保留旧 `/do` 自动执行并新增退出规划命令会与已确认的动词语义冲突，因此本变更明确为用户可见的兼容性变化。README 和帮助提供新例子：`/plan 任务`、`/do`、再输入“按上面的计划执行并验证”。

### 5. 帮助与补全共用定义，菜单由终端适配器呈现

帮助遍历可见定义，显示名称、别名、描述、用法、类型和可选参数提示；现有发送、换行、授权、取消和恢复说明由终端能力段补充。

补全查询返回候选文本、替换范围和描述，名称及别名前缀统一小写匹配；隐藏命令的全部标识都过滤。命令名补全仅作用于单行草稿的命令位置，保留外侧空白；参数候选由定义附带的静态语法信息提供，不能从提示字符串猜测。首版固定候选覆盖权限 mode/revoke、session list、memory list/show 及范围值，不扫描文件或生成提示词。

增强终端将补全查询接到现有 Buffer，Tab 无候选时无操作、单候选时直接替换、多候选时显示菜单；接受候选和关闭菜单不提交。多候选菜单打开时，Enter 先确认候选并关闭菜单，用户再次明确 Enter 才执行命令，Esc 关闭菜单并保留编辑能力。授权阶段与多行输入不启用该菜单，窗口大小变化不能让候选丢失可达性。plain 保留同样命令和帮助语义，不宣称提供交互式菜单。

### 6. 清屏由终端适配器控制，不操作会话

`/clear` 调用界面清屏能力，在交互终端清除可控显示并使布局失效、重绘状态栏与输入区；不把显示清理映射为历史重置、统计清空或新会话。原进程输入历史继续可用。

对重定向输出或不支持清屏的终端，只显示清屏不可用说明，不输出 ANSI 光标控制符。终端模拟器自身的历史滚动区是否完全清除取决于其能力，本合同保证应用可控区域及状态重绘，不承诺删除已有存档或外部终端记录。

### 7. 会话列表复用扫描，记忆新增真正只读的读取路径

会话查看通过现有身份和扫描服务获得元信息，不重新初始化会话、持有另一写入句柄或改变后台任务归属。`new`、`switch`、`resume` 等未支持子命令本地报错，并给出 `--resume` 引导。

记忆服务提供状态、列出合法笔记和按 `(scope, id)` 读取笔记的只读接口。默认列表同时展示项目和用户两域，域与 ID 共同构成展示身份。存储不存在时返回空，不触发 `_ensure`、`locked`、`snapshot`、`refresh` 或 `_read` 中的权限修复。

读取复用已有身份、frontmatter、大小及普通文件校验规则，但打开文件的路径不执行 chmod、创建或索引写入。查看目录及祖先须满足既有真实路径／符号链接边界；打开时禁止跟随符号链接，检查普通文件及有界大小。非法或损坏条目产生局部诊断，其余合法笔记仍可查看。后台可能原子更新笔记，因此查询只承诺所读合法版本，不建立跨域事务或阻塞维护的持久锁。

关闭自动维护时，查看仍能读取已有合法笔记；状态明确“自动维护已禁用”。完整正文通过安全输出通道展示，不使用带固定长度截断的摘要输出方法。索引是否健康不决定笔记能否查看；查看不更新当前注入版本或后台用量。

只展示缓存索引会遗漏未入选笔记，复用现有刷新接口则违背只读要求，故增加存储读取路径而不增加记忆写入命令。

### 8. 审查提示固定，目标由原始参数表达

内置定义保存固定审查文本：要求检查指定目标、报告有依据的问题及位置、区分已检查和未检查范围，不把审查当作自动修复。无参数附加“当前 Git 未提交改动”，有参数附加用户目标；不通过本地预执行 Git 命令收集动态上下文，也不调用模型生成提示词。

展开文本作为正常用户任务提交，工作历史和存档保存实际提交文本；原始 `/review` 字符串及展开文本均不加入终端的普通消息输入历史，以保持命令历史边界。审查的正常结束、失败、取消和后续记忆维护沿用普通任务合同。

命令不切换模式。执行模式下模型可按现有权限获得 Git 信息；规划模式下命令工具仍禁止，提示要求如实说明无法检查的范围。非 Git 项目、无改动或授权拒绝时不悄悄扩展审查目标。这里不增加强制只读审查权限机制，固定提示词不替代工具权限检查。

## Risks / Trade-offs

- `/do` 行为变化会影响既有使用习惯 → 在提案标记 BREAKING，更新全部帮助、提示、测试和验收例子，不留下自动执行承诺。
- 任务流迁移可能破坏取消或授权阶段隔离 → 共用一个流消费入口，覆盖普通消息、review、带任务 plan 和 compact 的失败及取消路径。
- 多候选菜单可能与现有 eager Enter 冲突 → 菜单优先处理确认，验证第一下 Enter 仅确认候选、第二下才提交，补全期间模型请求数始终为零。
- 名称与别名规范化可能引入隐性覆盖 → 启动前全面拒绝冲突，包括隐藏命令和同一条定义的重复项。
- “只读查看”误用存储维护接口会写磁盘 → 新增无写入读取路径，测试缺失目录、文件权限及索引内容在查看前后不变。
- `/compact` 仍有模型时延与用量 → 类型和帮助明确为独立维护，不宣称所有命令均零模型请求。
- `/review` 继承当前能力，规划模式可能无法读取 Git 差异 → 如实报告限制，支持显式文件目标，不自动切换模式或批准命令。

## Migration Plan

1. 建立注册、解析、分发及窄接口，迁移已有命令定义，先验证启动失败和普通正文保真。
2. 改造会话模式与提醒周期，删除自动消费计划路径；适配统一任务与摘要消费入口。
3. 补充会话和记忆查看、清屏、固定审查提示，接入帮助与补全菜单。
4. 同步用户文档、现有测试和验收清单，运行完整 pytest、构建及本次真实服务 tmux 验收。
5. 实现通过并获准归档时，同步六份增量规格，并单独更新主 `plan-mode` 的 Purpose：将“直接执行最新有效计划”改为“显式切换模式并由新用户请求启动执行”，因为增量规格不修改既有 Purpose。本次规划捕获不改主规格。

存档格式不变；若实现需要回退，回退本变更代码即可继续读取原存档。回退会恢复旧 `/do` 自动执行语义，必须与对应版本的帮助和 README 一起回退，不能仅替换命令处理函数。
