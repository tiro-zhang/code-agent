## Why

上一章已经提供六个工具，但每次用户提问最多执行一次工具，用户必须不断催促模型完成后续步骤。本章让 MewCode 在一次任务中自主请求模型、执行工具、读取结果并调整行动，直到模型结束或触发明确的停止条件。

## What Changes

- **BREAKING**：用 ReAct Agent Loop 替代每轮单次工具执行和禁止工具的最终答复阶段；工具失败后模型可以在同一任务中调整参数并继续执行。
- 引入原生异步 Agent、Provider 和统一事件流，提供文本、实际思考、工具调用、工具开始、工具结果、Token 用量、进度及停止原因；流式收集器同时即时转发片段和收集完整响应。
- 每次用户请求默认最多发起 20 次应用层 LLM 请求，可配置；纯文本答复及现有上下文超限恢复重试都消耗预算。模型结束、达到上限、用户取消、连续 3 轮全部未知工具或流式请求失败时停止。
- 接受一次响应中的多个工具调用：连续读类调用最多 4 个并发，写文件、改文件及 shell 命令形成串行边界；保持调用与结果配对及历史顺序。
- 增加两阶段 Plan Mode：默认执行模式；`/plan` 切换到只读规划，后续对话保持只读；`/do` 直接执行最新有效计划并恢复全部工具。
- 保留工具的进程隔离、超时、结构化错误及取消清理，保留现有完整轮次上下文裁剪恢复；取消与失败后仍保存已完成操作的结果。
- 本章不增加权限系统、上下文压缩、交互式确认、持久化任务或文件修改自动回滚。

## Capabilities

### New Capabilities

- `agent-loop`: 自主循环、请求预算、停止条件、双路流式收集、异步事件、按安全性分批执行与取消收尾。
- `plan-mode`: 只读规划模式、计划保存与失效、`/plan` 和 `/do` 的切换及直接执行计划。

### Modified Capabilities

- `interactive-chat`: 从单次工具阶段变为自主多步执行，展示异步进度和停止原因，保留多阶段历史及中断后的成对结果。
- `llm-providers`: 异步流式接口、多工具协议控制、结果按 ID 回灌、Token 用量与原有思考续接。
- `tool-system`: 增加只读元信息、按模式筛选工具、异步执行入口及多工具取消清理。
- `provider-configuration`: 在原有配置文件中支持可选的正整数 `max_iterations`，缺省为 20，启动前校验。

## Impact

- 新增 Agent、流式收集器和工具调度职责，调整 `types.py`、`session.py`、两个 Provider、工具注册/执行器以及终端事件消费；内部同步 Provider 和会话调用接口需要迁移。
- 使用当前已安装 SDK 的异步客户端，保留六个工具的同步执行方法及独立工作进程；既有工具参数、目录边界、拒绝覆盖和唯一匹配编辑语义保持兼容。
- 原有 `.env` 配置及启动命令继续有效；实现阶段需补充配置示例、README 和 `checklist.md`。
- 自动化验收覆盖五种停止条件、请求预算、事件顺序、多工具并发边界、历史配对与 Plan Mode。按项目约定用 tmux 验证真实多步操作和 `/plan` → `/do`，分别记录两种协议的验收结果。
