## Context

动机见 [proposal.md](proposal.md)。当前 `ChatSession.ask()` 使用同步生成器：首个响应最多处理一个工具，再以 `tool_choice=none` 请求最终答复。两种 Provider 都限制多工具生成，但已经能够独立拼接多个调用的参数碎片。`_response()` 已经同时转发文本和收集完整响应，可以提取这项职责。

`ToolExecutor` 为每次调用创建 POSIX 工作进程，通过管道收集结果，使用进程组处理超时和 Ctrl+C。目前轮询、等待和取消处理是同步的，并依赖主线程信号；把入口放入线程后仅取消等待，不能保证停止工具。六个工具的同步执行方法、目录约束、输出上限和结构化结果已经建立，本章沿用这些操作语义。

本地安装的 OpenAI、Anthropic SDK 均提供异步客户端。当前上下文超限恢复按完整用户轮次裁剪，步长为 1、2、4 等；用户已确认保留该行为，本章只使恢复请求受统一预算约束。

## Goals / Non-Goals

**Goals:**

- 循环、响应收集、工具调度、历史和终端展示各自有明确职责，Agent 不依赖终端对象。
- 请求预算只有一个来源，所有应用层模型请求都经过它；工具结果只有一个历史提交入口。
- 取消贯穿网络流、排队调用、活动工作进程和历史收尾，不留下孤立调用或继续运行的受控子进程。
- Plan Mode 复用同一循环和工具元信息，执行前再次检查模式约束。

**Non-Goals:**

- 通用 Agent 框架、事件持久化、后台任务或多任务同时修改同一个会话。
- 改写六个工具的文件操作算法、复用持久工作进程或扩展 Windows 进程管理。
- 权限审批、交互式确认、上下文摘要压缩，以及对外部进程和恶意目录变化提供新的隔离保证。

## Decisions

### 1. 原生异步编排，工具继续在独立进程内同步执行

采用原生异步 Agent 和 Provider。Provider 暴露 `AsyncIterator[ProviderEvent]`，使用 `AsyncOpenAI`、`AsyncAnthropic` 的原始流；工具执行器提供异步入口，六个工具继续使用同步 `execute()`。现有 `ChatSession` 保留会话历史、模式与待执行计划，Agent 负责一次任务的循环。

建议职责如下；模块可以按这些边界组织，不强制一项对应一个文件：

| 组件 | 输入与输出 | 职责 |
| --- | --- | --- |
| 会话 | 用户任务或模式指令、Agent 事件 | 保存历史、模式和待执行计划，提供单次任务上下文 |
| Agent | 任务、模式、历史、配置 → 异步事件 | 请求预算、循环与停止条件，协调收集和调度 |
| StreamCollector | Provider 异步流 → 实时事件和完整响应 | 转发文本与实际思考，收集消息和用量，检查正常结束 |
| ToolScheduler | 完整调用列表、允许工具 → 事件和有序结果 | 安全分批、并发上限、错误隔离及取消收尾 |
| ToolExecutor | 工具名、参数、执行上下文 → 结果 | 校验与工作进程生命周期、超时、输出收集和取消 |
| CLI | 终端输入、Agent 事件 | 解析指令、显示事件、把 Ctrl+C 转为任务取消 |

```text
CLI --async for--> Agent.run()
                     |
                     +--> StreamCollector --> Provider stream
                     |
                     +--> ToolScheduler --> ToolExecutor --> Worker
                     |
                     +--> Session history

Agent events --> CLI
```

循环用异步生成器向调用者提供事件。并发工具通过内部有界队列交付结果，由单一消费者发布事件及修改历史；队列容量与调用数量上限相容，停止时也有受控的排空和收尾路径。终端消费较慢时使用背压，不建立无限文本或结果队列。

替代方案是线程桥接现有同步 Provider。它减少接口迁移，但增加队列、流关闭和线程退出的协调，难以统一取消。本章选择原生异步，不新增 Agent 框架依赖；同步工具工作进程是保留的执行边界。

### 2. 双路收集完整响应，再进入执行判断

Provider 保留供应商协议解析职责，包括调用索引、参数碎片、正常结束标记和 Anthropic 原始续接块；Collector 负责通用的文本累计、用量收集及完成状态。复用已有参数拼接与错误包装，不在 Collector 再解析一套供应商协议。

每收到文本或实际思考片段，立即发布对应事件；同时累计最终文本。Provider 的正常完成事件交出完整助手消息，Collector 将它与用量封装为完整响应。一个请求最多产生一个完整响应；结束后的重复内容、缺失结束标记或异常协议都属于失败。

Provider 完成事件与任务 `finished` 事件分开：前者结束一次模型响应，后者结束整个用户任务。流未正常完成时，已显示内容仅留在界面，不提交不完整消息、不发布可执行的 `tool_call`，也不执行已拼好的参数。普通回答须包含非空文本；完整工具响应可以没有文本。

### 3. 请求预算与停止条件

每次用户任务创建独立预算，默认 `max_iterations=20`；`/plan <任务>`、规划模式中的后续消息和 `/do` 各自重新计数。即将调用 Provider 前预留一次预算，并发布请求进度；失败尝试、最终文本响应、上下文恢复重试均计数。一次响应中有多少工具不影响计数。

禁止 SDK 隐式自动重试，由应用显式决定是否发起请求，保证预算和停止原因可观察。除已有上下文超限恢复外，不增加网络或流式失败自动重试。

第 N 次已获授权的请求如果正常返回工具调用，处理该响应的整个工具批次、提交配对历史，然后在发起第 N+1 次请求前检查预算。预算耗尽不追加禁止工具的总结请求。如果第 N 次正常返回非空纯文本，仍属于模型正常结束。

| `finished.reason` | 触发条件 | 收尾 |
| --- | --- | --- |
| `model_done` | 完整响应无工具调用且文本非空 | 保存最终回答；规划模式保存有效计划 |
| `max_iterations` | 下一次请求将超过预算 | 保留已提交历史，说明达到上限 |
| `cancelled` | 用户取消活动任务 | 关闭模型流、停止活动进程、补齐取消结果 |
| `unknown_tool_limit` | 连续 3 个完整工具响应的全部名称都未注册 | 保存本批全部 `unknown_tool` 结果后停止 |
| `stream_error` | 模型请求失败、协议异常或空普通答复 | 丢弃本次不完整响应，保留先前已提交记录 |

未知工具计数由完整响应决定：包含任一已注册名称就清零，即使该调用参数错误或被当前模式禁止。全部未知时，各调用先获得结构化错误；前两轮可继续让模型调整，第三轮停止。上下文恢复尝试没有产生完整工具响应，不增加或清零该计数。

取消一旦生效就禁止启动后续请求或工具。若取消发生在清理边界，已获得的实际结果仍保存，不能改写成“未执行”；`finished` 在收尾完成后只发布一次。正常无工具响应优先判为 `model_done`，未知工具阈值在该批提交后判定，请求上限在下一次请求前判定，从而避免边界情况下重复停止事件。

### 4. 只读元信息与按顺序分批

工具登记增加本地 `read_only` 元信息。六个工具中 `read_file`、`glob_files`、`search_code` 为 true，其余为 false；未声明的工具按 false 处理。它既用于 Plan Mode 筛选，也用于并发调度，不导出为供应商不认识的工具字段。shell 不根据命令字符串猜测只读性。

调度器先取得完整调用列表并保留其顺序，将连续只读调用作为一组，组内最多 4 个工作进程并发。每个有副作用的调用单独构成串行批次；前一组全部完成及清理后，才进入下一组。未知、模式禁止和参数错误直接形成结果，不启动工作进程；无法确认只读性的调用按串行边界处理。

```text
read A + search --> edit A --> read A + glob --> shell
  parallel          serial      parallel       serial
```

普通工具错误或超时只影响对应结果，同一响应的其他调用继续执行；是否读取状态、修正参数或重试，由模型在下一次请求中决定。调度器不自动重试工具。界面可按完成顺序收到结果，结果消息则按原始调用顺序写入历史。

替代方案是全串行或把所有读工具集中到最前面。前者无法实现本章需要的并发；后者会把修改后的读取提前，改变模型意图。连续分组保留原始顺序并限制资源消耗。

### 5. 异步执行器的取消和资源回收

保留 `spawn` 工作进程、进程组及结构化管道。父进程以异步方式等待管道或截止时间，不能把同步 `poll()`、`sleep()`、`join()` 放在事件循环的常规路径阻塞所有任务。进程信号和期限由父进程负责，工作进程不决定是否进入下一轮。

单个工具超时仍先终止再强制清理同组进程，构造有界部分输出及 `timeout` 结果；它不会取消同组其他只读工具。任务取消则停止新调度，取消全部活动工具并等待每个清理完成；保留已经完成的结果，为开始但未完成的调用生成 `cancelled`，为未开始的调用生成带 `details.not_started=true` 的 `cancelled`。

清理受保护，重复 Ctrl+C 不能使调用/结果配对和进程回收提前退出。执行已完成、清理期间收到取消的竞争路径继续保存实际结果及完成标记；有副作用的结果仍准确说明影响，不声称回滚。并发执行不能让多个工具分别安装或恢复进程级 SIGINT 处理器；由 CLI/任务控制层统一传播取消。

沿用 POSIX 进程组边界。主动脱离组的后台进程不属于本章可保证的清理范围；不扩大既有 shell 能力和隔离承诺。

### 6. 统一事件与 Token 用量

事件带 `run_id`、本次请求序号和类型；工具事件再带原始调用 ID，避免并发结果串到另一个调用。数据由带类型的不可变记录表达，不依赖终端格式化或 SDK 对象。

| 类型 | 载荷及语义 |
| --- | --- |
| `text_delta` / `thinking_delta` | 原始片段；后者只使用实际可展示的模型输出 |
| `tool_call` | 正常完成响应中的完整调用，按模型顺序发布，不表示已开始执行 |
| `tool_started` | 实际进入执行入口的调用；校验拒绝和未启动取消不伪造进程开始 |
| `tool_result` | 调用 ID、工具名和 `ToolResult`，每个已接受调用恰好一个结果 |
| `usage` | 本次请求的输入、输出 Token 用量及是否完整；缺失字段为 `None` |
| `progress` | 当前模式、请求次数/上限、阶段；不计算任务完成百分比 |
| `history_trimmed` | 现有完整轮次裁剪的数量和提示 |
| `finished` | 停止原因、请求次数及可安全展示的说明 |

用量按请求发布一次，归一化后不重复累加。同一请求的累计输出数据采用最后有效值，不把每个更新相加；缓存输入等供应商附加数据与基础计数分开，未返回的字段不填零。若展示任务总量，缺失任一请求的用量时须标注统计不完整，不能把已知部分称为完整总量或账单。

终端沿用 `思考>`、`MewCode>`、`工具>`，增加简短进度、用量和明确停止原因。`tool_call` 表示已接收，`tool_started` 表示开始；写入参数只做有界摘要。保留凭据脱敏与控制字符转义，不默认打印完整写入内容。

### 7. 多工具协议控制及用量归一化

OpenAI Chat Completions 请求保持 `tool_choice=auto`，开启多调用能力 `parallel_tool_calls=true`；应用仍按安全性调度，不直接采用 API 字段作为本地并发承诺。原有按索引拼接及逐 ID 工具消息回灌继续使用。[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)

OpenAI 流请求增加 `stream_options={"include_usage": true}`，处理结束附近 `choices=[]` 的用量块，不能因没有 choice 而跳过其 `usage`。普通内容的结束标记后仍允许规定的用量块，不能误判为额外回答；中断可能没有完整用量。该行为已与本地 SDK 类型定义交叉核对。[OpenAI 官方流式示例的用量部分](https://developers.openai.com/cookbook/examples/how_to_stream_completions)

Anthropic 使用 `tool_choice={"type": "auto"}`，去掉 `disable_parallel_tool_use=true`，允许正常多调用响应；回灌为紧随助手的用户 `tool_result` 块，每个 ID 一个结果。继续完整保留工具轮次的思考、签名、不可展示块和顺序。[Claude Parallel tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use)

Anthropic 用量从消息起始及消息更新中取得，消息更新的计数为累计值，采用最后有效值。Provider 的原始流处理继续保留参数 JSON 错误的回灌路径，不能切换到提前解析失败就丢失调用 ID 的便利层。[Claude Streaming messages](https://platform.claude.com/docs/en/build-with-claude/streaming)

兼容服务未提供用量时正常运行并显示未知；明确拒绝协议参数时给出兼容错误，不隐式切换协议或追加不计数请求。原有参数总量和调用索引上限继续生效；缺失或重复 ID、缺失名称及非正常结束仍禁止执行整个不完整响应。模型选择和思考配置策略不在本次迁移范围。

### 8. 历史采用完整响应与结果配对提交

第一个响应完成前，用户问题作为候选消息；未正常结束不提交候选历史。获得工具响应后，调度结束或取消收尾为所有调用产生结果，然后一次提交用户问题（若尚未提交）、完整助手调用和有序工具结果，再进入下一次 LLM 请求。后续批次按同样边界提交。普通完整非空回答提交后结束任务。

本次未完成流只丢弃本次候选助手响应，保留已经提交的先前批次；下一次用户任务可以看到真实操作结果。工具执行或取消后不留下缺失结果的助手调用，也不因后续模型失败而重新执行先前工具。

上下文恢复继续只在未输出模型文本或思考片段、存在较早完整用户轮次时裁剪。多次 LLM/工具阶段仍属于同一个用户轮次，不能把当前任务的某个批次当成旧轮次删除；完整任务及配对结果一起保留。每次恢复请求预留预算，预算耗尽直接停止，裁剪本身不触发工具重放。

### 9. 两阶段 Plan Mode 与有效计划

默认 `execute` 模式。`/plan` 进入 `plan`，清除旧待执行标记并提示输入任务；`/plan <任务>` 在切换后立即运行只读 Agent。规划模式中的后续消息同样运行只读 Agent，并在开始新一轮规划时使上一待执行计划失效，避免失败后意外执行旧版本。

有效计划来自规划任务以 `model_done` 正常结束时的最终非空答复。会话保存任务上下文和该答复作为内存快照；不把中间文本、思考、工具结果或不完整答复当成计划。规划提示要求每次成功答复给出完整的当前计划，包含目标、步骤及验证方式；采用可读文本，不引入额外 JSON 计划协议或 Markdown 解析器。

`/do` 检查当前是否有待执行的有效计划。有则原子取得快照、清除待执行标记、切回执行模式，以“执行以下最新计划”及快照内容创建新的用户任务，重新分配请求预算，直接运行 Agent。历史中的规划上下文继续可用；模式指令作为独立系统提示映射到两种协议，不从工具输出构造系统指令。已启动的计划不会因再次输入 `/do` 被自动重复执行。

没有有效计划时，`/do` 只显示提示，不请求模型、不修改工具执行状态。计划仅保存在本次会话；退出后丢弃。

规划模式通过同一份 `read_only` 元信息筛选 API 工具定义，执行器在参数校验和启动进程前再次检查允许工具。已注册但不允许的调用得到 `tool_not_allowed`；未注册调用仍为 `unknown_tool`，两者计数语义不同。这是模式行为约束，不增加权限审批和用户确认流程。

### 10. 可验证的验收安排

自动化使用可控异步模型流验证多阶段读取、修改、命令检查和纯文本收尾；验证失败结果后模型调整而不是调度器自动重试。逐项覆盖五个停止原因、最后一次请求返回工具/纯文本的边界、上下文恢复消耗预算及当前任务不被裁剪。

并发验证使用进程握手和可控阻塞观察实际开始/完成顺序及最大活动数，覆盖读组并发、写边界、修改后读取和结果乱序完成但历史有序；不单靠墙钟耗时推断并发。取消验证覆盖模型流、多个活动读工具、串行写/命令、未启动调用，以及清理期间重复取消，检查进程/子进程确实退出和文件实际状态。

协议回归覆盖多个交错参数流、无 choice 用量块、累计用量去重、缺失用量、非法 JSON、思考签名续接、模式工具筛选及未知/禁止工具区分。Plan Mode 验证普通后续消息继续只读、计划修订、失败失效、无计划 `/do` 和直接执行最新计划。

实现完成后按 `AGENTS.md` 在 tmux 发出真实多步请求，检查实际文件和命令结果；真实验证只读计划期间无写入、`/do` 后按计划执行、Ctrl+C 后恢复提示符及下一轮上下文。OpenAI 兼容、DeepSeek Anthropic 兼容和官方 Claude 分别记录，不把兼容服务结果视为官方 Claude 验收。`checklist.md` 记录通过、失败、未执行和具体原因。

## Risks / Trade-offs

- [循环可能持续消耗请求且不完成目标] → 全部请求共用有限预算；不把模型停止原因等同于任务已经通过验收。
- [模型把有依赖的操作放在同一批] → 保留原始顺序，只并发连续读类调用，写与命令形成串行边界。
- [取消或超时发生前已经产生修改] → 保留实际结果和副作用说明；让模型后续依据结果检查状态，不由调度器重放或回滚。
- [异步取消只停止等待或打断清理] → 统一取消传播、保护清理、等待工作进程组回收后发布终止事件。
- [多工具结果更快占满上下文] → 保留工具输出上限和现有完整轮次恢复；恢复消耗统一预算，压缩留待后续章节。
- [兼容服务缺少用量或不支持参数] → 未知用量不虚构；参数拒绝报告兼容错误，通过分协议真实验收确认支持情况。
- [计划生成后外部文件可能变化] → 执行提示要求按需核对当前状态，继续使用工具已有文件变化和唯一匹配检查；计划不承诺锁定工作区。

## Migration Plan

内部调用从同步迭代迁移到异步迭代，保留现有同步 CLI 启动入口，由其管理事件循环及客户端关闭。配置新增可选 `max_iterations`，缺省 20、必须为正整数；原有五个必填字段和 `thinking` 继续有效。

同步迁移 Provider、会话及其测试替身，提取 Collector，添加 Agent 与调度，改造执行器取消，再接入模式指令和终端消费。实现阶段更新过时的单次工具描述、README、配置示例和验收清单，原有六工具与协议续接测试继续回归。

本章没有持久化数据迁移。实现验收完成后另行同步主规范并归档；回退版本会恢复单次工具行为，已经产生的文件和命令影响仍需依据实际状态处理。
