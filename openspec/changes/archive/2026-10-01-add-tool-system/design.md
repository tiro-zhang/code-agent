## Context

动机与范围见 [proposal.md](proposal.md)。现有 `Provider.stream()` 仅接收文本消息，`StreamEvent` 只有思考、文本和完成事件；`ChatSession.ask()` 仅在获得非空完整回答后一次性提交历史。两种适配器分别只接受 `stop` 和 `end_turn`，因此工具调用会被误判为未完成。

工具执行会产生文件和进程副作用，历史提交不能继续只依赖最终回答成功。既有 Anthropic 思考处理只用于展示，也不足以续接带签名的工具响应。配置在进程内固定，暂不需要跨供应商迁移历史。

设计适用本地 POSIX 终端，验收环境为 macOS，进程组方案同样适用于 Linux。Windows 的等价进程管理不在本次实现范围；工具初始化在不支持的平台给出明确错误。

## Goals / Non-Goals

**Goals:**

- 工具实现只关注参数和操作，注册、协议转换、执行边界和终端显示分别承担独立职责。
- 在收到完整响应后才决定执行，结果与调用 ID 一一配对，并在答复失败时保留可追溯记录。
- 给下一阶段循环编排留下可复用的执行入口；本阶段通过显式分支限制执行次数。

**Non-Goals:**

- 通用 Agent 框架、插件动态加载、MCP 接入、自动工具重试和持久化任务队列。
- shell 沙箱、持续 shell 会话、后台作业管理、交互式命令输入或文件变更自动回滚。
- 改变现有模型选择和思考参数策略；本变更只扩展工具响应的保存与续接。
- 优化上下文裁剪策略或引入摘要压缩；当前保留已实现的完整轮次裁剪与模型请求重试，后续再优化。

## Decisions

### 1. 工具、执行器和协议适配分层

在 `src/mewcode/tools/` 建立契约、注册、路径处理、执行器与六个工具实现。`Tool` 使用项目现有的 `Protocol` 风格，提供 `name`、`description`、`input_schema` 和同步 `execute(arguments, context)`。`ToolContext` 保存启动时解析出的根目录及执行限制，不包含 Provider 或终端对象。

`ToolRegistry` 检查重名、按名查找并列出与协议无关的定义；它提供协议导出入口，具体 JSON 包装由 Provider 适配函数完成。这样“集中登记并导出 API 列表”仍只有一个来源，各工具无需理解两家协议。相比为每个工具复制两份 API 定义，这能避免参数描述漂移。

`ToolExecutor` 校验 JSON、Schema 和上限，运行工作进程并统一转换结果。采用 `jsonschema` 做本地校验，Schema 使用对象类型、明确的必填字段与 `additionalProperties=false`；不把供应商 strict 模式当成本地校验替代品。

结果形式为 `ToolResult(ok, data, error, truncated)`，调用 ID 由外层工具结果消息持有。错误包含 `code`、`message`、`details`，允许失败时仍携带 stdout、stderr 等部分数据。类型错误、文件错误、超时和普通异常统一进入结果；取消作为单独状态处理。输出和错误经过 JSON 库编码，不能拼接 JSON 字符串。

### 2. 采用可终止的工具工作进程

每次有效调用启动短生命周期工作进程，父进程掌握截止时间和进程组。通过管道发送工具名、参数和上下文；工具参数不放进命令行。工作进程加载同一组内置工具，使用专门的结构化通信通道返回有界输出事件和最终结果。

POSIX 下为工作进程创建新 session/进程组；它启动的 shell 和搜索子进程保持在该组内。超时或 Ctrl+C 时向组发送终止信号，最多等待 1 秒后强制结束，回收工作进程及管道。命令输出由工作进程持续排空并有界上报，父进程保留已收到的输出，即使工作进程超时也能构造结果。

默认期限为 30 秒；`execute_command.timeout_seconds` 可取 1 至 120。相比线程计时后直接返回，进程方式可以终止仍在运行的 Python 文件操作与命令；代价是每次调用有启动开销。它提供取消和资源管理，不是安全沙箱。主动脱离进程组的守护进程不属于可保证清理的后台作业，工具说明不鼓励启动此类命令。

超时不等于撤销操作。命令以及文件提交已发生、但结果尚未送达时，错误须标记副作用可能发生，建议先检查状态；本轮不会重试工具操作。未提交的临时文件在能确认归属时清理，进程被强杀后也不能删除用户原有目标。

### 3. 明确六个工具的输入与限制

以下数值是本设计选择的初始默认值，用于形成可实现、可测试的契约；它们不是新增的用户偏好。

| 工具 | 参数 | 处理约定 |
| --- | --- | --- |
| `read_file` | `path`；`start_line=1`；`max_lines=200`，范围 1–1000 | 返回原始文本与实际行范围；保留换行，UTF-8 解码失败或特殊文件返回错误 |
| `write_file` | `path`、`content` | 创建父目录并仅新建文件；内容 UTF-8 编码后最多 1 MiB |
| `edit_file` | `path`、`old_text`、`new_text` | 原文非空，精确且唯一；目标与生成内容均最多 1 MiB |
| `execute_command` | `command`；`timeout_seconds=30`，范围 1–120 | 使用 `/bin/sh -c`，固定 cwd、非交互标准输入；分别返回 stdout、stderr、exit_code |
| `glob_files` | `pattern`；`max_results=100`，范围 1–1000 | 按相对路径排序，采用路径 glob 语义 |
| `search_code` | `pattern`；可选 `glob`；`max_results=100`，范围 1–1000 | 使用正则，返回路径、行号、行文本，按路径及行号排序 |

单次结果有效内容限制为 64 KiB，保留完整结构并设置 `truncated`；命令为 stdout 和 stderr 各保留最多 32 KiB 的前缀，持续排空后续输出以防死锁。文件读取使用有界块处理长行，截断落在完整 UTF-8 字符边界；含 NUL 的文件视为不支持的文本。搜索在条数或内容限制处停止并标记截断；不能把截断结果描述成完整集合。写入、编辑超限直接失败，不截断源内容。累计工具参数设置 2 MiB 上限，超限响应不执行工具并给出明确错误。

`/bin/sh` 选择固定 shell 以获得可复现的 POSIX 管道和重定向语义，不加载用户交互式配置；命令的退出码遵循该 shell，管道默认采用末条命令状态。`cd` 只影响当前调用。命令描述告知模型此阶段最多执行一个工具、目录范围和输出限制，但次数限制由会话代码执行。

搜索使用当前环境已有的 `rg`，安装要求写入 README。通过参数数组而非 shell 调用，使用 `--no-config`，明确禁止跟随链接目录，跳过隐藏和忽略文件；在非 Git 工作目录也读取适用的忽略规则。模式作为独立参数传入，避免以 `-` 开头的输入变成命令选项。`rg` 的无匹配退出状态映射为空结果；无效表达式和缺少程序分别映射独立错误。相较自行维护文件遍历及正则扫描，复用 `rg` 能保持两类搜索的忽略规则一致。

### 4. 文件路径与提交边界

固定 `Path.cwd().resolve()` 为本次会话根目录，不因 shell 命令改变。文件工具统一解析绝对或相对路径，使用路径包含关系判断而非字符串前缀比较，并检查解析后的已有祖先；搜索结果也验证路径归属。打开前检查普通文件，禁止 FIFO、设备等特殊文件。目标本身或祖先存在符号链接时检查真实目标；目录越界错误优先于文件存在错误，通过目录检查后，新建操作将包括断链在内的已有目录项视为已存在。

新建文件不能先 `exists()` 再覆盖写入。采用同目录暂存文件写完后原子发布且拒绝目标存在的方式，例如 POSIX 原子硬链接发布；创建与提交发生竞争时也保留既有目标。编辑读取完整字节、按 UTF-8 原文进行匹配，计数包含重叠起点，恰好一次才生成替换结果；同目录暂存后原子替换，保留权限和未改动字节，不做通用换行转换。

提交前若检测到目标内容已经变化，返回 `file_changed`，避免覆盖已观察到的外部编辑。该检查和路径校验面向本地单用户工作目录，不承诺对恶意并发重命名提供操作系统级隔离；需要该保证时须另行引入沙箱或更强的文件句柄约束。原子提交防止半份文件，但提交后结果丢失仍需按“副作用不确定”处理。

### 5. 扩展消息而保持会话与协议解耦

统一消息增加助手工具调用与工具结果，调用记录含 `id`、`name`、原始参数字符串及解析状态；结果消息持有对应 ID。完整助手响应附带 Provider 专属的原始内容块，用于精确重放思考签名等不宜抽象成文本的数据。会话不检查这些块的供应商字段，Provider 负责序列化；退出后与普通历史一起丢弃。

流式事件继续支持思考和文本增量，新增携带完整助手响应及结束原因的完成事件。界面可展示文字，但执行器只接收已正常完成的响应，不在单个参数块闭合时立即执行，避免后续流失败或出现第二个调用后无法撤销首个操作。

OpenAI 按 `tool_calls[*].index` 拼接增量，名称和 ID 可能只出现于首片；普通回答结束原因是 `stop`，工具响应是 `tool_calls`。保留助手调用后，用 `role=tool`、`tool_call_id` 和 JSON 结果正文续接。首阶段请求发送 `parallel_tool_calls=false`，最终答复阶段请求发送 `tool_choice=none`；上下文恢复重试沿用所在阶段的工具控制。协议格式依据 [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

Anthropic 按内容块索引累积 `tool_use`、`input_json_delta`、文本、思考和签名，等正常 `message_stop` 且结束原因为 `tool_use` 或 `end_turn` 后产出完整响应。优先使用 SDK 的原始流事件接口自行累积，避免便利层提前 JSON 解析失败而丢失可回灌的调用 ID。工具响应保留原始内容块，随后用用户消息中的 `tool_result` 回灌，错误同时设置 `is_error`。正常结束但 JSON 无效时保存有界原文，在错误结果中封装该原文；原始输入不能表示为对象时，回放的失败调用使用显式无效输入包装对象，且绝不执行它。[Claude 流式协议](https://platform.claude.com/docs/en/build-with-claude/streaming)、[无效 JSON 处理](https://platform.claude.com/docs/en/agents-and-tools/tool-use/fine-grained-tool-streaming)

Claude 工具轮次的思考、签名及不可展示块必须完整保留，不能根据终端显示文本重新构造；结果请求保持同一思考配置。纯文本轮次继续采用当前仅保存最终文字的语义历史。[Claude 思考续接](https://platform.claude.com/docs/en/build-with-claude/thinking)

DeepSeek 官方 Anthropic 兼容接口会忽略 `disable_parallel_tool_use` 和 `is_error`，但支持 `tool_choice=none`、工具定义和结果块。因此数量上限由会话执行，错误在 JSON 正文中明确表达，思考块按照其实际协议原样保存。模拟流和真实验收分别覆盖其行为，不能用 DeepSeek 结果代替官方 Claude 验收。[DeepSeek 兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)

### 6. 两阶段调用与分段提交历史

```text
user --> request(tools=auto) --> complete assistant response
                                  |
                  +---------------+----------------+
                  |                                |
                text                           tool call(s)
                  |                                |
               commit                    validate count + arguments
                  |                                |
                prompt                    execute once / error(s)
                                                   |
                                          commit call(s) + result(s)
                                                   |
                                           request(tools=none)
                                                   |
                                            commit final text
                                                   |
                                                 prompt
```

采用显式两个阶段的工具编排分支，不引入自动工具循环或 SDK 的自动工具 runner。正常流程最多发起两次模型请求。首响应若含多个有效 ID，全部产生 `too_many_tool_calls`，不选择执行其中一个；所有 ID 都补齐结果后只做最终答复。未知工具、参数校验错误等也占用本轮唯一的处理机会，修正执行留到下一用户轮次。

上下文超限恢复允许额外的模型请求：仅当本阶段尚未输出流式片段时，按完整对话轮次裁剪较早历史后重试同一阶段，并显示已丢弃的轮数。当前实现以 1、2、4 等递增步长裁剪；没有可裁剪的旧轮次，或已开始流式输出时，结束本轮并报错。恢复循环不会重新执行工具，也不会从最终答复阶段返回首阶段；最终答复的重试保持 `tool_choice=none`，并保留本轮的问题、调用和结果配对。各阶段及其重试维持相同思考配置。

历史提交分成两个边界。首响应未正常完成时保留当前的整轮不提交行为；正常的工具响应暂存为完整调用记录，执行结束或异常清理产生结果后，把用户问题、助手响应及所有结果一起提交，然后才请求最终答复。将这段收尾放在受控的取消处理路径，避免 Ctrl+C 留下孤立调用。

工具执行时取消，保存 `cancelled` 结果直接回提示符；工具已结束后的最终答复失败，仅丢弃该次部分答复，保留本轮已产生的记录。下一用户问题使用尚未因上下文限制裁剪的成对历史，不自动重新执行工具。如果最终答复响应违规请求工具，不执行、不提交该响应，也不再发起请求。工具之后的最终答复仍须是正常结束的非空文本。

### 7. 展示和验证围绕可观察行为

终端保留现有 `思考>`、`MewCode>` 分区，增加工具开始与结果状态；展示工具名、路径或有界命令摘要，不完整打印写入内容。展示与模型回灌分开，但二者均能看到错误及截断标记。显示文本对终端控制字符进行安全处理，避免命令输出影响提示符布局；原始结果在大小限制内保存为数据。

自动化验证覆盖六工具真实临时文件/子进程行为、两家假流参数拼接、思考原样重放，以及会话中实际执行次数与历史提交。超时测试检查同组子进程确实停止；文件测试覆盖重复创建、重叠匹配、换行保留与越界链接；不能仅断言抛出异常就宣称文件未改变。

端到端按项目约定在 tmux 用授权本地配置发真实请求，每个问题只要求一个工具：读取、创建、精确替换、管道命令、glob 和代码搜索。再验证拒绝覆盖、匹配失败、超时以及下一轮记得先前操作。`checklist.md` 记录通过、失败、未执行与原因，官方 Claude、DeepSeek 兼容和 OpenAI 兼容分别标注；供应商生成多工具的防御路径通过可控流确定验收。

## Risks / Trade-offs

- [文件路径校验不限制 shell，shell 可访问目录外或覆盖文件] → 在工具描述和 README 中准确说明两种边界；`write_file` 的拒绝覆盖保证仅适用于该工具。
- [某兼容服务不支持工具或不遵守参数] → 请求失败给出可修正的兼容提示，调用数量与第二阶段禁用在本地再次校验。
- [超时或中断前操作已经提交] → 返回副作用可能发生的结果并保存历史，不自动重试工具，也不承诺回滚。
- [逐工具进程有启动成本] → 当前每轮最多一次，优先确保超时可终止；将来仅在测量到性能问题时考虑复用工作进程。
- [上下文裁剪丢失较早信息并增加请求次数] → 保留当前按完整轮次裁剪和可见提示的恢复行为；无可裁剪历史或已输出流式片段时终止重试。裁剪策略、重试预算与摘要压缩留待后续优化，本次不扩展实现。
- [固定 shell 与搜索依赖限制可移植性] → 明确 POSIX 支持范围，缺少 `rg` 时只让搜索工具返回依赖错误。

## Migration Plan

本变更无持久化数据迁移。实现时先扩展内部类型和工具层，再接入两个 Provider，最后连接会话与终端，并同步 README 和验收清单。原有 `.env` 字段及启动命令继续有效。

完成自动化与 tmux 验收后另行归档变更，将新增能力和现有能力的增量规格同步到主规格；当前产物不直接修改主规格。回退应用版本只能停止后续工具能力，已由工具产生的文件与命令副作用需要用户按实际状态处理。
