## Why

MewCode 已具备流式多轮对话，但模型无法检查项目或执行实际操作。新增统一工具系统，让模型选取工具、应用执行操作并回传结果，为后续 Agent Loop 建立可独立验收的基础。

## What Changes

- 引入统一 Tool 接口和注册中心，集中管理名称、描述、参数 Schema、执行方法与供应商工具定义的转换。
- 提供 `read_file`、`write_file`、`edit_file`、`execute_command`、`glob_files`、`search_code` 六个工具，统一返回结构化成功或失败结果，处理参数错误、超时与输出限制。
- 文件读写、编辑及搜索限定在启动工作目录内，解析符号链接后也不得越界；`write_file` 仅新建文件，已存在时拒绝覆盖；`edit_file` 仅在原文恰好匹配一次时替换。
- 命令工具接受完整 shell 命令字符串，支持管道和重定向，在启动工作目录中执行；该工作目录不是 shell 的文件访问隔离边界。
- 扩展 Anthropic Messages 与 OpenAI Chat Completions 适配器，拼接流式工具参数，将调用和结果按各自协议回灌，并保留续接所需的供应商内容。
- 每个用户问题最多执行一次工具；回灌成功或错误结果后，再请求模型生成最终答复，该请求禁止继续调用工具。服务若一次返回多个调用，则全部拒绝执行并逐个返回错误。
- 终端展示工具状态；工具调用和结果进入会话历史，即使最终答复失败，也保留已发生的操作记录。
- 保留上下文超限后的恢复：本阶段尚未输出流式片段时，可裁剪较早的完整对话轮次并重试模型请求，终端提示裁剪数量。正常流程最多两次模型请求，该恢复路径允许额外请求，但不会重复执行工具。
- 本阶段不加入自动工具重试、连续工具调用、持久化 shell 或 Agent Loop；错误后的再次工具执行由用户下一次提问触发。上下文裁剪策略及摘要压缩留待后续优化。

## Capabilities

### New Capabilities

- `tool-system`: 工具契约、注册、参数校验、结构化结果、执行超时和输出限制。
- `core-tools`: 六个工具的参数与行为、文件目录边界、新建与唯一匹配编辑语义，以及 shell 命令执行。

### Modified Capabilities

- `llm-providers`: 从纯文本请求扩展为工具定义、流式调用解析、结果回灌及思考内容续接。
- `interactive-chat`: 每轮单次工具执行、工具状态展示、结果后的最终答复，以及含工具操作的历史、中断处理与上下文超限恢复。

## Impact

- 新增 `src/mewcode/tools/`，调整 `types.py`、`session.py`、两个 Provider 和终端展示逻辑。
- 引入本地 JSON Schema 校验依赖；搜索使用 `rg`，执行工具使用可终止的子进程。现有供应商配置格式保持可用。
- 新增工具与流式协议测试，更新 README 和 `checklist.md`，通过 tmux 验证真实工具请求、两种协议及失败恢复。
- 主规格中的“仅发送纯文本对话”约束需要替换；配置和既有纯文本交互仍须通过回归验收。
