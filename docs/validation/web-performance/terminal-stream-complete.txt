MewCode> 终端流式回复指 AI 在终端中输出回答时，不等待整段内容生成完毕，而是把结果拆成极小片段，边生成边发送、边接收边显示，最终呈现出文字持
续涌出的实时效果。其工作过程可以从模型、传输、客户端三个层面理解。

在模型层面，语言模型基于自回归方式逐 token 生成内容：它根据已有上下文预测下一个 token，再将该 token 并入上下文继续预测，如此循环直到结束。如
果采用非流式模式，服务端必须等整个循环完成后才返回一次完整响应；流式模式则在每个 token 或少量 token 产生时立即向外推送，因此用户能在模型刚开
始生成后不久就看到第一个字。

在传输层面，流式回复依赖一条保持开启的长连接。常见实现包括 HTTP 的分块传输编码、SSE（服务器发送事件）以及 WebSocket。服务端把增量内容封装成
一个个事件帧持续下发，帧中除文本片段外，还可能携带序号、结束标志、工具调用请求或错误信息。生成完毕时，服务端发送终止帧并关闭连接。网络本身可
能把多个片段合并成一个数据包，也可能把一个片段拆开发送，因此客户端必须按协议边界做缓冲与重组，不能假设一次读取正好对应一个 token。

在终端客户端层面，程序在后台持续运行读取循环，收到新数据块后解析出增量文本，立即写入标准输出并强制刷新缓冲区，使字符马上出现在屏幕上。与此同
时，客户端还要监听用户键盘事件，比如按下 Ctrl-C 时主动关闭连接、停止模型生成，并把已输出部分保留下来。对于工具调用类型的帧，客户端则需要暂停
文本渲染，执行命令或读写操作，再把结构化结果回填给模型，随后继续接收文本流。

流式回复的主要优势是首字延迟短、交互感强，长回答过程中可以随时判断方向或中断。代价是实现复杂度更高：需要处理分片粘包、中途出错、断线重连、并
发读写以及取消时的资源回收等问题。
